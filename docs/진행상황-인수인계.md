## 2. 코드 규약 ( 새 화면도 이 형태를 따를 것 )

### 파일 배치
```
packages/mes-core/
  database/migrations/                    마이그레이션
  src/Config/Models/ · Controllers/       기준정보 모듈
  routes/config.php                       /config/* 엔드포인트
  resources/js/Pages/Config/XxxManage.vue      목록 화면
  resources/js/Components/Config/XxxForm.vue   등록·수정 모달
src/config/menus.php                      메뉴 정의 ( 새 설치용 )
src/database/seeders/Config/              초기 데이터
```

### 업무 모듈 배치 ( 수주부터 )
```
packages/mes-core/
  src/Order/Models · Services · Controllers     업무 모듈 ( 네임스페이스 MesCore\Order )
  routes/order.php                             config('mes.modules') 에 Order 가 있을 때만 등록
  src/Purchase · routes/purchase.php           발주 ( Material 모듈이 켜져 있을 때 )
  resources/js/Pages/Order/ · Components/Order/
```
- **업무 모듈도 패키지에 둔다** ( 모든 업체가 쓰는 제품 기능 ). `src/app/Modules/*` 는 업체 전용 코드 자리
- 저장 · 채번 · 삭제 규칙은 **Service**( 트랜잭션 경계 ), 컨트롤러는 검증 · 응답만
- 전표 번호 : `XX-YYMMDD-NNN` ( 날짜별 순번, 같은 날짜 마지막 번호를 `lockForUpdate` 후 +1 ) — `SalesOrderService::nextOrderNo()`
- 전표 삭제 : 아래 단계가 없으면 지우고( 첨부까지 ), 있으면 취소 상태 — 기준정보( 미사용 처리 )와 다르다
- decimal 캐스트 칸에는 **문자열**로 넣는다 ( float 이면 brick/math 경고 )
- 새 모델의 등록자 · 수정자 기록은 trait **`MesCore\Support\RecordsAccount`** ( 기존 모델의 `booted()` 반복을 대신 )
- 여러 화면이 같이 쓰는 API 의 권한은 **`MenuPermissionService::canPage($user, [page_component…], $action)`** — 하나라도 되면 통과 ( 입고검사 · 첨부 `receipt_line` )

### 재고 규약 ( 재고-수불-설계 · 40-구매자재 §10 )
- **재고를 바꾸는 길은 `StockService::post()` 하나** — 원장 INSERT + 잔고 UPSERT 를 호출 쪽 트랜잭션 안에서. 잔고를 직접 고치지 않는다
- 원장은 **추가만**, 취소는 `reverse()`( 역분개 — `reverses_idx` / `reversed_by_idx` ). **화면에서 원장을 GROUP BY 하지 않는다** — 현재고는 `stock_balance`
- 전표는 `stock_txn` + `stock_txn_line`( 입고 `IN_PURCHASE` — 출고 · 이동 · 조정도 같은 표에 종류만 더함 ). 검사대기처럼 **재고에 아직 없는 줄은 줄 표에만**
- 시각 둘 : `occurred_at`( 화면 입력 · 수정 가능 ) · `recorded_at`( 서버 · 불변 ). 소급은 `StockService::checkBackdate()` ( 미래 시각은 막음 )
- LOT 발급은 `LotService::issueMaterialLot()` — `lot.material_source` · 자재 기준 LOT 규칙 · `lot_seq` 순번. `feature.lot` 이 꺼지면 `lot_idx = 0`
- 출고 · 이동 · 조정을 만들 때 : 원장 행에 `stock_txn_line_idx` 를 남기고, 되돌릴 때 그 줄의 원장을 `reverse()`
- 전표 번호는 `StockService::nextTxnNo('XX', $date)` — 입고 `RC` · 이동 `MV` · 조정 `AJ`
- 재고현황 팝업처럼 **여러 화면에서 여는 처리 창은 처리 코드 한 곳**( 각 화면의 Form 컴포넌트 + 같은 API ) — 화면목록 §5

### DB 규약
- **커스텀 컬럼 예비 슬롯** : 발주 · 수주 · 출하 테이블을 만들 때 `ext_c01~03`( varchar 200 ) · `ext_n01~02`( decimal 18,6 ) · `ext_d01~02`( date ) + 슬롯마다 인덱스를 **처음부터** 넣는다 ( 품목은 완료 — 10칸 ). 나중에 넣으면 전 테이블 마이그레이션
- PK `xxx_idx`, 코드 `xxx_code`, 이름 `xxx_name` ( `_cd` 쓰지 않음 )
- `is_use` ENUM('Y','N') · `remark` · 감사 4종( `create_account_idx` `create_datetime` `update_account_idx` `update_datetime` )
- 모델 `booted()`에서 등록자·수정자 자동 기록

### 화면 규약
- **새 화면 · 화면 수정은 [`packages/mes-core/docs/style-guide.md`](../packages/mes-core/docs/style-guide.md) 부터** ( 화면 틀 3단 · 좌우 분할 · 모달 · 알림 · 상태 색 — 살아 있는 예시는 개발 메뉴 → 스타일 가이드 ) · 2026-10-28 초안
- 목록 + 모달 ( 창고 · 라우팅 · BOM 은 좌우 분할 )
- 검색바 : 검색어 + 구분 + 사용 여부( 기본 "사용중" )
- **삭제 버튼은 미사용 처리**( `is_use = N` ) — ADR 0019. 물리 삭제 없음
- 체크박스 선택 → 일괄 미사용 처리 ( `DataGrid` + `rowHeaders: 'checkbox'` + **`@select="sel => checkedRows = sel"`** — 그리드 인스턴스를 직접 만지지 않는다 ). **`'checkbox'` 는 문자열로** ( 배열로 주면 공통 체크박스 렌더러가 빠진다 )
- 머리 + 줄 목록은 **트리**( `treeColumnOptions` + 행의 `_children` ) — 줄은 `_attributes: { checkDisabled: true }`, 행 클릭은 줄이어도 그 머리의 모달 ( 수주관리가 기준 )
- 그리드 : 상세는 **행 클릭**( `@row-click` ). 빈 결과는 `empty-text`. 오른쪽 클릭 메뉴는 복사( 셀 · 열 · 행 )만 — **내보내기는 엑셀 버튼 하나로** ( 그리드 기본 내보내기는 양식을 모르고 페이징이면 현재 페이지만 나감 )
- 목록 머리 : 왼쪽 **`◯◯ 목록 · N 건`**( 건수는 `text-xs text-gray-400` ), 오른쪽 **엑셀 버튼만** ( "행 클릭 = 수정" 안내는 두지 않음 ) — `ItemManage.vue` 가 기준
- 그 오른쪽에 **`<ExcelExportButton layout="xxx.list" :rows :columns filename>`**. 양식은 `resources/excel/` ( 공통 `packages/mes-core` · 업체 `src` — 같은 이름이면 업체가 이김 ). 없으면 그리드 열 그대로
- **엑셀 일괄 등록을 붙일 때** : ① 저장 검증을 `Config/Validation/XxxRules` 로 꺼내 화면 저장과 같이 쓴다 ② `ImportHandler` 구현( `Config/Imports` ) → `CoreServiceProvider` 에서 `register` ③ 컨트롤러에 `importValidate` · `importCommit` + 라우트( 쓰기 권한 ) ④ 양식 `xxx.import.json` ⑤ 화면 머리 `<ExcelImportButton>` ( [+ 등록] 왼쪽 )
  - 결과는 행 단위 `rows: [{ row, key, action, status, messages, data }]` — **나중에 결과 목록 모달**이 이걸 그대로 그린다 ( 서버 변경 불필요 )
- **업무 모듈 목록은 서버 페이징** : 컨트롤러 `use RespondsWithList` → `listResponse($request, $query, [정렬 허용 컬럼], 'legacyKey', $map)`, 화면은 `DataGrid :pagination="{ page, perPage, total }" @page @sort`, 엑셀 `:rows` 는 `export=1` 로 전체를 받는 함수. 정렬 열은 `sortable: true` + 서버 허용 목록( 별칭 가능 — `addSelect` 서브쿼리 ). **검색바는 `SearchBar`** ( 수주관리가 기준 )
- 권한 : `page.props.permissions[menuCode]`의 `can_write` / `can_delete`
- 확인창은 `showAlert(...)` ( `window.confirm` 쓰지 않음 )
- 숫자 입력은 `BaseInput`의 `min` · `empty-value` 옵션 사용

- **첨부파일을 붙일 때** : ① `CoreServiceProvider` 의 `AttachmentService` 에 `register('ref_type', '권한 따를 page_component', 모델::class)` ② 화면에 `<AttachFiles ref-type="…" :ref-id="idx" :readonly="!canWrite" />` ( 저장 전 = id 없음이면 안내만 ). 권한은 그 화면의 읽기( 보기 · 받기 ) / 쓰기( 올리기 · 삭제 )

### 서버 규약
- 라우트 권한 : `MenuAuth::class . ':Config/XxxManage,can_read|can_write|can_delete'`
- 머리 + 줄(N)은 **한 트랜잭션**으로 저장, 요청에 없는 기존 줄은 삭제
- 줄 동기화 시 **기존 줄 IDX 를 유지** ( BOM 투입 지점처럼 다른 테이블이 참조하므로 )
- 검증 실패는 422 + 한국어 메시지, 경고는 `warnings` 배열로 200 응답에 실어 보냄 ( 막지 않음 )

### 설정 · 정책 읽기 ( 정책 설정 )
- **모든 모듈은 `PolicyService`로만 읽는다** — `app(PolicyService::class)->get('lot.shipment_lot', ['item' => $itemIdx, 'partner' => $partnerIdx])` · `->isEnabled('feature.lot')`
  - 키는 `group.key`. 없는 키는 예외( 오타 방지 ). BOOL → bool, INT → int|null, 나머지 → string|null
  - 스코프 상속 · 입고검사 충돌 규칙( `EXEMPT_THEN_PRIORITY` ) · 선행 조건( `depends_on` )을 서비스가 처리
- 저장은 `PolicyService::set()` — 권한( `SYSTEM_ADMIN` 은 레벨 0 만 ) · 스코프 · 형태 · 후보 · 선행 조건 검증 → 이력 → 캐시 비움. 실패는 `PolicyException`( 한국어 메시지 )
- **정책 추가** : `src/config/system_config.php` 에 한 항목 → `php artisan db:seed --class="Database\Seeders\Config\SystemConfigSeeder"` ( 정의만 동기화, 값은 안 건드림 )
- **쓰는 곳이 없는 정책은 `visible => false`** 로 둔다. 그 정책을 읽는 모듈을 개발할 때 `true` 로 바꾼다 ( 효과 없는 설정을 화면에 두지 않음 )
- 메뉴를 기능 스위치에 묶으려면 `menus.php` 항목에 `'feature_key' => 'feature.xxx'` + 기존 DB 는 `system_menu.feature_key` 갱신
- **마스터 화면의 정책 덮어쓰기** ( 거래처 · 품목 방식 그대로 )
  - 컨트롤러에 `POLICY_KEYS` 를 두고, 폼 조회에 `entityFields(keys, 'ITEM'|'PARTNER', idx)`, 저장 트랜잭션 안에서 `applyEntity(keys, values, scope, idx)`
  - 저장 권한은 그 마스터 메뉴의 쓰기 권한 ( 라우트 `MenuAuth` 가 이미 검사 ). 검증 오류는 `policies.{key}` 로 돌아온다
  - 저장 실패 `catch` 에서 `$policy->flush()` ( 롤백된 값이 요청 메모에 남지 않도록 ). 캐시는 커밋 후에만 비운다
  - 화면은 `<PolicyOverrideField v-model="policies[key]" :field="…" />` — '' 이 따름, 보낼 때 null

### 멀티테넌시 대비 ( ADR 0027 )
지금은 "설치 하나 = 업체 DB 하나"로 돌고 연결 교체가 없다. SaaS 는 나중에 **미들웨어만 끼우면** 되도록 아래를 지킨다.
- **DB 이름 · 연결 이름을 코드에 쓰지 않는다** ( 모델에 `$connection` 지정 금지, `DB::connection('mysql')` 금지 )
- **캐시 키에 DB 이름**을 넣는다 — `'mes:xxx:' . DB::connection()->getDatabaseName()` ( 정책 · 메뉴 캐시가 기준 )
- **파일 저장 경로에 업체 구분 폴더**를 둔다 — 첨부파일부터
- **큐 · 배치 작업에는 업체 정보를 담아** 넘긴다 — 큐를 처음 쓰는 업무 모듈에서 기반을 같이 만든다
- 업체 테이블에 **`tenant_id` 컬럼을 넣지 않는다**

### 새 메뉴 추가 절차
1. `src/config/menus.php`에 항목 추가 ( 새 설치용 )
2. 기존 DB 에는 메뉴 행을 직접 insert 하거나, 이미 있으면 `url_path` · `page_component`만 채움
3. 메뉴 옵션( 레벨 0·1·10·99 )은 읽기·쓰기·삭제 전부 `Y` ( 레벨은 상한, 실제 권한은 템플릿·개인 지정 )

## 4. 다음에 할 일 ( 우선순위순 )

### A. 기준정보 — 완료. 남은 것은 다른 기능에 걸린 항목뿐
- `W_SERIAL_SEQ_CAPACITY` ( 시리얼 순번 자릿수 < 품목 1회 최대 생산 수량 ) — 기준 데이터가 없어 보류
- LOT 채번 : 순번 카운터 테이블( 규칙 × 리셋 구간 키 ) + 발행 시 `LotRule::render()` 사용 — 작업지시 · 입고 · 출하 개발 때

### B. 공통 기반 ( 남은 것 )
1. 엑셀 일괄 등록을 다른 기준정보( 공정 · 설비 … )로 **추후 넓힌다** ( 사용자 판단 2026-10-08 ). 시점은 미정 — 절차는 2장 화면 규약
2. 첨부파일 — 품목 · 거래처에 적용. 업무 화면( 입고검사 · 공정검사 · 출하 )에는 만들 때 붙인다
- 완료된 것 : 정책 설정 1 ~ 4단계 · 커스텀 컬럼 슬롯( 품목 · BOM 줄 ) · 공통 그리드 보강 · 엑셀 내보내기 · 엑셀 일괄 등록( 품목 · 거래처 ) · 세션 만료 안내 · **엑셀 업로드 결과 목록** · **첨부파일**( 품목 · 거래처 )
- 코드관리는 표 안 편집 그리드라 엑셀 버튼 미적용

### C. 멀티테넌시 — 결정 완료 ( 2026-10-08 · ADR 0027 )
- `tenant_id` 넣지 않음 · 업체별 설치 주력 · SaaS 는 필요할 때 **업체 목록 + 연결 교체 미들웨어 + 업체 순회 마이그레이션 + DB 식별 1행 대조**만 붙인다
- 그때까지는 2장 "멀티테넌시 대비" 규약만 지킨다

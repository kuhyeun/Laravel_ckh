# 알림 설계

> 작성일: 2026-09-01 · 상태: 초안 (미결은 §7)
> 화면에 **실시간으로 밀어 넣는** 알림을 웹소켓으로 전달합니다.

---

## 1. 웹소켓은 전달 수단일 뿐이다

**알림의 진실은 DB의 `notification` 행입니다.** 웹소켓은 그것을 빨리 보여 줄 뿐입니다.

```
사건 발생 → notification INSERT  ← 여기가 진실
                 │
                 ├─ 웹소켓으로 push   (연결되어 있으면)
                 └─ 수신함에 쌓임      (언제나)
```

이 순서를 뒤집으면 안 됩니다. **웹소켓으로만 보내고 저장하지 않으면**
브라우저를 닫았던 사람은 그 알림을 영영 못 봅니다.

| | 웹소켓 | 수신함 |
|---|---|---|
| 목적 | **지금 보고 있는 사람**에게 즉시 | 나중에 온 사람도 빠짐없이 |
| 없으면 | 새로고침해야 보임 | **알림이 사라짐** |
| Phase 1 | 포함 | 포함 |

---

## 2. 끊기는 것이 정상이다

공장 와이파이는 끊깁니다. 태블릿은 절전으로 들어갑니다.
**연결이 끊긴 동안 발생한 알림을 놓치지 않는 것**이 설계의 핵심입니다.

```
접속        → 서버에 last_seen_id 를 함께 보냄
서버        → 그 뒤로 쌓인 알림을 한 번에 내려보냄
이후        → 새 알림만 push
연결 끊김   → 클라이언트는 조용히 재연결 (지수 백오프)
```

**폴링으로 대체하지 않습니다.** 사용자 200명이 5초마다 물어보면
아무 일도 없는 하루에 350만 번의 빈 요청이 돕니다.

| 상황 | 처리 |
|---|---|
| 재연결 | `last_seen_id` 이후를 **한 번에** 받습니다 |
| 서버 재시작 | 클라이언트가 재연결하고 위와 같이 복구 |
| 웹소켓 자체가 막힘 | **수신함은 그대로 돕니다.** 배지 숫자만 늦게 갱신됩니다 |

---

## 3. 채널에 테넌트를 박는다

```
tenant:{tenant_id}:user:{user_id}
```

**채널 이름에 테넌트가 들어갑니다.** 구독 요청이 자기 테넌트와 다르면
그 자리에서 연결을 끊습니다 — 물어보지 않습니다.

| 검사 | 시점 |
|---|---|
| 세션 토큰 유효성 | **접속할 때** |
| 토큰의 테넌트 = 구독 채널의 테넌트 | **구독할 때마다** |
| 사용자 비활성화 | 접속할 때 + 주기 확인 |

> 알림 본문에 **다른 테넌트의 데이터가 섞이는 사고**는 조용히 일어나고,
> 일어난 뒤에는 되돌릴 수 없습니다. 채널 이름에 경계를 박아 두면
> 코드가 실수해도 채널이 막습니다.

브로드캐스트 채널(`tenant:{id}:all`)은 **공지에만** 씁니다.
업무 알림은 언제나 개인 채널입니다 — 권한이 없는 사람에게 보이면 안 되기 때문입니다.

## 4. 서버가 여러 대일 때

한 서버에 붙은 사용자에게, 다른 서버에서 발생한 사건을 알려야 합니다.

| 배포 | Phase 1 |
|---|---|
| **온프레미스** | 서버 1대. **그대로 됩니다** |
| **중앙 · 단일 인스턴스** | 그대로 됩니다 |
| **중앙 · 다중 인스턴스** | 인스턴스 간 전달이 필요합니다 |

**Phase 1은 단일 인스턴스를 가정하되, 발행 지점을 한 곳으로 모읍니다.**

```
NotificationPublisher.publish(tenant, user, payload)
   └─ 지금은 로컬 세션 맵으로 직접 전달
   └─ 나중에 여기만 Redis pub/sub로 바꿉니다
```

발행이 코드 곳곳에 흩어지면 나중에 전부 찾아 고쳐야 합니다.
**한 곳으로 모아 두는 비용은 지금 거의 0**이고, 나중에 바꾸는 비용은 큽니다.

## 5. 무엇을 밀어 넣는가

**실시간이 필요한 것만** 보냅니다. 소음이 되면 사람들이 전부 꺼 버리고,
그러면 정말 중요한 알림도 같이 사라집니다.

| 종류 | 받는 사람 | 왜 실시간인가 |
|---|---|---|
| **검사 대기 발생** | 검사자 | 공정이 **막혀 있습니다.** 늦게 알수록 라인이 섭니다 |
| **음수 재고 발생** | 자재 담당 | 원인 전표가 가까울수록 추적이 쉽습니다 |
| **안전재고 미달** | 생산 계획 | 부족 시점 전에 지시를 내야 합니다 |
| **작업지시 배정** | 작업자 | 다음에 뭘 할지 |
| **납기 임박 · 초과** | 영업 · 생산 | |
| 결재 도착 · 반려 | 결재선 | **Phase 2** |

**Phase 1의 알림은 이 다섯 가지입니다.** 늘리는 것은 쉽고 줄이는 것은 어렵습니다.

### 종류마다 켜고 끈다

```sql
CREATE TABLE notification_pref (
  tenant_id  INT         NOT NULL,
  user_id    BIGINT      NOT NULL,
  kind       VARCHAR(30) NOT NULL,
  in_app     BOOLEAN     NOT NULL DEFAULT TRUE,   -- 수신함
  push       BOOLEAN     NOT NULL DEFAULT TRUE,   -- 웹소켓 · 화면 토스트
  sound      BOOLEAN     NOT NULL DEFAULT FALSE,
  PRIMARY KEY (tenant_id, user_id, kind)
) ENGINE=InnoDB;
```

행이 없으면 **기본값(수신함 · push 켜짐, 소리 꺼짐)** 입니다.
전 사용자 × 전 종류를 미리 만들어 두지 않습니다.

## 6. 스키마

```sql
CREATE TABLE notification (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  tenant_id   INT         NOT NULL,
  user_id     BIGINT      NOT NULL,
  kind        VARCHAR(30) NOT NULL,        -- INSPECTION_WAIT · STOCK_NEGATIVE · ...
  title       VARCHAR(120) NOT NULL,
  body        VARCHAR(400) NULL,
  ref_type    VARCHAR(20) NULL,            -- WORK_ORDER · LOT · SALES_ORDER
  ref_id      BIGINT      NULL,            -- 눌렀을 때 갈 곳
  is_read     BOOLEAN     NOT NULL DEFAULT FALSE,
  created_at  DATETIME(6) NOT NULL,
  read_at     DATETIME(6) NULL,
  PRIMARY KEY (id),
  KEY ix_inbox (tenant_id, user_id, id),        -- 수신함 · 재연결 복구
  KEY ix_unread (tenant_id, user_id, is_read)   -- 배지 숫자
) ENGINE=InnoDB;
```

`ref_type` + `ref_id`가 **알림을 눌렀을 때 갈 곳**입니다.
첨부파일(`attachment`)이 어디에나 붙는 방식과 같습니다.

| 규칙 | 내용 |
|---|---|
| 보관 | **90일 후 삭제**하는 배치. 읽은 알림을 영원히 쌓아 둘 이유가 없습니다 |
| 배지 숫자 | `is_read = false` 개수. 인덱스로 O(1) |
| 같은 사건 반복 | **묶지 않습니다** — 안전재고 미달이 매일 뜨면 매일 뜨는 게 맞습니다 |

## 부록 · 결정 요약

| 결정 | 값 |
|---|---|
| 전달 | **웹소켓 push** + **수신함**. 웹소켓은 전달 수단, 진실은 `notification` 행 |
| 끊김 복구 | 재연결 시 `last_seen_id` 이후를 **한 번에**. 폴링 안 함 |
| 채널 | `tenant:{id}:user:{id}` — **채널 이름에 테넌트를 박음** |
| 다중 인스턴스 | Phase 1은 단일 가정. **발행 지점 한 곳**으로 모아 나중에 교체 |
| 종류 | Phase 1 **5종**. 결재 알림은 Phase 2 |
| 설정 | 종류별 `in_app` · `push` · `sound`. 행이 없으면 기본값 |
| 보관 | **90일** 후 삭제 배치 |

## 1. 문서 성격과 전제

요구사항 1차는 **고객 인터뷰 원문 수준의 기능 나열**입니다. 우선순위·데이터모델·화면정의·예외처리가 없고,
원문에 `**` / `?????` 로 미결 표시된 항목이 7건 있습니다. 따라서 이 문서는

- 원문을 개발 가능한 단위로 **분해·분류**하고,
- **리스크와 선행 결정 사항**을 드러내고,
- **MVP 경계**를 긋는 것

까지를 범위로 합니다. 화면정의서·ERD는 다음 단계입니다.

### 시스템 성격 판단

**패키지형 MES(다수 제조사 판매)** 로 판단합니다. 근거:

- 슈퍼관리자의 `기능옵션관리 / 메뉴관리 / 커스텀 컬럼관리 / 컬럼명 관리`
- `업체정보관리`
- "업체에서 필요한만큼 설정" (LOT규칙), "사용여부 설정으로 자동 추가/삭제" (창고/LOT/바코드 메뉴)

→ **테넌트별 기능 on/off와 화면 커스터마이징이 1급 요구사항**이며, 이것이 아키텍처의 주축입니다.
단일 고객 SI로 만들면 나중에 되돌릴 수 없습니다.

대상 업종은 **이산제조(가공·조립)**. 근거: 환봉/코일/판소재 잔재 처리, 설비 공정, LOT, 외주, 세트제품.

## 2. 개발내용 정리

### A. 플랫폼 / 횡단 관심사

모든 업무 모듈이 의존하므로 **가장 먼저** 만들어야 합니다.

| 항목 | 내용 | 난이도 |
|---|---|---|
| 인증·권한 | 사용자관리, 권한관리(메뉴/기능 단위), 마이페이지(내정보·알림) | 중 |
| 멀티테넌시 | 업체정보관리, 테넌트 격리 | 중 |
| 기능옵션관리 | 창고/LOT/바코드 등 모듈 on/off → 메뉴 자동 노출·숨김 | 중 |
| 메뉴관리 | 메뉴 트리 구성, 권한 매핑 | 하 |
| **커스텀 컬럼** | 품목/발주/수주/출하에 컬럼 추가·삭제. **기능형 / 일반 텍스트형** 구분. 목록·검색·정렬·엑셀에 전파 | **상** |
| 컬럼명 관리 | 표준 필드 라벨을 테넌트별 재정의 | 중 |
| 코드관리 | 공통코드 (**품목 단위 `UNIT`** · 첨부파일 구분 코드 포함) | 하 |
| 공통 검색 | 기간 + 검색어 + 통합검색 + 상세검색(품목·수주·생산지시). 리스트 **첫 컬럼에 상세보기 버튼 고정** | 중 |
| 첨부파일 | 전 모듈 공통 저장소. 구분: 성적서 / 밀시트 / 도면 등 | 하 |
| 알림 | 알림 발송·수신함·설정 | 중 |
| **전자결재** | 양식 editor + 결재선 + **5개 연동지점**(수주 / 발주서 / 작업지시서 / 외주발주 / 출하지시서) | **상** |
| **라벨(바코드/QR)** | 발행·선발행·재발행·동일번호 중복발행·라벨지 규격/분할·인쇄이력·폐기(사유) | **상** |

### B. 기준정보관리

| 항목 | 핵심 요건 |
|---|---|
| 품목 | 자재(원자재/원소재) · 제품(완제품/반제품/세트제품) + **BOM**. 품목별 **자재 차감 위치 설정**(수주연동 입고자재만 / 창고 선입선출), 출하 시 **제품 차감 위치 설정**(수주연동 생산품만 / 창고 선입선출) |
| 거래처 | 구매처·고객사·외주처 **멀티 선택**(기본 전체). 담당자 N개(본사/출고지). 출고지(공장) N개. **입고검사 정책**: 무검사 / 샘플링 / 전수 |
| 공정 | 구분: 생산 / 검사 / **설비생산**(설비 필수, 기본설비 + 사용가능설비 N) / 외주. 기본 단일공정 4종(원자재입고·원자재출고·검사·포장)은 **시작/종료 시간 미기록, 완료 클릭만** |
| 공정라우팅 | 동일 공정 **중복 선택 허용**(예: 가공→검사→가공) |
| 설비 | 설비 마스터 |
| 창고 | **다단계 로케이션** (A동 - 1구역) |
| 검사기준서 | 검사 항목·규격 |
| 제조리드타임 | default + 품목별. 자재구매·입고·생산·검사·포장 소요일. **실적 데이터로 재계산하여 갱신하는 기능** |
| 시리얼번호 | **중요 제품은 낱개마다 번호.** `item.serial_use`로 품목에서 켜고, **최종 공정 실적 수량만큼 발번**. 재고는 여전히 LOT 단위 — 시리얼은 식별표입니다 |
| LOT규칙 | 포맷 4종(자재기준/생산일기준/종료일기준/분할생산기준). 조합: `품목코드+날짜+순번`, `생산공장+생산라인+날짜+교대조`. **날짜는 `YY`/`YYMM`/`YYMMDD` 선택**(그 단위가 순번 리셋 주기), **거래처는 입고 · 출하 · 외주에만**(발행 시 선택 가능). 업체가 N개 등록 → **작업지시 시 선택 발행** |

### C. 수주관리

- 리스트(수주 단위, 클릭 시 **트리로 하위 품목** 전개) / 등록(1수주 N품목, **품목별 납품일 상이**) / 삭제
- **정기수주**: 특정 프로젝트의 반복 수주. 스케줄 지정 또는 상시. 일정마다 생산계획·작업지시 생성
- **수주 진행현황 보드**
  `수주명 | 품목 | 수량 | 원자재입고(d) | 원자재출고(d) | 1공정(s/e/검사badge) | 2공정 | 3공정 | 출하검사(d) | 출하(d)`
- 수주이력: 1년 단위로 수주수량 / 생산실적 / 납품실적 비교
- 전자결재 연동(수주 결재)

### D. 구매 / 자재 / 재고

| 항목 | 핵심 요건 |
|---|---|
| 구매자재관리 | 발주. 전자결재(발주서) |
| 입고 | 창고 입고. 입고검사 정책에 따라 검사 선행 |
| 출고 | 생산 전 자재 출고 = **선점**. 생산실적관리에서도 출고 가능 |
| 사용처리 | 원/부자재는 **필요시점 자동 차감 가능**(공정 시작 전 / 외주 출고 전 사급자재) — 설정 |
| 재고관리 | **LOT 단위 수량 + 해당 LOT의 발행 바코드 유무**. LOT **쪼개기 / 합치기 / 다른 품목으로 변경**. 품목 클릭 시 입출고 이력 |
| 창고 | 창고별 보유수량, 창고이동, **LOT 일부 이동** |
| 잔재 재입고 | 환봉/코일/판소재 **부분 사용 후 반납 재입고**(1000mm 중 500mm 사용) → 재입고 후 바코드 발행 |
| 재공관리 | 작업지시번호별 재공품 수량 |
| 재고조정 | 조정 사유·이력 |
| 재고실사 | **실사 시점부터 입출고 재계산**. 입고기록보다 이전 시점 실사가 **나중에 등록**될 수 있음(전산 지연) |
| **자재구매계획 시뮬레이션** | ① 확정 생산계획 기준 ② 수주 + 확정 생산계획 기준. 수주는 **납기일 역산**. 발주분 제외. 입고예정 표시. 버킷: **일 1~30 / 주 1~12 / 월 1~12** |

> 원문 `수불 기록에 대해서 정의 필요**` — **해결됨.** [재고-수불-설계.md](./재고-수불-설계.md) 참조.

### E. 생산

| 항목 | 핵심 요건 |
|---|---|
| **생산계획 시뮬레이션** | 품목별 / 설비별. 수주에 대해 예정일 산출. **설비공정은 사용중 설비를 제외하고 가능한 일정 탐색** = 유한능력 스케줄링 |
| 생산일정관리 | 캘린더 또는 간트. **겹치지 않는 선에서 다단 배치**(한 줄 1건 아님). 대기 계획을 badge로 나열 후 **드래그로 일정 삽입/변경** |
| 계획등록 / 확정 | 확정 계획이 자재구매계획의 입력이 됨 |
| 작업지시 | 수주 **분할·병합** 지시 / 수주 없이 단독 지시. 공정 순서 **DnD 변경**. 작업자·설비·공정별 기한·품목별 생산기한 지정. **계획에서 지시 생성**(설비 default). 품목별 지시 시 공정 일괄 |
| LOT 발행 | LOT규칙 선택 발행 |
| **라우트시트(공정흐름표)** | 단일 QR(시작/종료 구분 없음). **최초 스캔 = 수량 0으로 s 기록** → **이후 스캔마다 수량 누적 + e 기록**. 수량 바코드(5/10/50/100/150/200) 스캔 또는 수동 입력 후 엔터 확정. **e 기록 시점부터 다음 공정 진행 가능**(수량 제한 있음). 회당 상승 수량 지정 가능 |
| 설비 연동 | 스캔 후 설비 변경 시 **설비에서 수량 조회**. 설비는 **누적 카운터** → 최초 취득값·현재 취득값 보관 필요. **수동 처리 가능해야 함** |
| 공정실적관리 | 전체 생산실적 이력 |
| **LOT추적** | 입고·공정·검사 기록. **정추적/역추적 그래프**. 폐기·발행. 바코드로 LOT 조회. **LOT 번호 기반 추적**(DB relation 아님 — 전산 지연 시 링크 단절·복구 불가 회피 목적) |
| 불량 처리 | ① **폐기**(차감된 채 완료) ② **폐기 후 재생산**(자재 추가 투입, 폐기수량 제외 목표 달성) ③ **불량수정**(차감·추가 없음, 부자재 일부 추가 가능) |
| 외주관리 | 외주발주 / 외주발주서 / 출고 / 입고. 전자결재 |

### F. 품질

- 공통: **검사완료처리 + 첨부파일**. 옵션으로 *불량만 등록* 또는 *검사완료처리*
- 입고검사: 검사필수 / 무검사 (자재입고 전 검사 → 자재팀 확인 후 입고처리 *옵션*)
- 외주입고검사
- 공정검사: 공정라우팅에 검사 삽입 또는 품목별 필수/무검사. 시점: **공정 시작 전 / 초·중·종 / 공정 후 / 직접의뢰**
- 출하검사: 출하품 검사 → 출하처리
- 불량관리: 전체 불량이력, **목표 대비 불량률 그래프**, 상세
- 불량이슈관리: 빈발 불량 공유, 개선 이력. 불량관리에서 이슈 등록
- 검사이력: 검사일·시각 등, 검사시트 열람
- 바코드 스캔으로 검사완료 처리
- **검사시트: 엑셀 파일을 등록해두면 그 모양대로 열어 작성·저장** — 원문 `??????????` 미결

### G. 출하관리

- 출하품 관리(판매자재 / 생산제품·부품), 출하 가능 품목, **출하대기품**
- 출하: 수주 선택 출하 / 품목 선택 출하(**수주 연동분은 불가**)
- 출하대기 → 출고 → 출하완료 시 **사용처리(선점)**
- 바코드 스캔 출하
- 출하건 묶음 관리 + 품목 전체가 보이는 이력
- **출하 바코드**: 출하건 단위 생성(제품 바코드 아님) — 고객사 지정 LOT/바코드
- 클레임관리: 고객사 클레임 등록·처리, 불량 반품, **불량 재입고 → 재생산(또는 수정) → 재출하**
- **생산 전후 행위 사전 지정**(라우팅에서 계획 시 발주 자동 → 생산완료 시 출하까지 자동) — 원문 `**` 미결
- 전자결재(출하지시서)

### H. 설비관리 / 기타

- 설비보전: 점검·수리 내역, **점검주기**, 정기점검 시트(점검항목) → 선택 시 **주기별 점검항목 자동 등록**
- 설비유휴관리: 유휴 기록
- 영업관리: 수주–출하 통합 뷰
- 데이터관리: 전 모듈 첨부파일 관리(구분 코드)
- 계측기관리, 공구관리

## 4. 리스크 Top 7

**1. 생산계획 시뮬레이션 (유한능력 스케줄링)**
원문은 "사용중인 설비를 제외하고 가능한 일정 찾기" 한 줄뿐입니다. 제약조건(설비 캘린더, 교대조, 셋업시간,
선후행 공정 대기, 납기 우선순위)이 전혀 정의되지 않았습니다. **별도 설계 과제**로 분리해야 하며,
여기서 일정이 무너지는 것이 이 프로젝트의 최대 리스크입니다.

**2. 수불·재고 정합성** — *원문 "정의 필요\*\*"* · **설계 확정됨 → [재고-수불-설계.md](./재고-수불-설계.md)**
"실사 시점부터 재계산" + "실사가 입고보다 이전 시점인데 나중에 등록될 수 있음" = **소급 입력 허용**이고,
현장 실태상 **소급은 예외가 아니라 기본 동작**입니다(오늘 생산건 처리 후 1주일 전 건을 나중에 입력).

채택 구조: **원장 + 잔고 + 스냅샷 3층**, `occurred_at` / `recorded_at` **이중 시간축**, 취소는 역분개.
파생 리스크가 남습니다 — 소급이 **선입선출·공정 순서 검증·재고 부족 검증**을 전부 깨뜨리므로
세 가지 모두 차단이 아닌 **경고 후 허용**을 기본값으로 잡았습니다. 정렬 축(`occurred_at` vs `recorded_at`)도
화면별로 분리해야 하며, 이를 놓치면 "방금 입력한 건이 목록에서 사라지는" 문제가 생깁니다.

**3. 커스텀 컬럼**
동적 스키마가 목록·검색·정렬·엑셀·결재양식·바코드 라벨까지 전파됩니다. "기능을 위한 컬럼"이 무엇인지
(계산식? 참조? 날짜 규칙?) 정의되지 않았습니다.

**4. 라우트시트 스캔 UX**
시작/종료 구분이 없는 단일 QR로 상태를 전이시킵니다. 오스캔·중복스캔·수량 오입력·공정 역행 등
**예외 시나리오 설계가 기능 자체보다 큽니다**. 현장에서 가장 많이 쓰는 화면이므로 품질 기준을 높게 잡아야 합니다.

**5. 설비 카운터 연동** — *원문 "인터페이스 준비\*\*"*
설비 벤더·프로토콜(OPC-UA / Modbus / 시리얼 / 벤더 API) 미정. 대상 설비 목록도 없음.
**MVP 범위 밖**으로 두되, 수동 입력 경로를 정식 기능으로 만들어 두면 연동 없이도 운영됩니다.

**6. LOT 추적 방식**
원문이 명시적으로 **DB relation 대신 LOT 번호 기반 추적**을 선택했습니다(전산 지연 시 링크 단절 회피).
대신 번호 오타·중복·규칙 변경 시 추적이 끊깁니다. 번호 유일성 보장과 링크 보정 화면이 필요합니다.

**7. 검사시트 = 엑셀 원형 유지** — *원문 "??????????"*
웹에서 임의 엑셀 서식을 그대로 열어 편집·저장하는 것은 비용이 큽니다.
대안: ① 검사항목 기반 폼 빌더 ② 엑셀 템플릿에 값만 주입해 다운로드 ③ 상용 스프레드시트 컴포넌트 도입.

| **선점 · 출고 미사용** | **예약 개념 없음** — 출고가 곧 차감이라 `가용 = 현재고`이고 `reserved_qty` 컬럼을 두지 않습니다. 출고했지만 안 쓴 자재는 `wo_stock`(작업지시 × 품목 × LOT) 별도 테이블. **안전재고 판정은 창고 가용만** → [재고-수불-설계.md](./재고-수불-설계.md) §9.2-1 |
| **자재 LOT 발급** | 공급처 LOT(Heat No · Coil No)을 **그대로 쓸지 / 자체 발급 후 표시만 할지** 시스템관리자가 설정. 기본값 자체 발급. 입고 시기가 다르면 **합치지 않고 별도 LOT** |
| **품목 구분 기준** | **"단독으로 파는가"** — BOM에서 하위에 있다고 반제품이 아닙니다. 단독 판매되면 `FINISHED`, 사내에서만 소비되면 `SEMI`. **세트 구성품은 대부분 완제품**입니다 |
| **세트제품** | **미조립 세트 = 포장공정 하나짜리 라우팅을 가진 완제품.** 포장은 실물 작업이라 작업 실적 · 포장자재 차감 · 세트 LOT · 세트 재고가 전부 생깁니다. 조립품은 **별개 품목**(BOM · 단가 · 품번 · 라우팅이 다름). 수주 라인은 **세트 그대로**이고 구성품으로 전개하지 않습니다 → [ERD.md](./ERD.md) §6 |
| **부족 시점 계산** | **버킷은 보는 단위**(일·주·월), **판정 기준은 따로**(버킷 내 최저 / 버킷 말) — 굵게 보면 골짜기가 사라지므로 기본은 **버킷 내 최저**. 필요량은 **커버 구간(리드타임 + 발주 주기)** 의 최저로, 지시 수량은 거기에 **최소 수량 · 배수**를 얹어 냅니다. 납기는 **MAX(오늘, 역산일)** — 과거로 발주할 수 없고 **지연 일수는 남깁니다**. **확정 수주만** 셉니다 → [ERD.md](./ERD.md) §9 |
| **단가 · 안전재고 · 표준시간** | 전부 **품목 마스터**에. 단가는 **판매 · 발주 · 외주 3종**이고 전표 라인의 **기본값일 뿐** — 건마다 고치고 **라인 값을 저장**합니다. 거래처×품목 단가표는 두지 않습니다. `safety_stock`은 부족 시점 계산의 기준선, `order_cycle_days`(발주 주기) · `moq`(최소 수량) · `unit_round`(배수)가 지시 수량을 정하고, `cycle_time_sec`은 **1개 생산 표준시간** |
| **리드타임 두 축** | `lead_time` **일수** 5구간(구매·입고·생산·검사·포장, `item_id=0`이 default)과 `cycle_time_sec` **개당 초**는 **다른 것**입니다. 수량 기반 일정은 개당 시간으로만 나옵니다. 실적 재계산은 Phase 2 |
| **초 · 중 · 종 개별 on/off** | `routing_line.insp_first` · `insp_middle` · `insp_last`. **초물과 종물만 하는 현장이 있습니다.** 검사 공정 완료는 **켜진 것 중 마지막** 기준. 지시 시점에 복사되어 소급 없음 |
| **공정 미달 종료** | 지시 수량을 못 채워도 **사유와 함께 닫습니다**(`short_qty` · `short_reason`). **지시 수량은 그대로**이고 남은 수량으로 새 지시를 자동 생성하지 않습니다 — 미달은 지워야 할 오류가 아니라 남겨야 할 사실 |
| **설비 교체 · 검사 불량** | 설비를 바꾸면 **실행을 종료하고 새로 엽니다**(설비별 실적을 잃지 않기 위해). 검사에서 등록한 불량은 **앞 생산 공정의 실행**에서 차감합니다(`defect.target_run_id`) — 검사 공정은 수량을 만들지 않습니다 |
| **자재소요 계산식** | 자재를 얼마나 낼지 **업체가 식으로 등록**합니다 — `CEIL(ORDER_QTY*BOM_QTY/FLOOR(SPEC/(CUT+KERF)))`. **좁은 수식**(변수 + 연산자 5 + 함수 6, 반복·조건 없음)이라 항상 종료합니다. 정의는 **공용 DB `calc_def`**, 등록은 **시스템관리자**. 내장 3종은 Phase 1, 등록 화면은 Phase 2 → [자재소요-계산-설계.md](./자재소요-계산-설계.md) |
| **BOM 메뉴 끄기** | **실 가공만 하는 업체는 BOM 메뉴를 아예 안 씁니다.** `feature.bom`으로 끄면 메뉴가 사라지고 **품목의 주 자재로만** 관리합니다 — BOM 테이블은 그대로 쓰이고 메뉴만 숨깁니다 |
| **자재 차감 방식** | `material.consume_mode` — **자동**(계산식 + 선입선출로 LOT까지 시스템이 정함) / **수동**(식별표 스캔 또는 직접 선택). `timing`은 **언제**, `mode`는 **어떻게**. 스코프 `TENANT → ITEM`이라 소재는 수동, 볼트는 자동으로 둘 수 있습니다 |
| **BOM 자동 생성** | **가공품은 제품 1 : 원자재 1**이 대부분이고 여러 자재는 **조립품뿐**입니다. 그래서 **품목 등록 화면에서 주 자재를 지정하면 BOM(`V1`)이 자동 생성**됩니다 — 한 줄짜리 BOM을 품목 수만큼 손으로 만들 이유가 없습니다. **진실은 여전히 `bom`·`bom_line` 하나**이고 품목에 자재 컬럼을 두지 않습니다(2줄 이상이면 품목 화면은 읽기 전용) → [ERD.md](./ERD.md) §6 |
| **QR 로그인** | **본인이 QR 로그인 사용을 켠 사람만** 발급받고 로그인합니다(opt-in, 기본 꺼짐 — 끄면 기존 QR도 즉시 무효). 현장 단말은 **개인 QR을 찍어 로그인**합니다 — 장갑 낀 손으로 비밀번호를 칠 수 없습니다. QR에는 **불투명 토큰만** 담고 서버는 **해시만** 보관하며, 분실하면 **재인증 후 재발급**하고 이전 QR은 그 순간 무효입니다. **QR에는 토큰만 담고 카드 표면에 이름 · 부서 · 발급일을 인쇄**합니다 — 카드가 섞이면 누구 것인지 알아야 합니다. **QR은 사진 한 장으로 복사되므로** 관리자 계정은 금지하고 **유휴 10분 자동 로그아웃**을 겁니다 — 공용 단말에서 **남의 이름으로 실적이 남으면 불량 추적이 무너집니다** |
| **바코드가 화면을 연다** | 라우트시트에는 바코드가 **두 종류** — 상단의 **작업지시 바코드**는 그 지시의 **스캔 화면을 열고**(실적 안 올림), 공정 바코드가 **실적을 올립니다**. 현장은 **시트를 집어 상단을 한 번 찍으면** 그 화면이 떠 있습니다 — 메뉴를 찾아 들어가지 않습니다 |
| **자재는 공정을 막지 않는다** | 자재가 없어도 **1공정은 돕니다.** 미출고 · 재고 부족 모두 **경고만** — 막으면 현장이 시스템을 떠나고 그러면 실적도 안 들어옵니다. **출고 · 공정 시작 · 사용처리는 순서가 정해져 있지 않고**, 창고에서 빼오는 것이 시작 이후여도 됩니다. **자재투입 공정을 완료하면** 그 줄의 자재가 사용처리되고 **미출고분은 자동 출고**(재고 없으면 음수 + 미결) → [자재소요-계산-설계.md](./자재소요-계산-설계.md) §9 |
| **공정 조건부 자재** | `bom_line.routing_line_id`가 **투입 지점이자 소요 조건**입니다 — **공정 마스터가 아니라 라우팅의 그 줄**을 가리킵니다(`가공 → 검사 → 가공`에서 어느 가공인지 구분). 그 줄이 작업지시에 **없으면 자재도 소요가 없고**(도금을 빼면 도금액도 빠짐), 제외된 줄은 **회색으로 남깁니다**. **소요 시점도 그 줄을 따라갑니다** — `1→2→3(자재투입)→4`면 착수일이 아니라 **3공정 도달일** |
| **기능형 커스텀 컬럼** | `custom_field_def.kind = FUNCTIONAL` + `var_name`. **계산식이 값으로 읽는 컬럼**입니다 — 톱날 손실(`KERF`) · 비중(`DENSITY`) · 로스율(`LOSS`). 원문의 *"특정 기능을 위한 컬럼"* 이 이것입니다 |
| **실시간 알림** | **웹소켓 push + 수신함.** 웹소켓은 전달 수단일 뿐이고 **진실은 `notification` 행**입니다 — 저장 없이 push하지 않습니다. 끊기면 재연결해 `last_seen_id` 뒤를 한 번에 받고, **폴링하지 않습니다**. 채널은 `tenant:{id}:user:{id}`. Phase 1 **5종**(검사 대기 · 음수재고 · 안전재고 미달 · 작업지시 배정 · 납기 임박) → [알림-설계.md](./알림-설계.md) |
| **작업지시 발행 근거** | `ORDER`(수주) / `STOCK`(안전재고 · 부족 시점) / `MANUAL`. **`sales_order_line_id`는 NULL 허용** — 재고 기반 지시를 담아야 합니다. 부족 계산에 **확정 발주의 입고 예정을 포함**하고, 안전재고는 **품목 단위**. MRP 아님 → [ERD.md](./ERD.md) §9 |

### 미확정 (2건)

| # | 결정 사항 | 영향 범위 |
|---|---|---|
| 1 | **설비 연동 대상·프로토콜** | 생산 실적 |
| 2 | **검사시트 방식** (§4-7 대안 중 택1) | 품질 |

### 설계 단계에서 알 수 없는 것 — 관측으로 대체

**소급 지연 최대치**와 **일 전표 라인 수**는 설계 단계에서 확보할 수 없습니다.
설계 입력에서 제외하고, 시스템이 스스로 측정하게 합니다.

| 미지수 | 왜 몰라도 되는가 |
|---|---|
| 일 전표 라인 수 | 파티션 미사용이므로 사전 추정 불필요. 전환이 필요해지면 무중단 가능 |
| 소급 지연 최대치 | 영향은 스냅샷 주기 하나뿐이고 스냅샷은 재생성 가능한 캐시. 정책 기본값도 차단 없이 경고만 |

**대응: `ops_metric_daily` 관측 배치를 Phase 1에 포함**합니다.
야간 배치가 하루 한 줄(전표수·라인수·소급지연 P50/P95/최대·원장 행수·테이블 크기·재계산 소요) 기록합니다.
3개월이면 소급 한계 기본값·파티션 전환 시점·스냅샷 주기를 전부 데이터로 결정할 수 있습니다.

### 모르는 상태에서 설계하는 원칙

1. **차단하지 않는다** — 검증은 경고로. 임계값을 모르는 상태의 하드 블록은 현장을 멈춥니다
2. **되돌릴 수 있는 쪽을 고른다** — 비파티션, 캐시형 스냅샷
3. **모르면 측정 장치를 먼저 넣는다** — 추정하지 않습니다

이 원칙은 앞으로 나올 다른 미지수에도 동일하게 적용합니다.

## 6. MVP 정의

### 한 줄 정의

> **수주 1건이 자재 입고 → 작업지시 → 바코드 공정실적 → 검사 → 출하까지 시스템 안에서 완결되고,
> 그 결과로 재고와 LOT 이력이 맞는다.**

계획 최적화·결재·커스터마이징은 **이 한 바퀴가 돈 다음** 문제입니다.
한 바퀴가 돌지 않는 MES는 현장에서 쓰이지 않고, 쓰이지 않으면 나머지 기능은 검증할 데이터도 없습니다.

### Phase 0 — 플랫폼 기반

인증 · 사용자/권한 · 메뉴관리 · 코드관리 · 공통 목록/검색 프레임 · 첨부파일 · **테넌트 DB 라우팅 + 스키마 마이그레이션 도구** · **공통 정책 서비스 + 기능 스위치 10건**

### Phase 1 — MVP

| 영역 | 포함 |
|---|---|
| 기준정보 | 거래처, 품목 + BOM, 공정 + 공정라우팅, 창고(로케이션), 설비(등록), 검사기준서, **LOT규칙 1종**, **제조리드타임 마스터**(등록만 — 자동 재계산은 Phase 2), **품목 단가 3종 · 안전재고 · 발주주기 · 최소수량 · 배수 · 개당 표준시간** |
| 수주 | 리스트(트리), 등록/수정/삭제, **수주 진행현황 보드** |
| 구매·자재 | 발주, 입고, 출고(선점), **LOT 단위 재고**, 입출고 이력, 재고조정, **재고실사**, 재공관리, 창고이동, **소급 입력 · 음수재고 미결 화면** |
| 생산 | 작업지시(**수주 기반 · 재고 기반 · 수동**), **품목별 부족 시점 조회 → 일괄 지시**, LOT 발행, **라우트시트 스캔 실적**, 공정실적관리, 불량-**폐기**만 |
| 품질 | 입고검사 · 공정검사 · 출하검사 — **검사완료처리 + 불량등록 + 첨부**, 불량 목록 |
| 출하 | 출하대기, 수주 기반 출하, 사용처리, 출하 이력 |
| 라벨 | 바코드/QR **발행 · 출력 · 스캔**, 발행 이력 |
| 알림 | **웹소켓 실시간 push + 수신함 + 종류별 on/off**. Phase 1 5종 |
| 운영 | **`ops_metric_daily` 관측 배치** — 볼륨·소급지연·배치소요 일일 기록 |
| 추적 | LOT 정/역추적 (기본 목록형, 그래프는 Phase 2) |

### Phase 2 — 계획과 자동화

생산계획 시뮬레이션 + 간트/드래그 일정 · 자재구매계획 시뮬레이션 · **전자결재 5종** ·
**커스텀 컬럼 / 컬럼명 관리** · **기능옵션관리** · 외주관리 · LOT 쪼개기/합치기/품목변경 ·
잔재 재입고 · 정기수주 · 불량 재생산/수정 · 불량이슈관리 · 검사시트 · 클레임관리 ·
수주이력 리포트 · 불량률 그래프 · LOT 추적 그래프

### Phase 3 — 확장

설비보전(점검주기 자동등록) · 설비유휴관리 · **설비 카운터 연동** · 계측기·공구관리 ·
생산 전후 행위 자동 연계(자동 발주/자동 출하) · 리드타임 자동 재계산 · 영업 대시보드 · 알림 고도화

### ⚠ MVP에서 빼되 **설계는 미리** 해야 하는 것

나중에 넣으면 전 테이블 마이그레이션이 발생합니다. 기능은 Phase 2지만 **스키마 자리는 Phase 1에**:

| 항목 | Phase 1에 미리 넣을 것 |
|---|---|
| 커스텀 컬럼 | 품목/발주/수주/출하 테이블에 **예비 슬롯 컬럼 + 인덱스** 사전 생성 (품목 10 · 나머지 각 7) |
| 전자결재 | 대상 문서 5종에 결재상태 필드 + 문서 ID 체계 |
| 생산계획 | 작업지시에 계획 참조 FK |
| 외주 | 공정구분 enum에 `외주` 값, 거래처 구분에 `외주처` |
| 기능옵션 | 메뉴 테이블에 옵션키 컬럼 |
| 수불 | **원장+잔고+스냅샷 3층 — 이건 Phase 1에 기능까지 완성** ([설계](./재고-수불-설계.md)) |

## 1. 왜 가장 먼저 만드는가

현장에서 가장 많이 쓰는 화면이고, 한 번 정해지면 되돌리기가 가장 어렵습니다.
시작·종료 구분이 없는 **단일 QR로 상태를 전이**시키기 때문에 예외 시나리오 설계가 기능 자체보다 큽니다
([개발범위-및-MVP.md](./개발범위-및-MVP.md) §4 리스크 4).

`docs/라우트시트 샘플/` 의 실물 양식에서 구조만 참고했습니다. **품번·품명·거래처·담당자 등
특정 업체를 식별할 수 있는 값은 프로토타입에 일절 사용하지 않았습니다.**

## 2. 인쇄 양식

**A4 세로** 기준입니다. 실물 양식에서 구조만 가져왔습니다.

| 영역 | 항목 |
|---|---|
| 헤더 | Shop Order(작업지시 · **바코드**), Part Number, Nomenclature, PC / DC / IBU / T/M/S, Order(Batch), Batch No, **LOT**, 지시수량, **회당 상승 수량**, Project, Issue Date |
| **General Information** | 안내문 — **첫 장 상단에만** |
| 공정 목록 | `OP` · **구분** · 공정(Dept 병기) · 설비/외주처 · **바코드** · QTY · DATE · OPER |
| 결재 | Planner · Q.C Engineer · Approval |

### General Information

- **업체 사용자가 직접 작성합니다.** 시스템관리자 설정이 아니라 **업체 데이터**입니다
  ([정책-설정-설계.md](./정책-설정-설계.md) §7 — 구조는 시스템관리자, 그 안은 업체의 권한).
- 편집은 해당 화면의 **쓰기 권한**을 가진 사용자가 합니다.
- **첫 장 상단에만 인쇄**하고 2장부터는 반복하지 않습니다. 2장 이후는 헤더 요약 + 공정 목록만 이어집니다.

### 구분 — 공정 구분 코드

검사 결과가 아니라 **공정의 구분 코드**입니다. **공정 정보를 등록할 때 알파벳을 원하는 대로 입력**하고
(`process.class_code`), 라우트시트에는 그 값을 그대로 인쇄합니다.

> **시스템이 값을 정해두지 않습니다.** ENUM이 아니라 자유 입력이며, 업체마다 다른 문자를 씁니다.
> 시스템은 값을 검증하지 않습니다.

샘플 양식이 쓰는 값 (참고용):

| 값 | 뜻 | 해당 공정 |
|---|---|---|
| `F` | 가공 · 표면처리 · 제작공정 | 정밀가공, 외주 표면처리, 조립, 포장 |
| `I` | 품질검사 · 공정검사 | 초중종검사, 최종검사 |
| `M` | 자재투입 | 자재투입(원자재 출고) |

**기본 단일 공정**(원자재입고 · 원자재출고 · 검사 · 포장)은 업체가 만드는 공정이 아니라
시스템이 제공하므로 **값이 미리 정해져 있습니다** — 검사는 `I`. 사용자가 입력하지 않습니다.

**범례는 인쇄하지 않습니다.** 업체마다 다른 문자를 쓰지만, 같은 줄에 **공정명**이 있어서
읽는 사람에게 필요한 정보는 이미 다 있습니다. 이 코드는 분류·집계용 보조 값입니다.

**Dept 컬럼도 같은 성격입니다.** 업체가 등록하는 **부서 · 작업장 코드**이고 시스템이 값을 정하지 않습니다.
샘플 양식은 `O.V` · `VQ1` · `101` 처럼 문자와 숫자를 섞어 씁니다.

> 라우트시트에 인쇄되는 코드류(**구분**, **Dept**)는 전부 **업체가 정하는 값**입니다.
> 시스템이 의미를 부여하거나 값을 검증하지 않습니다. 프로토타입의 값은 자리표시자입니다.

> **컬럼 제목은 미확정입니다.** 실물 양식에서 읽어내지 못해 **`구분`** 으로 이름 붙였습니다.
> 레거시 2글자 약어를 베끼기보다 읽으면 아는 이름이 낫다고 봤습니다 — 확인되면 한 단어만 고치면 됩니다.

### 기본 단일 공정은 완료만 처리한다

원문 *"원자재입고, 원자재출고, 검사, 포장 기본 단일 공정 (s-e 시간기록하지 않음, 완료시 클릭 정도)"*.

- **시작·종료 시각과 수량을 기록하지 않습니다**
- 스캔 **한 번**으로 완료 처리됩니다
- 다음 공정은 이 공정이 **완료**되면 시작할 수 있습니다

### 품목의 공정라우팅 — 기본값 하나

공정라우팅 목록에서 **기본으로 쓸 것 하나를 지정**해 둘 수 있습니다.

```
routing.is_default   테넌트에 하나만 true
```

| 상황 | 품목 등록 시 |
|---|---|
| 기본 라우팅이 지정되어 있음 | 그 라우팅이 **자동으로 들어감** |
| 사용자가 직접 다른 것을 선택 | 선택한 것으로 **변경** |
| **기본 라우팅 미지정** | 품목의 공정라우팅은 **빈값** |

> **기본값은 품목 등록 시점에만 적용됩니다.** 나중에 기본 라우팅을 바꿔도
> **이미 등록된 품목의 라우팅은 그대로**입니다. 소급 적용하면 진행 중인 작업지시가 뒤틀립니다.

기본 라우팅을 바꿀 때 화면에 *"기존 품목에는 적용되지 않습니다"* 를 표시합니다.

### 바코드

- **작업지시 바코드** 1개 (Shop Order)
- **공정 순서마다 바코드** 1개 (`S OP.` 010 / 020 / …)
- 시작·종료를 구분하지 않는 **단일 코드**입니다

## 3. 회당 상승 수량

> **`work_order.scan_qty` — 작업지시 단위로 하나만 설정합니다.**

- 스캔할 때 이 값을 **조회해서 수량 입력창에 자동으로 채웁니다**
- **확인(엔터)을 눌러야 확정**됩니다 — 자동 가산하지 않습니다
- 다른 수량이 필요하면 **수량 바코드**(5 / 10 / 50 / 100 / 150 / 200)로 덮어쓰거나 직접 고칩니다
- **남은수량 전체**를 한 번에 선택할 수 있습니다 (버튼 또는 `QTY-ALL` 바코드)
- 라우트시트 **헤더에 인쇄**합니다 — 원문 *"찍을때 수량이 몇개씩 올라갈지 지정할 수 있도록(라우트시트에 표시)"*

공정별로 다른 값을 두지 않습니다. 작업지시 하나에 값 하나입니다.

## 4. 스캔 규칙

| 동작 | 기록 |
|---|---|
| 공정 바코드 **최초** 스캔 | 수량 `0`으로 **시작(s)** 기록. 수량은 올리지 않음 |
| 공정 바코드 **재**스캔 | `scan_qty`가 채워진 수량창 표시 → 엔터 또는 수정 후 엔터 → **누적 + 종료(e) 갱신** |
| 수량 바코드 | 채워진 값과 다를 때 사용. **확인(엔터) 필요** |
| **남은수량 전체** | 버튼 또는 `QTY-ALL` 바코드. **기준 수량 − 공정 합계**를 한 번에 채움. 마지막 자투리를 손으로 계산하지 않게 함 |
| 공정 바코드 없이 수량 바코드만 | **거부** — 대상 공정을 알 수 없음 |
| 완료된 공정 재스캔 | 경고 — 이미 완료 |

종료(e)는 **스캔할 때마다 갱신**됩니다. 마지막 스캔 시각이 곧 종료 시각입니다.

### 공정 수량은 작업지시 수량을 따라가지 않는다

각 공정의 상한은 지시수량이 아니라 **앞 수량 공정의 실적**입니다.

| 공정 | 기준 수량 |
|---|---|
| 첫 수량 공정 | **지시수량** |
| 이후 수량 공정 | **앞 수량 공정의 실적** (검사 · 기본 공정은 건너뜀) |

020 정밀가공에서 150개만 나왔으면 040 조립은 **150개까지만** 할 수 있습니다.
불량 · 폐기로 앞 공정 수량이 줄면 뒤 공정의 기준도 자동으로 줄어듭니다 —
원문 *"폐기(수량차감된 그대로 진행 완료)"*.

**남은수량 전체**도 이 기준으로 계산합니다. 기준을 넘겨도 **막지 않고** 경고만 표시합니다.

## 5. 같은 공정을 설비 여러 대에서 동시에 진행한다

라우팅에서는 **한 줄**이지만 실적은 **설비별로 따로** 쌓입니다.

| 항목 | 처리 |
|---|---|
| 실적 단위 | **공정 × 설비**마다 시작(s) · 종료(e) · 수량을 따로 기록 |
| 공정 수량 | 설비별 수량의 **합계** |
| 다음 공정 조건 | 설비별이 아니라 **공정이 시작되었는가** — 수량은 0이어도 됩니다 |
| 라우트시트 인쇄 | 공정 **1줄**. 설비 칸에는 **사용 가능한 설비만** 나열하고 **실제 설비는 스캔할 때 확정** — 인쇄 시점에는 알 수 없음 |

### 내 설비 — 단말에 미리 지정한다

현장 단말은 대개 **설비 옆에 고정**되어 있습니다. 그래서 스캔할 때마다 설비를 고르게 하지 않습니다.

```
스캔 화면 상단에서 "내 설비"를 한 번 지정 (단말에 저장)
   ↓
공정 스캔
   ├ 설비가 1대            → 자동
   ├ 내 설비가 그 공정에 있음 → 자동, 묻지 않음
   └ 그 외                 → 그때만 선택을 묻는다
```

- 지정한 설비가 **그 공정의 설비 목록에 없을 때만** 선택을 요청합니다
- 설비는 언제든 바꿀 수 있고, **이미 기록된 수량은 설비별로 그대로 남습니다**
- 설비마다 담당자가 자기 단말에서 찍으므로, 한 공정을 여러 단말이 동시에 진행합니다

```sql
work_order_op          -- 작업지시 공정 (라우팅 1줄)
   └ work_order_op_run -- 설비별 실행
        equipment_id, started_at, ended_at, qty, operator_id
```

공정 누적 수량 = `SUM(run.qty)`

## 5-1. 바코드 두 종류

라우트시트에는 바코드가 **두 종류** 찍힙니다. 하는 일이 다릅니다.

| 바코드 | 위치 | 하는 일 |
|---|---|---|
| **작업지시 바코드** | 시트 **상단** | **그 지시의 스캔 화면을 엽니다.** 실적은 올리지 않습니다 |
| **공정 바코드** | 공정 순서마다 | **실적을 올립니다** — 시작 · 수량 · 검사 |

```
공정실적관리(PRD-06) 를 띄워 둔 현장 단말
   │
   │  작업지시 바코드 스캔
   ▼
라우트시트 스캔(PRD-05) — 그 작업지시로 바로 열림
```

**현장은 시트를 집어 상단을 한 번 찍습니다.**
메뉴를 찾아 들어가고 작업지시를 검색하는 과정이 사라집니다 —
장갑 낀 손으로 목록을 뒤지게 하면 아무도 안 씁니다.

| 코드 형식 | 해석 |
|---|---|
| `W-2608-114` | **작업지시** — 화면을 엽니다 |
| `W-2608-114\|2` | **공정** — 실적을 올립니다 |
| `QTY-50` · `QTY-ALL` | 수량 (공정 스캔 뒤에만) |
| 그 외 | **자재 식별표**(LOT) — 사용처리 |

`W-` 로 시작하고 구분자가 없으면 작업지시입니다. **형식으로 갈립니다.**

## 6. 진행 조건과 차단

### 다음 공정을 시작할 수 있는 조건

| 앞 라인 | 조건 |
|---|---|
| **생산 공정** | **시작되었으면** — 설비 하나라도 시작(s)이 찍히면 됩니다. **수량 0이어도 열립니다** |
| **검사 공정** | **검사 완료 처리** |
| **기본 단일 공정** | **완료 처리** (자재투입 · 포장 등) |

> **수량이 아니라 시작이 조건입니다.** 최초 스캔은 **수량 0으로 시작(s)만** 기록하는데,
> 그 상태에서도 다음 공정은 **준비를 시작할 수 있어야** 합니다.
> 1개가 나올 때까지 뒷공정을 세워 두면 **라인 전체가 앞공정 속도에 묶입니다.**

> **자재는 진행 조건이 아닙니다.** 조건은 위 셋뿐입니다.
> 자재가 없어도 1공정은 돕니다 — **막으면 현장이 시스템을 떠나고, 그러면 실적도 안 들어옵니다**
> ([자재소요-계산-설계.md](./자재소요-계산-설계.md) §9.1).

**자재투입 공정을 완료하면** 그 줄에 붙은 자재가 **사용처리**되고,
출고가 안 돼 있으면 **자동으로 출고까지** 처리합니다(§9.3). 재고가 없으면 음수 재고로 남깁니다.

### 외주 공정은 현장에서 스캔하지 않는다

**외주는 외주관리 화면에서 출고 · 입고로 처리합니다.** 라우트시트에는 순서와 외주처가 인쇄되지만,
현장에서 바코드를 찍는 대상이 아닙니다. 스캔하면 **거부하고 이유를 표시**합니다.

> *"외주 공정입니다 · 외주관리에서 출고 · 입고로 처리하세요"*

외주 공정의 완료 여부는 **외주 입고**가 결정합니다. 그 다음 공정은 외주 입고가 끝나야 시작됩니다.

### 진행 수량은 현재 공정 기준

작업지시 상단에 보여주는 숫자는 **지금 진행 중인 수량 공정의 실적**입니다.
현장이 알고 싶은 것은 "지금 몇 개 했나"이기 때문입니다.

진행 중인 수량 공정이 없으면 **마지막으로 실적이 있는 수량 공정**을 보여줍니다.

### 차단과 경고

| 상황 | 처리 | 근거 |
|---|---|---|
| 검사 공정 미완료 + 다음 공정 시작 | **차단** | 정책 없음 · 불변 규칙 |
| SHEET 모드의 검사 공정을 현장에서 스캔 | **차단** — 품질관리에서 처리, 해당 순서 **대기중** | `quality.mode.process` |
| 초물 미완료 + 본 생산 수량 누적 | **경고 후 허용** | 현장이 흐름에 따라 판단 |
| 중물 미실시 | **경고** — 검사 공정을 닫을 때 1회 | 시점은 작업자 임의 |
| 앞 생산 공정에 수량 없음 | 정책에 따름 (기본 경고 후 허용) | `production.process_order_block` |
| **자재 미출고 · 재고 부족** | **경고만. 막지 않습니다** | 현장은 실물을 갖고 있고 전표만 늦습니다 |

> **거부는 반드시 이유를 보여줍니다.** 스캔이 조용히 실패하면 현장은 바코드가 안 읽힌 줄 알고 계속 찍습니다.

---

## 7. 초중종검사의 배치

**라우팅에서 생산 공정 바로 뒤에 검사 공정 1줄**로 들어갑니다. 초 · 중 · 종은 그 줄 안의 체크포인트 3개입니다.
쪼개서 3줄로 만들지 않습니다 — 라우트시트가 읽히지 않고 수량 누적 흐름이 끊깁니다.

```
  [생산공정] ─────────────────────────▶  (계속 진행 가능)
       │ 수량 1개 기록
       ▼
  [초중종검사] ── 초물 ── 중물 ── 종물 ──▶ 검사 완료
     (초물 미완료로 생산 진행 시 경고)          │
                                               ▼
                                         [다음공정] 시작
```

**생산과 검사는 동시에 굴러갑니다.** 검사 공정이 닫힐 때
앞 생산 공정은 끝났을 수도, 아직 진행 중일 수도 있습니다.

### 초 · 중 · 종은 개별로 켜고 끈다

**초물과 종물만 하는 현장이 있습니다.** 라우팅 라인에서 체크포인트마다 지정합니다.

```
라우팅 등록 — 검사 공정 줄
   초물 [v]   중물 [ ]   종물 [v]
```

| 규칙 | 내용 |
|---|---|
| 최소 하나 | 셋 다 끄면 검사 공정을 둘 이유가 없습니다. 저장 시 막습니다 |
| **검사 공정 완료** | **켜진 것 중 마지막**이 완료되면 닫힙니다 — 위 예에서는 **종물** |
| 라우트시트 인쇄 | 꺼진 체크포인트는 **찍히지 않습니다** |
| 스캔 화면 | 꺼진 체크포인트는 **버튼이 없습니다.** 미실시 경고도 없습니다 |

지시 시점에 `work_order_op`로 복사되므로 **라우팅을 바꿔도 진행 중 지시에 소급되지 않습니다.**

상세는 [정책-설정-설계.md](./정책-설정-설계.md) §6 B-3.

## 부록 · 결정 요약

| 결정 | 값 |
|---|---|
| 바코드 | 작업지시 1개(**화면 열기**) + **공정 순서마다 1개**(**실적**). 시작·종료 구분 없음 |
| 최초 스캔 | 수량 `0`으로 시작(s) |
| 재스캔 | `scan_qty` 자동 채움 → **엔터로 확정** → 누적 + 종료(e) 갱신 |
| 수량 선택 | `scan_qty` 기본값 · 수량 바코드 · **남은수량 전체** 셋 중 하나. 모두 엔터로 확정 |
| 회당 상승 수량 | **`work_order.scan_qty`** — 작업지시 단위 하나. 시트 헤더에 인쇄 |
| 다음 공정 조건 | 생산 = **시작(s) 기록** · 검사/기본 = **완료** · 외주 = **외주 입고 완료** |
| 자재 | **진행 조건 아님.** 미출고·부족 모두 경고. 자재투입 공정 완료 시 **사용처리 + 자동 출고** |
| 외주 공정 | **현장 스캔 안 함.** 외주관리 화면에서 출고 · 입고로 처리, 시트에는 표시만 |
| 진행 수량 표시 | **현재 진행 중인 수량 공정**의 실적 |
| 공정 기준 수량 | 지시수량이 아니라 **앞 수량 공정의 실적**. 첫 공정만 지시수량 |
| 설비 동시 진행 | 같은 공정을 **설비 여러 대**에서 동시 진행. 실적은 **공정 × 설비**로 기록, 공정 수량은 합계 |
| 내 설비 | 스캔 화면에서 **단말에 미리 지정**. 해당되면 묻지 않고 자동 사용 |
| 구분 | **공정 구분 코드** `process.class_code` — 공정 등록 시 **알파벳 자유 입력**. 시스템이 값을 정하지 않음. 기본 공정만 값이 정해져 있음(검사 = `I`) |
| 기본 단일 공정 | 시작·종료 시각과 수량 **미기록**, 스캔 한 번으로 **완료만** |
| 초중종 | 생산 공정 **바로 뒤 1줄**, 체크포인트 3개, **병행 진행** |
| 체크포인트 on/off | **개별 지정**(`routing_line.insp_*`). 검사 공정 완료는 **켜진 것 중 마지막** |
| 초물 | 원칙이되 **경고 후 허용** |
| 품목 라우팅 기본값 | `routing.is_default` 하나. **등록 시점에만 적용**, 소급 적용 없음. 미지정이면 빈값 |
| General Information | **업체 사용자가 작성** · **첫 장 상단에만** 인쇄 |

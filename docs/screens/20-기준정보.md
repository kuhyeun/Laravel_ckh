# 기준정보 — 화면정의

> 작성일: 2026-09-02 · 상태: 초안
> `BAS-01` ~ `BAS-11`. 뒤의 모든 화면이 여기에 의존합니다.

**모든 화면이 [00-화면목록 §4-1](./00-화면목록.md)의 공통 규칙을 따릅니다** —
상단 로그인 표시 · 첫 컬럼 상세보기 · 기간 기본값은 정책 · 결과 알림은 서버 `notice`.
아래에는 **그 화면만의 것**을 적습니다.

---

## 0. 공통

### 0.1 목록 · 등록의 기본형

기준정보 10개는 **거의 같은 모양**입니다. 다른 것만 각 절에 적습니다.

```
┌─ 검색바 (CMP-02) ────────────────────────────────────┐
│ [검색어           ] [사용중 ▾] [조회] [초기화]  [+ 등록] │
├─ 목록 (CMP-01) ──────────────────────────────────────┤
│ ▸ │ 코드      │ 명칭            │ …          │ 사용 │
│ ▸ │ RM-BAR-20 │ 환봉 Ø20        │ …          │  ●  │
└──────────────────────────────────────────────────────┘
```

| | |
|---|---|
| 첫 컬럼 | **상세보기 버튼 고정**(`▸`) — 누르면 등록 화면 |
| 검색 | 코드 · 명칭 통합 검색 + `사용중 / 미사용 / 전체` |
| 신규 | `[+ 등록]` — **빈 폼**을 같은 방식으로 엽니다 |
| 삭제 | **하지 않습니다.** `is_active = false`로 내립니다(§0.3) |

### 0.2 페이지와 모달 둘 다로 열립니다

```
메뉴에서        →  /master/items/{id}     페이지
수주등록에서     →  모달                    같은 ItemForm
```

**본체(`XxxForm.vue`)는 라우터를 모릅니다.** `saved` · `cancel` 이벤트만 내고,
닫기와 이동은 감싼 쪽이 정합니다([프로그램-스펙 §12.3](../프로그램-스펙.md)).

| 화면 | 모달로도 열리는 곳 |
|---|---|
| `BAS-01` 거래처 | 수주등록 · 발주등록에서 **새 거래처** |
| `BAS-02` 품목 | 수주등록 · 발주등록 · BOM에서 **새 품목** |
| `BAS-04` 공정 | 라우팅 등록에서 **새 공정** |
| `BAS-07` 설비 | 공정 등록에서 **새 설비** |

**모달은 만든 것을 돌려줍니다** — 수주등록에서 품목을 만들면 그 품목이 **그대로 선택**됩니다.

### 0.3 지우지 않고 내립니다

기준정보는 **전표가 참조합니다.** 지우면 과거 전표가 깨집니다.

| 동작 | 처리 |
|---|---|
| 삭제 버튼 | **없습니다** |
| 사용 안 함 | `is_active = false`. 목록에서 회색, **새 전표에서 선택 불가** |
| 과거 전표 | 그대로 보입니다 |
| 되살리기 | 다시 `true`로 |

### 0.4 커스텀 컬럼

**품목만** 커스텀 컬럼을 갖습니다([커스텀-컬럼-설계.md](../커스텀-컬럼-설계.md)).
정의는 **시스템관리자**가 하고, 여기서는 **값만** 입력합니다.

## BAS-01 거래처관리

```
경로   기준정보 > 거래처관리
권한   조회 USR · 등록/수정 ADM
원본   partner · partner_contact · partner_site · policy_value
```

### 레이아웃

```
┌─ 기본 ───────────────────────────────────────────────┐
│ 거래처코드 * [PT-0012    ]   거래처명 * [샘플공업     ] │
│ 구분 *      [v] 구매처  [v] 고객사  [ ] 외주처         │
│ 사업자번호  [000-00-00000]   대표자  [            ]    │
│ 사용        [v]                                       │
├─ 입고검사 ───────────────────────────────────────────┤
│ 입고검사    ( ) 따름(테넌트: 샘플링)  (●) 전수  ( ) 무검사│
├─ 담당자 (N) ─────────────────────────────────────────┤
│ ▸ │ 구분 │ 소속 │ 이름 │ 연락처      │ 이메일 │ [+] │
├─ 출고지 (N) ─────────────────────────────────────────┤
│ ▸ │ 출고지명 │ 주소              │ 담당자 │ [+]       │
└──────────────────────────────────────────────────────┘
```

### 필드

| 항목 | 컬럼 | 유형 | 필수 | 기본값 | 비고 |
|---|---|---|---|---|---|
| 거래처코드 | `partner_cd` | 문자 20 | ● | | **테넌트 안에서 유일** |
| 거래처명 | `name` | 문자 60 | ● | | |
| 구매처 | `is_supplier` | 불리언 | | `true` | **멀티 선택.** 한 곳이 셋 다일 수 있습니다 |
| 고객사 | `is_customer` | 불리언 | | `true` | |
| 외주처 | `is_subcon` | 불리언 | | `false` | `feature.subcontract` 꺼지면 숨김 |
| 입고검사 | `policy_value` | ENUM | | 따름 | `quality.incoming_inspection` **ENTITY 오버라이드** |
| 사용 | `is_active` | 불리언 | | `true` | |

**담당자**(`partner_contact`)와 **출고지**(`partner_site`)는 **N건**입니다.

### 담당자는 구분과 소속이 다른 축입니다

**구분은 업체마다 다릅니다** — 본사 · 출고지 · 영업담당 · 회계담당 · 품질담당 ….
고정 목록으로 잡으면 반드시 모자라므로 **코드 마스터**에서 고릅니다.

| 컬럼 | 무엇 | 원본 |
|---|---|---|
| `contact_type` | **무슨 역할인가** | `code_item` 의 `PARTNER_CONTACT_TYPE` 그룹 |
| `site_id` | **어디 소속인가** | `partner_site` FK · **비우면 본사** |

*"1공장의 영업담당"* 같은 조합이 실제로 생깁니다. **한 축으로 묶으면 표현되지 않습니다.**

```
▸ │ 구분     │ 소속    │ 이름   │ 연락처        │
▸ │ 영업담당  │ 본사    │ 김담당 │ 02-000-0000   │
▸ │ 영업담당  │ 1공장   │ 이담당 │ 031-000-0000  │
▸ │ 회계담당  │ 본사    │ 박담당 │ 02-000-0001   │
```

초기 코드값 — `HQ`(본사) · `SITE`(출고지) · `SALES`(영업담당) · `ACCT`(회계담당).
업체가 `SYS-06`에서 더합니다.

### 입고검사 설정이 하는 일

```
품목 = 무검사        → 거래처를 무시하고 무검사
품목 ≠ 무검사        → 거래처 값이 있으면 거래처, 없으면 품목
```

`EXEMPT_THEN_PRIORITY` 전략입니다([정책-설정-설계.md](../정책-설정-설계.md) §4).
**화면에 현재 유효값을 함께 보여 줍니다** — *"따름(테넌트: 샘플링)"* 처럼.

### 검증

- 거래처코드 중복 → `E_DUP_CODE`
- 구분 **셋 다 해제** → `E_PARTNER_ROLE_NONE` (하나 이상)
- 참조 중인 거래처를 미사용으로 → **경고 후 허용**(`W_PARTNER_IN_USE`, 진행 중 수주 N건)

## BAS-02 품목관리

```
경로   기준정보 > 품목관리
권한   조회 USR · 등록/수정 ADM
원본   item · bom · bom_line · lead_time · policy_value · custom_field_def/value
```

**가장 큰 화면입니다.** 지금까지 설계한 것이 거의 다 여기로 모입니다.

### 레이아웃 — 탭 4개

```
┌─ 품목 · PN-A 완제품 A ──────────────────── [저장] [취소] ┐
│ [기본] [재고·발주] [단가] [추가정보]                      │
├───────────────────────────────────────────────────────┤
│ 기본                                                   │
│  품번 *   [PN-A       ]   품명 *  [완제품 A          ]  │
│  구분 *   [제품 ▾] [완제품 ▾]                           │
│  단위 *   [EA  ▾]        규격    [                  ]  │
│  라우팅   [표준가공 ▾]   ⓘ 등록 시점에만 자동 적용        │
│  주 자재  [RM-BAR-20 환봉 Ø20 ▾]  소요 [ 1 ]           │
│           └ 저장하면 BOM V1 이 만들어집니다              │
│  사용     [v]                                          │
└───────────────────────────────────────────────────────┘
```

### 탭 1 · 기본

| 항목 | 컬럼 | 유형 | 필수 | 기본값 | 비고 |
|---|---|---|---|---|---|
| 품번 | `item_cd` | 문자 40 | ● | | 테넌트 안에서 유일 |
| 품명 | `name` | 문자 100 | ● | | |
| 대분류 | `item_type` | ENUM | ● | | `MATERIAL` / `PRODUCT` |
| 소분류 | `item_kind` | ENUM | ● | | `RAW` `STOCK` / `FINISHED` `SEMI` `SET` |
| 단위 | `spec_unit` | **코드** | ● | `EA` | **드롭다운.** `code_item`의 `UNIT` 그룹 — 자유 입력이 아닙니다 |
| 기본 라우팅 | `routing_id` | FK | | `routing.is_default` | **등록 시점에만** 자동. 이후 수동 |
| **주 자재** | (BOM) | 참조 | | | **저장 시 BOM `V1` 자동 생성**(§아래) |
| **시리얼 사용** | `serial_use` | 불리언 | | `false` | **낱개마다 번호.** `feature.serial`이 켜져야 보입니다 |
| 사용 | `is_active` | 불리언 | | `true` | |

#### 시리얼은 중요 제품만 켭니다

**켜면 생산 수량만큼 행이 생깁니다.** 볼트 10만 개에 켜면 10만 행입니다.

| | |
|---|---|
| 켜는 대상 | 고객사가 **개체 단위로 추적을 요구**하는 제품 |
| 발번 시점 | **최종 생산 공정 실적** — 그 수량만큼 |
| 재고 | **바뀌지 않습니다.** 재고 단위는 그대로 `품목 × LOT × 창고` |
| 출하 | 출하등록에서 **낱개를 스캔**합니다 |

**연간 예상 수량이 큰 품목에 켜면 경고**합니다 — `W_SERIAL_HIGH_VOLUME`.

#### 단위는 코드 마스터에서 고릅니다

**자유 입력을 막습니다.** `EA` · `ea` · `개` · `EA.` 가 서로 다른 단위가 되면
재고 현황에서 **같은 물건이 두 줄로 나뉩니다.**

| | |
|---|---|
| 원본 | `code_item` 의 **`UNIT` 그룹** — 새 테이블이 아닙니다 |
| 관리 화면 | **`SYS-06` 코드관리** |
| 초기 데이터 | `EA` · `BOX` · `kg` · `g` · `mm` · `m` · `L` · `SET` |
| 추가 | 업체가 `SYS-06`에서 더합니다. 코드 값은 **영문** |

**드롭다운에 없는 단위는 여기서 만들지 않습니다.** 목록 끝에 *"코드관리에서 추가"*
링크를 두고 `SYS-06`으로 보냅니다 — 품목 화면에서 마스터를 늘리면
**오타가 그대로 마스터가 됩니다.**

> 계산식도 이것을 봅니다. `SPEC` · `CUT`이 mm인지 m인지를
> **단위 코드가 정합니다** — 자유 문자열이면 시스템이 알 수 없습니다.

#### 구분 기준은 "단독으로 파는가"

| 물어볼 것 | 답 |
|---|---|
| 고객에게 **단독으로 팔리는가** | 예 → `FINISHED` |
| **사내 공정에서만** 소비되는가 | 예 → `SEMI` |
| BOM에서 하위인가 | **판단 근거가 아님** |

`SET`은 **미조립 세트 전용**입니다 — 조립품은 그냥 `FINISHED`이고 별개 품목입니다
([ERD.md](../ERD.md) §6).

#### 주 자재 — BOM을 대신 만들어 줍니다

**가공품은 제품 1 : 원자재 1이 대부분**이라 BOM 화면을 따로 열 이유가 없습니다.

| BOM 라인 수 | 이 칸의 동작 |
|---|---|
| **0줄** | **입력 가능** → 저장 시 BOM `V1`(활성) 생성 |
| **1줄** | 그 줄을 보여주고 **고칠 수 있습니다** |
| **2줄 이상** | **읽기 전용** — *"BOM에서 관리 · 4종"* + `BAS-03`으로 이동 |

`feature.bom`이 꺼져 있으면 **이 칸이 유일한 BOM 입력 수단**입니다.

```
│ 재고 · 발주                                            │
│  포장 수량   [ 100 ] EA/BOX     안전재고  [ 500 ]      │
```

| 항목 | 컬럼 | 유형 | 필수 | 기본값 | 비고 |
|---|---|---|---|---|---|
| 포장 수량 | `pack_qty` | 수 | | | 박스당 수량. 잔량은 `loose_qty` |

| 최소 수량 | `moq` | 수 | | `0` | 지시 · 발주 하한 |

| 규격 차원 | `spec_dim` | 정수 | | `1` | **Phase 1은 1만** |
| 최소 사용 규격 | `min_usable_spec` | 수 | | | 이 미만 잔재는 **폐기 대상** |
| 계산식 | `calc_cd` | 문자 30 | | 정책 | [자재소요-계산-설계.md](../자재소요-계산-설계.md) |

지시 수량이 어떻게 나오는지 **입력 옆에 미리보기**를 답니다.

```
필요 1,400  →  최소 1,000 통과  →  1,000 배수 올림  →  지시 2,000
```

| 리드타임 | `lead_time` | **일수** 5구간. 없으면 default(`item_id = 0`) |
| 표준시간 | `item.cycle_time_sec` | **읽기 전용** — `routing_line` 합계 |
| 추가 항목 | `ext_c01…` `ext_n01…` | 정의는 **시스템관리자**. 여기선 값만 |

**기능형 커스텀 컬럼**(`kind = FUNCTIONAL`)은 `var_name`이 붙어 있어
**계산식이 값으로 읽습니다** — `KERF` · `LOSS` · `DENSITY`.

### 검증

| 코드 | 조건 |
|---|---|
| `E_DUP_CODE` | 품번 중복 |
| `E_ITEM_KIND_MISMATCH` | `MATERIAL`인데 `FINISHED` 같은 조합 |
| `E_SPEC_DIM` | `spec_dim = 2` (Phase 1) |
| `W_ITEM_NO_ROUTING` | `PRODUCT`인데 라우팅이 없음 — **경고만** |
| `W_SERIAL_HIGH_VOLUME` | 시리얼을 켰는데 **연간 수량이 큼** — 행이 그만큼 생깁니다 |
| `W_ITEM_IN_USE` | 참조 중인데 미사용으로 내림 |

**`SET`은 라우팅이 필요합니다** — 미조립 세트도 **포장공정 하나**를 갖습니다.
없으면 `W_SET_NO_ROUTING`.

## BAS-03 BOM관리

```
경로   기준정보 > BOM관리          ⓘ feature.bom 이 꺼지면 메뉴가 없습니다
권한   조회 USR · 등록/수정 ADM
원본   bom · bom_line
```

### 레이아웃

```
┌─ 품목 [PN-A 완제품 A ▾]  버전 [V2 ▾] ● 활성  [버전 추가] ┐
│ 변경일 [2026-08-28]   사유 [볼트 규격 M6 → M8      ]      │
│ 승인   [2026-08-30 김승인]  [승인]   ⓘ 없어도 활성 가능    │
├───────────────────────────────────────────────────────┤
│ ▸ │ 자재      │ 소요 │ 투입 지점        │ 계산식   │ 절단 │
│ ▸ │ 환봉 Ø20  │  1   │ (없음 · 첫 공정)  │ BAR_CUT │ 100 │
│ ▸ │ 볼트 M6   │  8   │ 4. 조립          │ BOM_BASIC│  —  │
│ ▸ │ 도금액    │ 0.2  │ 6. 도금          │ BOM_BASIC│  —  │
│ ▸ │ 포장재 B  │  1   │ 8. 포장          │ BOM_BASIC│  —  │
└───────────────────────────────────────────────────────┘
```

### 필드

| 항목 | 컬럼 | 필수 | 비고 |
|---|---|---|---|
| 버전 | `bom.version` | ● | **자유 문자열**(`V1` · `A` · `1.0`) |
| 활성 | `bom.is_active` | | **품목당 하나.** 전환은 트랜잭션 |
| **변경일** | `bom.changed_at` | | **설계변경 발효일.** 업체가 적습니다 — 시스템 시각이 아닙니다 |
| 변경 사유 | `bom.remark` | | |
| **변경승인일** | `bom.approved_at` | | `[승인]`을 누른 시각 |
| **변경승인자** | `bom.approved_by` | | 누른 사람. `user_account` |
| 자재 | `bom_line.child_item_id` | ● | |
| 소요 | `bom_line.qty` | ● | 제품 1개당 |
| **투입 지점** | `bom_line.routing_line_id` | | **라우팅의 그 줄.** 비우면 첫 수량 공정 |
| 계산식 | `bom_line.calc_cd` | | 비우면 품목 → 정책 순 |
| 기능형 값 | `bom_line.ext_n01…` | | 절단 길이(`CUT`) 등 |

### 날짜가 셋입니다

**`updated_at`으로 갈음할 수 없습니다.** 그것은 행을 마지막으로 손댄 시각이라
**오타 하나만 고쳐도 바뀝니다.**

| 컬럼 | 무엇 | 누가 |
|---|---|---|
| `changed_at` | **설계변경 발효일** — 이 BOM으로 만들기 시작하는 날 | **업체가 적습니다** |
| `approved_at` | **변경 승인일** | `[승인]` 누른 시각 |
| `activated_at` | 활성으로 돌린 시각 | 시스템 |

**도면 개정은 지난주에 났고 시스템에는 오늘 넣습니다.** 그래서 `changed_at`은
직접 적는 칸이고, 미래 날짜도 허용합니다 — *"다음 달 1일부터 적용"*이 됩니다.

### 승인은 기록이지 관문이 아닙니다

**승인 없이도 활성 전환은 됩니다.** 대신 `W_BOM_NO_APPROVAL`로 경고합니다.

| | |
|---|---|
| 왜 안 막나 | 대부분 **종이로 결재하고 시스템에 옮겨 적습니다.** 막으면 현장이 멈춥니다 |
| 그럼 왜 적나 | *"이 BOM 누가 승인했나"*는 **품질 감사에서 반드시 나옵니다** |
| 언제 관문이 되나 | `feature.approval`이 켜지는 **Phase 2** |

**승인 후 라인을 고치면 승인이 풀립니다** — 승인한 내용과 다른 것이 되기 때문입니다.
`approved_at` · `approved_by`가 지워지고 다시 눌러야 합니다.

**별도 이력 화면이 없습니다.** 변경 한 번이 버전 하나이므로
버전 목록이 곧 변경 이력입니다.

### 투입 지점이 소요 조건입니다

**공정 마스터가 아니라 라우팅의 줄**을 고릅니다 —
`가공 → 검사 → 가공`에서 **어느 가공인지** 공정으로는 못 가립니다.

| `routing_line_id` | 작업지시에 그 줄이 | 소요 |
|---|---|---|
| 비움 | — | **언제나** |
| 있음 | 있음 | 소요 |
| 있음 | **없음** | **소요 없음** |

**드롭다운에는 그 품목 라우팅의 줄이 순서대로** 나옵니다 — `4. 조립` 처럼.
라우팅이 없으면 이 칸이 **비활성**입니다.

### 동작

| 트리거 | 처리 |
|---|---|
| 버전 추가 | 현재 버전을 **복사**해 새 버전. **승인 정보는 복사하지 않습니다** |
| 활성 전환 | 기존 비활성 + 새 활성 **한 트랜잭션**. `activated_at` 기록 |
| 승인 | `approved_at` · `approved_by` 기록. **활성 전환과 별개** |
| 승인 후 라인 수정 | **승인이 풀립니다** — 두 칸을 비우고 다시 눌러야 합니다 |
| 라인 삭제 | 즉시 삭제(전표가 참조하지 않음 — 작업지시는 `bom_id`를 고정) |

> **BOM 변경은 진행 중 작업지시에 소급되지 않습니다.**
> 작업지시가 `bom_id`를 고정하기 때문입니다.

### 검증

- 자기 자신을 자재로 → `E_BOM_SELF`
- **순환 참조**(A→B→A) → `E_BOM_CYCLE`
- 활성 버전 0개 → `W_BOM_NO_ACTIVE`
- **승인 없이 활성 전환** → `W_BOM_NO_APPROVAL` — 막지 않고 경고만
- 변경일이 **미래** → `W_BOM_CHANGED_FUTURE` — 예정 등록이면 정상입니다
- 같은 자재 두 줄 → **허용**(투입 지점이 다르면 정상)

### 필드

| 항목 | 컬럼 | 비고 |
|---|---|---|
| 라우팅명 · 코드 | `routing.name` `routing_cd` | |
| 기본 라우팅 | `routing.is_default` | **테넌트에 하나.** 품목 등록 시점에만 적용 |
| 순서 | `routing_line.seq` | **DnD로 변경** |
| 공정 | `routing_line.process_id` | **같은 공정 중복 허용** |
| 개당 표준시간 | `routing_line.cycle_time_sec` | 수량 기반 일정의 원본 |
| 초 · 중 · 종 | `insp_first` `insp_middle` `insp_last` | **개별 on/off** |
| 선행 진행 | `routing_line.pre_approve_min` | **종물 전에 다음 공정으로** 나가는 데 필요한 승인 수. `0`이면 불가 |
| 설계 승인 | `pre_approved_by_design` | 켜면 **매번 묻지 않습니다.** 켠 사람과 시각이 남습니다 |

### 초 · 중 · 종은 개별로 켭니다

**초물과 종물만 하는 현장이 있습니다.**

| 규칙 | 내용 |
|---|---|
| 최소 하나 | 셋 다 끄면 검사 공정을 둘 이유가 없습니다 → `E_IFL_NONE` |
| **완료 기준** | **켜진 것 중 마지막**이 끝나면 공정이 닫힙니다 |
| 인쇄 · 스캔 | 꺼진 체크포인트는 **나타나지 않습니다** |

### 종물을 기다리지 않고 나갈 수 있습니다

**종물은 마지막 생산품을 봅니다.** 생산이 다 끝나야 검사할 수 있는데
그동안 뒷공정은 놉니다. 도금 · 열처리처럼 **묶어서 돌리는 공정**이 뒤에 있으면
한 배치를 놓쳐 하루가 밀립니다.

그래서 **종물 전에 다음 공정으로 나가는 길**을 둡니다. 조건은 **승인**입니다.

| 설정 | 뜻 |
|---|---|
| **불가** (`pre_approve_min = 0`) | 종전대로. 종물이 끝나야 다음 공정 |
| **승인 N명** | 그 작업지시마다 **N명이 승인**하면 진행 |
| **설계 승인** | 라우팅에서 한 번 켜면 **매번 묻지 않습니다** |

#### 설계 승인은 매번 묻지 않겠다는 선언입니다

위험이 낮아 늘 통과시키는 공정에 씁니다. **체크하는 순간 그 사람이 승인자**가 되고
`pre_approved_by` · `pre_approved_at`에 **누가 언제 켰는지** 남습니다.

> BOM 승인과 같은 원칙입니다 — 나중에 *"누가 이걸 열어 놨나"*에 답해야 합니다.
> 승인 정보 없이 체크만 남으면 **아무도 책임지지 않는 설정**이 됩니다.

#### 초물과 중물은 건너뛰지 못합니다

**켜진 것 중 종물만** 건너뜁니다.

```
초물 ✔  중물 ✔  종물 ⏳  →  승인하면 다음 공정 진행 가능
초물 ⏳                    →  승인해도 진행 불가
```

초물도 안 본 물건을 뒷공정에 넘기는 것은 **선행 진행이 아니라 검사를 안 하는 것**입니다.

**검사 공정 자체는 여전히 열려 있습니다.** 종물이 완료돼야 닫힙니다 —
선행 진행은 **다음 공정의 잠금만** 풉니다.

#### 대가는 종물 불합격입니다

| 종물 | |
|---|---|
| 합격 | 아무 일도 없습니다 |
| **불합격** | **뒷공정이 이미 진행된 상태**입니다 |

종물이 떨어지면 **선행 진행한 뒷공정에 알림을 쏘고** 그 작업지시를 추적 대상으로 올립니다.
도금까지 끝난 물건을 되돌릴 수는 없지만 **어디까지 갔는지는 알아야** 합니다.

> **막지 않고 알립니다.** 이미 벌어진 일을 시스템이 되돌릴 수 없습니다.
> 할 수 있는 것은 **누가 승인했고 어디까지 갔는지 남기는 것**뿐입니다.

### 순서를 바꿔도 BOM이 안 깨집니다

`bom_line.routing_line_id`가 **순번이 아니라 줄의 `id`**를 가리킵니다.
DnD로 순서를 바꿔도 참조가 유지됩니다.

| 동작 | BOM에 미치는 영향 |
|---|---|
| 순서 변경 | **없음** |
| 줄 추가 | 없음 (새 줄은 참조하는 BOM 라인이 없습니다) |
| **줄 삭제** | 그 줄을 가리키던 BOM 라인이 **`NULL`로** — 화면에서 다시 지정해야 합니다 |

줄을 지울 때 **참조하는 BOM 라인이 있으면 경고**합니다 — `W_ROUTING_LINE_IN_BOM`.

### 검증

- 공정 0건 → `E_ROUTING_EMPTY`
- 기본 라우팅이 2개 이상 → `E_ROUTING_MULTI_DEFAULT`
- 검사 공정이 **첫 줄** → `W_ROUTING_INSP_FIRST` (앞에 만들 것이 없습니다)
- **종물이 꺼져 있는데** 선행 진행을 켬 → `E_PRE_APPROVE_NO_LAST` — 건너뛸 것이 없습니다
- 승인 N명과 설계 승인을 **둘 다** 켬 → `E_PRE_APPROVE_BOTH` — 하나만 고릅니다
- 설계 승인을 켬 → `W_PRE_APPROVE_DESIGN` — **검사 없이 나가는 길을 상시로 여는 것**입니다

## BAS-06 창고관리

| 항목 | 컬럼 | 비고 |

| 출처 | `inspection_spec_item.master_id` | **마스터에서 골랐으면** 채워집니다. 직접 입력이면 `NULL` |

### 항목은 골라 쓰거나 새로 씁니다

**둘 다 됩니다.** `[+ 마스터에서 선택]`과 `[+ 직접 입력]` 버튼이 나란히 있습니다.

| 항목 | 마스터가 주는 것 | 기준서에서 채우는 것 |
|---|---|---|
| **치수**(외경 · 길이) | 이름 · 방법 · 단위 | **규격 · 상한 · 하한 — 필수** |
| **외관 · 표면** | 이름 · 방법 · **판정 기준까지** | 그대로 씁니다 |

**치수는 규격이 품목마다 다릅니다.** 외경 20.0 ± 0.1은 그 품목의 것이지
"외경"이라는 항목의 것이 아닙니다 — 그래서 **이름만 빌려 옵니다.**

**외관 검사는 품목이 달라도 문구가 비슷합니다.** 거기서 마스터가 값을 합니다.

#### 고르는 순간 복사됩니다

`master_id`는 **어디서 왔는지 표시일 뿐, 값을 따라가지 않습니다.**

> **마스터를 고쳐도 기존 기준서는 바뀌지 않습니다.**
> BOM · 단가와 같은 원칙입니다 — 이미 검사한 이력이 나중에 뜻이 달라지면
> **과거 판정의 근거가 사라집니다.** 새 기준서부터 새 값이 붙습니다.

> **Phase 1은 `SIMPLE` 모드**라 이 기준서를 **참고 자료로만** 씁니다.
> 값을 채워 판정하는 것은 `SHEET` 모드이고 **Phase 2**입니다
> ([정책-설정-설계.md](../정책-설정-설계.md) §6).

## BAS-10 LOT규칙관리

```
경로   기준정보 > LOT규칙관리      ⓘ feature.lot 이 꺼지면 메뉴가 없습니다
권한   조회 USR · 등록/수정 ADM
원본   lot_rule
```

```
┌─ 규칙 [생산일 기준]  [v] 사용 ───────────────────────┐
│ 기준      (●) 생산일  ( ) 자재  ( ) 종료일  ( ) 분할생산  │
│ 조합      [품목코드] + [날짜] + [순번(3)]   [+ 요소 추가]  │
│ 날짜 단위 ( ) 년도 YY  (●) 년월 YYMM  ( ) 년월일 YYMMDD  │
│ 거래처    ( ) 넣지 않음  (●) 항상  ( ) 발행 시 선택   ⓘ 입고·출하·외주만 │
│ 미리보기  PN-A-2609-001                                    │
└─────────────────────────────────────────────┘
```

| 항목 | 비고 |
|---|---|
| 기준 | 포맷 **6종** — 자재 · 생산일 · 종료일 · 분할생산 · **출하일** · **시리얼** |
| 조합 | 품목코드 · **날짜** · 순번 · 거래처(**입고·출하·외주만**) · 생산공장 · 생산라인 · 교대조 |
| 미리보기 | **입력하는 동안 실제 형태를 보여 줍니다** |

### 날짜는 세 가지 중에 고릅니다

**날짜 요소를 넣으면 세밀도를 함께 고릅니다.**

| 선택 | 형식 | 예 | 자릿수 | 미리보기 |
|---|---|---|---|---|
| 년도 | `YY` | `26` | 2 | `PN-A-26-001` |
| 년월 | `YYMM` | `2609` | 4 | `PN-A-2609-001` |
| 년월일 | `YYMMDD` | `260902` | 6 | `PN-A-260902-001` |

**어느 날짜를 쓰는지는 기준이 정합니다** —
생산일 기준이면 작업지시 시작일, 종료일 기준이면 완료일입니다.

### 순번은 날짜가 바뀔 때 리셋됩니다

**고른 세밀도가 곧 리셋 주기입니다.**

| 날짜 | 순번이 돌아오는 때 | 순번 3자리로 담기는 양 |
|---|---|---|
| `YY` | 해가 바뀔 때 | **연 999건** |
| `YYMM` | 달이 바뀔 때 | 월 999건 |
| `YYMMDD` | 날이 바뀔 때 | 일 999건 |

**날짜 요소가 없으면 리셋도 없습니다** — 순번이 계속 누적됩니다.

> **자릿수를 짧게 잡으면 언젠가 발행이 막힙니다.**
> `YY` + 순번 3자리는 **연 999건**이 상한이고, 넘는 순간 그날 작업지시가 멈춥니다.
> 화면이 **조합할 때 미리 경고**합니다.

### 거래처는 입고 · 출하 · 외주에만

**생산 LOT에는 넣지 않습니다.** 재고 기반 작업지시(`work_order.source = STOCK`)는
수주가 없어 **납품처가 아직 없고**, 그러면 같은 규칙인데 번호 형태가 달라집니다.

| 기준 | 거래처 | 들어가는 것 |
|---|---|---|
| **자재**(입고) | **넣을 수 있습니다** | **구매처** — 외주 입고면 **외주처** |
| **출하일** | **넣을 수 있습니다** | **납품처** |
| 생산일 · 종료일 · 분할생산 | **선택지에 없습니다** | — |
| 시리얼 | 없습니다 | — |

**거래처가 반드시 있는 LOT에만 넣습니다.** 전부 `lot.partner_id` 한 컬럼이고,
부르는 이름이 셋일 뿐 **자리는 하나**입니다.

#### 넣을지는 발행할 때 고를 수도 있습니다

**규칙에 박아 두는 것과 그때그때 고르는 것, 둘 다 됩니다.**

| 설정 | 발행 화면에서 |
|---|---|
| 넣지 않음 | 아무것도 묻지 않습니다 |
| **항상 넣음** | 자동으로 들어갑니다 — 담당자가 손댈 일이 없습니다 |
| **발행 시 선택** | **체크박스가 뜹니다** — 담당자가 그 건마다 고릅니다 |

```
입고등록 · 출하등록
  ┌─────────────────────────────────────┐
  │ LOT 규칙  [자재 기준 ▾]                │
  │ 거래처    [v] 번호에 넣기               │
  │ 미리보기   RM-BAR-20-PT0012-2609-001   │
  └─────────────────────────────────────┘
```

**같은 자재라도 고객사가 요구하는 건에만** 거래처를 넣는 현장이 있어
발행 시 선택을 둡니다. 체크를 풀면 **구분자까지 함께 빠집니다** — `RM-BAR-20-2609-001`.

### 출하 LOT 규칙도 여기서 만듭니다

**출하 LOT을 자동 채번하는 업체만** 씁니다 — `lot.shipment_lot = AUTO`.

| `lot.shipment_lot` | 출하등록에서 |
|---|---|
| `NONE` | **제품 LOT 그대로 나갑니다.** 이 화면과 무관합니다 |
| `AUTO` | 여기서 만든 규칙을 **골라 발행**합니다 |
| `EXTERNAL` | **고객사가 준 번호를 입력**합니다. 규칙을 쓰지 않습니다 |

**기준에 `출하일`이 하나 더 있습니다.** 원문의 4종은 생산 LOT을 위한 것이고,
출하 LOT은 **출하등록일**을 날짜로 씁니다 — 그래서 **5종**입니다.

| 기준 | 날짜로 쓰는 것 | LOT |
|---|---|---|
| 자재 | 입고일 | 자재 |
| 생산일 | 작업지시 시작일 | 생산 |
| 종료일 | 작업지시 완료일 | 생산 |
| 분할생산 | 설비 · 작업자 변경 시점 | 생산 |
| **출하일** | **출하등록일** | **출하** |
| **시리얼** | — (LOT 번호를 그대로 씁니다) | **낱개** |

### 출하 LOT에 제품 LOT을 넣을 수 있습니다

**`제품LOT + 거래처`가 실제로 쓰이는 조합입니다.**

```
출하 LOT   L-260902-001-PT0012
           └ 제품 LOT ┘ └ 거래처 ┘
```

고객사가 **출하 라벨에서 원 LOT을 바로 읽으려는 것**이 목적이라,
조합 요소 `LOT번호`를 **출하일 기준에서도** 고를 수 있습니다.

#### 넣으면 제품 LOT마다 한 장씩 나옵니다

출하 LOT은 원래 **제품 LOT을 여럿 묶습니다.** 그런데 번호에 `LOT번호`가 들어가면
**둘 중 어느 것을 넣을지 정해지지 않습니다.**

| `LOT번호` | 출하 LOT | 제품 LOT |
|---|---|---|
| 없음 | **1개** | 여럿을 묶습니다 |
| **있음** | **제품 LOT 수만큼** | **하나씩** |

```
없음   출하 LOT 1개 ─┬─ 제품 LOT A  60
                      └─ 제품 LOT B  40

있음   L-260902-001-PT0012 ─ 제품 LOT A  60
       L-260903-007-PT0012 ─ 제품 LOT B  40
```

**출하 건은 그대로 하나입니다.** 거래명세서는 한 장이고 **라벨만 여러 장** 나옵니다.
출하등록 화면이 **발행 전에 몇 장인지** 알려 줍니다.

> **묶어 놓고 번호를 지어낼 수는 없습니다.** 대표 LOT 하나만 적으면
> **라벨에 없는 LOT이 상자 안에 들어갑니다.** 고객사가 원 LOT을 번호로 요구한다는 것은
> **섞지 말라는 뜻**이기도 합니다.

### 시리얼 규칙 — 조합에 `LOT번호`가 들어갑니다

**중요 제품은 낱개마다 번호가 붙습니다**(`item.serial_use`).
시리얼은 **LOT 아래층**이라, 조합 요소에 `LOT번호`가 하나 더 있습니다.

```
기준      (●) 시리얼
조합      [LOT번호] + [순번(4)]
미리보기   L-2609-001-0001
```

| | |
|---|---|
| 기본형 | **`LOT번호 + 순번`** — 시리얼만 보면 **어느 LOT인지 바로 압니다** |
| 자릿수 | LOT 하나의 **최대 생산 수량**으로 잡습니다. 4자리면 LOT당 9,999개 |
| 리셋 | **LOT이 바뀔 때** — 날짜가 아닙니다 |
| `UNIQUE` | **겁니다.** 바코드와 정반대입니다 — 중복되면 개체 식별자가 아닙니다 |

**발번은 최종 생산 공정 실적이 확정될 때** 그 수량만큼 한 번에 만듭니다.
**불량은 발번하지 않습니다** — 폐기할 물건에 번호를 붙이지 않습니다.

> **재고는 여전히 LOT 단위입니다.** 시리얼은 그 안의 식별표일 뿐,
> `stock_ledger`를 낱개로 쪼개지 않습니다 — 쪼개면 원장이 100배가 됩니다.

**업체가 N개 등록해 두고 발행할 때 고릅니다** — 하나로 고정하지 않습니다.
생산 LOT은 작업지시에서, 출하 LOT은 출하등록에서, 시리얼은 **실적에서 자동**입니다.

> 입고 자재는 공급처 LOT을 `lot.external_lot_no`에 **그대로 받습니다.**
> 출하 LOT도 `EXTERNAL`이면 같은 자리에 **고객사 번호**가 들어갑니다.

### 검증

| 코드 | 조건 |
|---|---|
| `E_LOT_RULE_EMPTY` | 조합 요소 0개 |
| `E_LOT_DATE_UNIT` | 날짜 요소를 넣고 **세밀도를 고르지 않음** |
| `W_LOT_RULE_NO_SEQ` | 순번이 없는 조합 — 같은 날 중복 가능 |
| `W_LOT_SEQ_CAPACITY` | 세밀도 대비 **순번 자릿수가 부족** — `YY` + 3자리는 연 999건 |
| `E_LOT_PARTNER_SCOPE` | **생산 · 시리얼 기준**에 거래처를 넣음 — 입고 · 출하 · 외주만 됩니다 |
| `W_LOT_NO_SHIP_RULE` | `shipment_lot = AUTO`인데 **출하일 기준 규칙이 0건** |
| `E_SERIAL_NO_LOT` | 시리얼 기준인데 조합에 **`LOT번호`가 없음** |
| `E_LOT_NO_SCOPE` | **생산 · 입고 기준**에 `LOT번호`를 넣음 — 출하 · 시리얼만 됩니다 |
| `W_SHIP_LOT_SPLIT` | `LOT번호`가 든 출하 규칙 — **제품 LOT마다 따로 발행**됩니다 |
| `W_SERIAL_SEQ_CAPACITY` | 순번 자릿수 &lt; 품목의 **1회 최대 생산 수량** |

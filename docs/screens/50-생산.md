## 1. 테이블 ( 1단계 )

ERD §9 를 이 프로젝트 DB 규약으로. 실적 · 실행 · 선행 승인 · `wo_stock` 표는 **해당 단계에서** 만든다.

```
work_order           지시 머리
work_order_source    지시 ↔ 수주 줄 ( 분할 · 병합 — §9-3 )
work_order_op        지시의 공정 ( 라우팅에서 복사한 사본 )
work_order_material  지시의 자재 ( BOM 에서 복사한 사본 — 2단계 출고가 쓴다 )
```

### `work_order`

| 칸 | 내용 |
|---|---|
| `wo_no` | `WO-YYMMDD-NNN` ( §9-4 ) |
| `source` | `ORDER` 수주 / `STOCK` 재고 / `MANUAL` 수동 ( ADR 0012 ) |
| `production_plan_idx` | **생산계획 참조 — 자리만** ( 생산계획은 Phase 2. 개발범위 §6 *설계는 미리* — 계획 표가 생길 때 FK ) |
| `item_idx` | 만들 품목 — **제품 대분류**( 완제품 · 반제품 · 세트 ) |
| `routing_idx` | 복사해 온 라우팅 ( 표시용 — 실제 공정은 `work_order_op` ) |
| `bom_idx` | **지시 시점의 사용 중 BOM 버전 고정** — BOM 이 바뀌어도 소급되지 않음 ( ERD §9 ) |
| `lot_idx` · `lot_rule_idx` | **생산 LOT** — 지시 저장 때 발급 ( §5 ) |
| `target_qty` | 지시 수량 — 미달로 끝나도 **고치지 않는다** ( 미달은 3단계 `short_qty` ) |
| `scan_qty` | **회당 상승 수량** — 라우트시트 헤더에 인쇄 · 스캔 수량창 기본값 ( 라우트시트 §3 ) |
| `start_date` · `due_date` | 착수 예정일 · 생산 기한 |
| `status` | §6 |
| `approval_status` | Phase 1 `NONE` ( 작업지시서 결재는 Phase 2 ) |
| `remark` | 비고 |

### `work_order_op` — 라우팅의 사본

| 칸 | 내용 |
|---|---|
| `seq` | 순서 ( OP 010 · 020 … 으로 인쇄 ) — **지시에서 DnD 로 바꿀 수 있다** |
| `process_idx` | 공정 · `routing_line_idx`( 라우팅에서 왔으면 ) |
| `equipment_idx` | **지정 설비** ( 공정의 설비 후보 중 · 기본 설비가 기본값 ) — 실제 쓴 설비는 3단계 실행에 |
| `cycle_time_sec` | 개당 표준시간 ( 라우팅에서 복사 ) |
| `due_date` | **공정별 기한** ( 선택 ) |
| `worker_idx` | **작업자 지정** ( 선택 ) — 실제 작업자는 3단계 실행에 |
| `insp_first` · `insp_middle` · `insp_last` | 초 · 중 · 종 ( 초중종 검사 공정만, 라우팅에서 복사 — **라우팅이 바뀌어도 소급 안 됨** ) |
| `pre_approve_min` · `pre_approved_by_design` | 종물 전 선행 진행 승인 조건 ( 복사 — ADR 0025 ) |
| `status` · `qty` · `short_qty` · `short_reason` | 3단계에서 쓴다 — 칸만 지금 |

### `work_order_material` — BOM 의 사본

| 칸 | 내용 |
|---|---|
| `child_item_idx` · `qty_per` · `calc_code` · `ext_n01`( 절단 길이 ) | BOM 줄에서 복사 |
| `work_order_op_idx` | **투입 지점** — BOM 줄의 라우팅 줄을 지시 공정으로 옮겨 단 것 ( ADR 0007 ). 비면 첫 수량 공정 |
| `required_qty` | 소요량 — 1단계는 **`qty_per × 지시 수량`** 로 보여 주기만. 계산식( 절단 · 물림 손실 )은 2단계 출고에서 |

> BOM 을 **버전 번호로만 고정**하지 않고 줄을 복사하는 이유 — 같은 버전의 줄을 나중에 고칠 수 있어( BOM관리 ) 번호만으로는 그때의 소요가 남지 않는다.

## 3. PRD-03 작업지시 등록 · 수정 ( 모달 xl )

```
┌─ 작업지시 등록 ──────────────────────────────────────────────────────────┐
│ [기본] [공정 5] [자재 3] [첨부]                                             │
│ 출처   (●) 수동 ( ) 재고   ( 수주 기반은 수주에서 엽니다 )                     │
│ 품목 * [PN-A 완제품 A ▾]   지시 수량 * [ 500 ]   회당 상승 [ 50 ]             │
│ 착수 예정 * [10-13]  생산 기한 * [10-20]   LOT 규칙 [생산일 기본 ▾]            │
│ 라우팅 [RT-01 기본 ▾]  BOM V2 ( 사용 중 · 자재 3 )                            │
│ 수주 연결  SO-261008-001 #1  PN-A  남은 500 → [ 500 ]   [+ 수주 줄]           │
│ 비고 [                                    ]                               │
└────────────────────────────────────────────────── [취소] [등록] ─────────┘
```

### 기본 탭

| 항목 | 규칙 |
|---|---|
| 출처 | 등록 화면에서는 **수동 / 재고**. **수주**는 수주 화면에서 열 때 정해진다( §4 ) — 수주 줄을 붙이면 수주 |
| 품목 | 제품 대분류 · 사용 중. 고르면 **라우팅( 품목의 기본 라우팅 )** · **사용 중 BOM** · 회당 상승 기본값을 채운다 |
| 지시 수량 | 0 초과 |
| 회당 상승 | 기본 = 품목 포장 수량( 없으면 1 ) — 라우트시트 §3 |
| 착수 예정 · 생산 기한 | 필수. 기한 < 착수면 경고. 수주 연결이 있으면 생산 기한 기본 = 가장 이른 납품일 − 제조리드타임( 포장 · 검사 ) |
| LOT 규칙 | 생산 기준( `PRODUCE_START` 생산일 · `PRODUCE_END` 종료일 ) 사용 중 규칙 — §5 |
| 라우팅 | 기본 = 품목의 기본 라우팅. 바꾸면 **공정 탭을 그 라우팅으로 다시 채움**( 확인 후 ) |
| BOM | 사용 중 버전 표시 ( 고르지 않음 ). 없으면 **경고 후 허용** — 자재 없는 지시( 재작업 등 ) |
| 수주 연결 | §4 — 줄마다 이 지시에 담는 수량. 합 ≠ 지시 수량이면 경고 ( 초과 생산 · 일부만 담기 정상 ) |

### 공정 탭 — 라우팅 사본

```
│ ≡ │ OP  │ 공정         │ 구분 │ 설비          │ 작업자   │ 기한   │ 초 중 종 │ ✕ │
│ ≡ │ 010 │ 원자재출고   │ 시스템 │ —           │          │        │          │   │
│ ≡ │ 020 │ CNC 가공     │ 설비 │ [CNC-3 ▾]     │ [홍길동▾]│ [10-15]│          │ ✕ │
│ ≡ │ 030 │ 초중종검사   │ 검사 │ —             │          │        │ ☑ ☐ ☑   │ ✕ │
│ [+ 공정]                                                                  │
```

- **순서 DnD · 추가 · 삭제** — 원문 *"공정 순서 DnD 변경"*. 라우팅 원본은 바뀌지 않는다
- 설비는 **그 공정의 설비 후보**( BAS-04 )에서 — 설비 공정이 아니면 칸 없음
- 초 · 중 · 종은 **초중종 검사 공정**만 · 셋 다 끌 수 없음 ( 라우팅과 같은 규칙 )
- 시스템 공정 4종은 표시만 ( 3단계에서 *완료만 처리* )
- 공정을 바꾸면 **자재의 투입 지점**이 그 공정을 가리키도록 다시 맞춘다 — 지운 공정을 가리키던 자재는 **첫 수량 공정**으로

### 자재 탭 — BOM 사본 ( 1단계는 보기만 )

```
│ 자재        │ 개당 │ 소요( × 500 ) │ 투입 공정      │ 현재고 │
│ RM-BAR-20   │ 0.1  │ 50            │ 020 CNC 가공   │ 55     │
```

- 현재고는 잔고 합계( 참고 ) — 모자라도 막지 않는다 ( ADR 0008 *자재는 공정을 막지 않는다* )
- 출고 · 계산식 소요는 2단계 `INV-03`

## 4. 수주에서 지시 — 분할 · 병합

원문 *"수주 분할 · 병합 지시 / 수주 없이 단독 지시"*.

| | 내용 |
|---|---|
| 진입 | **수주 수정 창의 품목 줄에 [작업지시]** — 그 줄을 담은 지시 등록 창이 열린다 ( 출처 = 수주 ) |
| 분할 | 수주 줄 500 을 **300 + 200** 두 지시로 — 줄의 *남은 지시 수량* 을 보여 준다 |
| 병합 | 같은 품목의 **여러 수주 줄**을 한 지시에 — 지시 창의 [+ 수주 줄] ( 같은 품목 · 확정 수주 · 남은 지시 수량이 있는 줄 ) |
| 남은 지시 수량 | 수주 줄 수량 − 그 줄을 담은 지시들의 담은 수량( 취소 제외 ) |
| 표 | `work_order_source( work_order_idx, sales_order_line_idx, qty )` — 지시 하나에 수주 줄 여럿, 수주 줄 하나에 지시 여럿 |
| 수주 잠금 | 지시가 붙은 수주 줄은 **품목 변경 · 삭제 불가** — 수주의 *아래 단계 있음* 판정( `hasDownstream` )에 지시를 더한다 |

## 5. 생산 LOT

ADR 0020 *LOT은 재고가 움직이기 전에 발행한다* — 라우트시트에 LOT 이 인쇄되므로 **지시 저장 때** 발급한다.

| | |
|---|---|
| 규칙 | LOT규칙관리의 **생산 기준**( `PRODUCE_START` 생산일 / `PRODUCE_END` 종료일 ) 사용 중 규칙 — 여럿이면 고른다 |
| 번호의 날짜 | 생산일 기준 = **착수 예정일** / 종료일 기준 = **생산 기한** ( §9-5 ) |
| 거래처 요소 | 생산 기준에는 넣을 수 없다 ( BAS-10 규칙 — 거래처는 입고 · 출하만 ) |
| 순번 | 입고와 같은 `lot_seq` |
| 규칙이 없으면 | 저장 막음 + 안내 ( 입고와 같다 ) · `feature.lot` 꺼짐이면 LOT 없이 |
| 분할생산( `SPLIT` ) | 설비 · 작업자가 바뀔 때 새 LOT — **3단계** 실적에서 |
| 취소 | 지시를 취소해도 LOT 은 남는다 ( 미사용 — 번호 재사용 없음 ) |
| 재고 | LOT 은 생기지만 **재고는 3단계 완료 때** ( `in_at` 도 그때 ) |

## 6. 상태 · 수정 · 취소

```
대기( WAIT ) ──첫 실적( 3단계 )──▶ 진행( RUN ) ──모든 공정 종료──▶ 완료( DONE )
     │
     └──[취소]──▶ 취소( CANCELED )
```

| 상태 | 고칠 수 있는 것 |
|---|---|
| 대기 | **전부** — 품목 · 수량 · 공정 · 수주 연결 · 날짜 ( 품목을 바꾸면 LOT 은 그대로 — 번호에 품번이 있으면 §9-7 ) |
| 진행 | 날짜 · 공정별 기한 · 작업자 · 비고만 ( 수량 · 공정 구성 잠금 — 3단계 ) |
| 완료 · 취소 | 읽기 전용 |

- [취소]는 **대기**만 — 진행 중 지시는 3단계의 *미달 종료* 로 닫는다 ( 지시 수량은 고치지 않는다 — ERD §9 )
- 삭제는 없다 — LOT 이 이미 발급되어 라벨이 나갔을 수 있다 ( 취소로 남긴다 )

# 1단계 보완 — 작업지시서( 머리 ) · 여러 품목

> 작성일: 2026-10-28 · 상태: **확정 · 구현 완료** ( §B-8 — 사용자 판단 2026-10-28 )
> 구현하며 정한 것 — 화면이 보내지 않은 저장된 줄은 그대로 둔다( 줄을 빼는 것은 [줄 취소] ) · 줄 오류는 `lines.{n}.*` 로 그 줄에 표시 · 줄 경고는 줄 번호를 붙이고 날짜 경고는 지시서에서 한 번 · 지시서의 [+ 수주 줄]은 제품 대분류 수주 줄만 · 지시서 칸은 지시서가 대기 · 진행일 때 고침
> 배경 : 현장에서 **여러 생산계획 · 여러 품목을 작업지시 한 장**으로 만드는 경우가 있다. 지금 작업지시는 품목 하나 기준.

## B-1. 방향 — 지금 작업지시 위에 "지시서"를 얹는다

```
작업지시서  WO-261028-001          ← 새로 ( 사람이 보는 "작업지시" 한 장 · 착수 · 기한 · 담당 · 비고 )
 ├─ 품목 줄 WO-261028-001-01  PN-A 완제품 A  100   ← 지금의 work_order 그대로
 ├─ 품목 줄 WO-261028-001-02  PN-B 완제품 B   50      ( 라우팅 · BOM 사본 · 공정 · 자재 · 생산 LOT 을 줄마다 )
 └─ 품목 줄 WO-261028-001-03  PN-A 완제품 A  200
```

- 사람에게는 **지시서 한 장에 여러 품목** · 시스템 안에서는 **품목 줄 하나 = 지금의 작업지시 하나**
- 그래서 지시 서비스 · 자재출고 · 공정 복사 · LOT 발급은 **줄 단위 그대로** 쓴다
- 품목이 하나뿐인 지시 = 줄이 하나인 지시서
- **품목 줄 하나 = 제품 LOT 하나** ( 작업내역 E-2 )

다시 만들기( 작업지시 자체를 머리 + 줄 구조로 )는 버린다 — 서비스 · 자재출고 · 공정 복사 · LOT 을 전부 다시 써야 한다.

## B-2. 테이블

```
work_order_sheet     지시서 ( 새로 )
work_order           품목 줄 ( 기존 — sheet_idx · line_no 추가 )
work_order_source    품목 줄 ↔ 수주 줄 ( 기존 그대로 · 생산계획 칸은 계획 화면이 생길 때 )
```

### `work_order_sheet` ( 새로 )

| 칸 | 내용 |
|---|---|
| `sheet_no` | `WO-YYMMDD-NNN` ( 지금의 지시번호 규칙 — 날짜는 지시한 날 ) |
| `start_date` · `due_date` | 착수 예정일 · 생산 기한 — **지시서에만 입력** ( 품목 줄마다 두지 않음 ) |
| `manager_idx` | 담당자 ( **사용자 목록**에서 고름 · 선택 ) |
| `status` | 품목 줄에서 정해진다 ( B-5 ) |
| `remark` | 비고 |

### `work_order` ( 기존 = 품목 줄 )

| 칸 | 바뀌는 것 |
|---|---|
| `sheet_idx` · `line_no` | **추가** — 지시서 · 줄 순번( 01, 02 … ) |
| `wo_no` | 줄 번호 `WO-261028-001-01` ( 지시서 번호 + 순번 ) |
| `start_date` · `due_date` | 칸은 남기고 **지시서 값을 복사**해 둔다 — LOT 번호의 날짜 · 기존 조회가 그대로 쓰도록. 화면에서는 고치지 않음 |
| `approval_status` | 그대로 ( 결재 · 첨부는 품목 줄 단위 — B-8 #7 ) |
| 나머지 | 그대로 — 품목 · 라우팅 · BOM · 생산 LOT · 지시 수량 · 회당 상승 · 상태 |

│ ☐ │ ▾ WO-261028-001     │ PN-A 외 1건         │      │            │ 2026-10-29 │ 2026-11-05 │               │      │ 진행 │
│   │    WO-261028-001-01 │ PN-A 완제품 A        │ 100  │ P-2610-011 │            │            │ SO-261020-003 │ 2/5  │ 진행 │
│   │    WO-261028-001-02 │ PN-B 완제품 B        │ 50   │ P-2610-012 │            │            │ —             │ 0/4  │ 대기 │
│ ☐ │ ▸ WO-261028-002     │ PN-C 완제품 C        │ 300  │ P-2610-013 │ 2026-10-30 │ 2026-11-10 │ SO-261021-001 │ 0/3  │ 대기 │

- 검색 · 기간 · 상태 거르기는 지금과 같음 ( 품목 · LOT · 수주번호로 찾으면 그 줄이 든 지시서 )
- 행 클릭 → 지시서 수정 창 ( 품목 줄을 클릭하면 그 줄이 선택된 채로 )
- 체크는 지시서 단위 → [취소] ( B-6 )

## B-4. PRD-03 작업지시서 등록 · 수정 ( 모달 xl )

```
┌─ 작업지시서 등록 ─────────────────────────────────────────────────────────────┐
│ 착수 예정 * [10-29]  생산 기한 * [11-05]  담당 [홍길동 ▾]  비고 [            ]    │
│ ─ 품목 줄 ───────────────────────────────────── [+ 품목] [+ 수주 줄] ──────── │
│ │ 01 │ PN-A 완제품 A │ 100 │ 대기 │ ✕ │   ┌ [기본] [공정 5] [자재 3] [첨부] ── │
│ │ 02 │ PN-B 완제품 B │  50 │ 대기 │ ✕ │   │ ( 선택한 품목 줄 — 지금 지시 창의 탭 ) │
│                                         │   품목 · 수량 · 회당 상승 · LOT 규칙 · │
│                                         │   라우팅 · BOM · 수주 연결           │
└──────────────────────────────────────────── [줄 취소] [지시서 취소] [저장] ───┘
```

| 항목 | 규칙 |
|---|---|
| 지시서 칸 | 착수 예정 · 생산 기한 필수 ( 기한 < 착수면 경고 — 지금과 같음 ). **모든 품목 줄에 적용** |
| [+ 품목] | 빈 품목 줄 추가 ( 출처 수동 / 재고 ) — 줄의 기본 탭은 지금 지시 창의 기본 탭에서 날짜만 뺀 것 |
| [+ 수주 줄] | 확정 수주에서 남은 지시 수량이 있는 줄을 고른다. **같은 품목 줄이 있으면 그 줄에 병합**, 없으면 새 품목 줄 |
| 병합 이력 | 품목 줄의 기본 탭 *수주 연결* 에 수주 줄마다 **담은 수량 · 추가한 사람 · 일시** — 저장해도 유지 ( 연결을 지우고 다시 넣지 않고 바뀐 것만 고침 ) |
| 품목 줄 ✕ | 아직 저장 안 한 줄만 지움. 저장한 줄은 [줄 취소] ( LOT 이 발급됨 ) |
| 공정 · 자재 탭 | 선택한 품목 줄 기준 — 지금과 같음 ( 공정 DnD · 설비 · 작업자 · 초중종 · 자재 보기 · [출고] ) |
| 첨부 | **품목 줄 단위** ( 지금처럼 — 선택한 줄의 [첨부] 탭 ) |
| 저장 | 지시서 + 모든 품목 줄을 **한 트랜잭션** — 하나라도 실패하면 전부 취소. LOT 은 줄마다 발급 ( 지금 규칙 ) |
| 수주에서 열기 | 수주 줄 [작업지시] → 그 줄을 담은 **줄 하나짜리 지시서** 등록 창 ( 지금 흐름 그대로 ) |

## B-5. 상태

품목 줄의 상태는 지금 그대로( 대기 → 진행 → 완료 · 취소 ). 지시서 상태는 **줄에서 정해진다**.

| 지시서 | 조건 |
|---|---|
| 대기 | 취소 안 된 줄이 모두 대기 |
| 진행 | 진행 중인 줄이 하나라도 있음 ( 또는 일부 완료 · 일부 대기 ) |
| 완료 | 취소 안 된 줄이 모두 완료 |
| 취소 | 모든 줄이 취소 |

고칠 수 있는 것

| | |
|---|---|
| 지시서 칸 ( 날짜 · 담당 · 비고 ) | 지시서가 완료 · 취소가 아니면 — 날짜를 바꾸면 줄에 복사 ( LOT 은 다시 발급하지 않음 — 지금 규칙 ) |
| 품목 줄 추가 | 지시서가 완료 · 취소가 아니면 |
| 품목 줄 내용 | 줄 상태 규칙 그대로 ( 대기 = 전부 · 진행 = 공정 기한 · 작업자 · 비고 · 완료 / 취소 = 읽기 전용 ) |

## B-6. 취소 — 줄 하나 / 지시서 전체 둘 다

| | 규칙 |
|---|---|
| [줄 취소] | 대기인 품목 줄만 ( 지금 규칙 ) — 그 줄의 LOT 은 미사용으로 남음 · 수주 남은 지시 수량 되돌아감 |
| [지시서 취소] | **모든 줄이 대기일 때** 전부 취소. 진행 · 완료 줄이 있으면 막고 안내 ( 제안 — B-8 #6 ) |
| 출고된 줄 | 지금 규칙 그대로 막음 ( 출고 취소 먼저 ) |

| 화면 · 기능 | 바뀌는 것 |

# 2단계 — `INV-03` 자재출고

> 작성일: 2026-10-12 · 상태: **2단계( INV-03 자재출고 ) 확정 · 구현 완료** ( §17 제안대로 — 사용자 판단 2026-10-12 )
> 근거 : [자재소요-계산-설계](../자재소요-계산-설계.md) §2-9 · [재고-수불-설계](../재고-수불-설계.md) §9.2-1 · ERD §7 `wo_stock` · 40-구매자재 §20-1

## 10. 무엇을 하는가

**창고 → 작업지시** 로 자재를 낸다. 출고는 언제나 **작업지시에 묶인다**( 지시 없는 출고는 재고조정 · 창고이동 ).

```
작업지시 고름 → 자재 줄마다 계산식으로 소요 계산 → 선입선출로 LOT 채움( 고칠 수 있음 ) → 출고 확정
                                                                     │
                                       원장 OUT( 참조 WORK_ORDER ) ──┤
                                       wo_stock.issued_qty +  ───────┘   ← 창고 재고는 줄고, 지시가 보유
```

- **사용처리( 투입 )는 3단계** — 원장에 남지 않고 `wo_stock.consumed_qty` 만 오른다 ( 재고-수불 §9.2-1 )
- **자재는 공정을 막지 않는다** — 출고 · 공정 시작 · 투입은 순서 무관 ( 계산 설계 §9.1-9.2 ). 3단계의 *투입 시 미출고분 자동 출고* 도 이 단계의 출고 서비스를 그대로 쓴다

## 11. 테이블

| 표 | 내용 |
|---|---|
| `calc_def` **( 새로 )** | 계산식 정의 — `calc_code` · `name` · `expr` · `result_kind`( QTY / SPEC_COUNT / WEIGHT ) · `sample_json` · `is_builtin`. **내장 3종 시드**: `BOM_BASIC` · `BOM_LOSS` · `BAR_CUT`. 등록 화면( `SYS-13` )은 Phase 2 |
| `wo_stock` **( 새로 )** | 지시가 보유한 자재 — `work_order_idx` · `item_idx` · `lot_idx`( 0 = LOT 미사용 ) **PK** · `issued_qty` · `consumed_qty` · `qty`( = 출고 − 사용 ). **출고할 때만 원장에 OUT**, 사용은 이 표만 |
| `stock_txn` | `txn_type = ISSUE_WO` · 번호 **`IS-YYMMDD-NNN`** · 줄마다 `work_order_idx` · `work_order_material_idx` · `consumed_qty`( 출고와 함께 사용처리한 몫 — 취소 때 같이 되돌림 ) ( 새 칸 ) |
| `work_order_material` | `issued_qty` 칸 추가 ( 줄별 출고 합계 — 목록 · 자재 탭 표시용, 전표에서 다시 계산 가능 ) |

> `calc_def` 위치 — 설계는 *공용 DB* 지만 ADR 0027( 업체별 설치 · `tenant_id` 없음 )이라 **업체 DB 에 둔다.** 내장 식은 시더가 매번 덮어써 업체끼리 같게 유지.

## 13. 소요 계산

계산 설계 §6 그대로. 줄마다 :

| 단계 | 내용 |
|---|---|
| 식 결정 | `work_order_material.calc_code` → 자재 품목 `calc_code` → 정책 `material.issue_calc` → `BOM_BASIC` |
| 변수 | `ORDER_QTY` 지시 수량 · `BOM_QTY` 개당 · `SPEC` LOT 규격 · `PACK` · `STOCK` · `ISSUED` · `REMAIN` · `SETUP` · `CUT`( 자재 줄 `ext_n01` ) · `KERF` · `LOSS` ( §17-3 ) |
| `SETUP` | 투입 공정( `work_order_op_idx`, 없으면 첫 수량 공정 )의 **지정 설비** `setup_loss` → 없으면 **후보 중 최댓값**( `W_SETUP` ) → 시스템 · 검사 공정 0 |
| `SPEC` 이 식에 있으면 | 재고가 있는 **규격별로 따로 계산** · 채취 0 개 · `min_usable_spec` 미만 LOT 제외. 기본은 **가장 큰 규격** 에만 수량 |
| 후처리 | `QTY` · `SPEC_COUNT` → 올림 정수 / `WEIGHT` → 소수 3자리 |
| 경고 | `W_NULL` · `W_DIV0` · `W_NEG` · `W_OVER` · `W_SETUP` · `W_NOLOT` — **막지 않는다** |

**기본 출고 수량 = 계산 − 이미 출고**( 0 미만이면 0 ). 시스템이 몰래 빼지 않는다는 원칙( 계산 설계 §6.1 )과 다르게 보일 수 있지만, 식의 결과( ⓘ )는 그대로 보이고 *이미 출고* 를 옆에 나란히 보인다.

## 14. LOT 채우기

| 항목 | 내용 |
|---|---|
| 후보 | 그 자재의 **잔고 > 0** 인 LOT × 창고 ( 검사대기 · 불합격 = `in_at` NULL 제외 ) |
| 정렬 | **선입선출** `in_at` → LOT 번호. 정책 `stock.remnant_consume = REMNANT_FIRST` 면 **잔재 LOT( `parent_lot_idx` 있음 ) 먼저** ( 잔재 재입고는 Phase 2 라 지금은 효과 없음 ) |
| 자동 채움 | 정책 `material.consume_mode`( 품목 스코프 ) `AUTO` → 선입선출로 위에서부터 채움 / `MANUAL` → **비워 두고** 사람이 고름 |
| 한도 | 한 LOT 줄에 **그 잔고보다 많이 낼 수 없다** ( 실물이 없는 조각 ). 모자라는 몫은 *부족 n* 경고만 — 음수 재고는 3단계 자동 출고에서만 생긴다 |
| 창고 | **사용 중 창고** 전부 ( 창고별 권한은 아직 없다 — `can_move` 는 메뉴 권한이라 창고를 거르지 못함 ) |

## 15. 출고 확정 · 취소

- 확정 : 한 트랜잭션 — 전표 `ISSUE_WO` + 줄 → `StockService::post()` 로 원장 OUT · 잔고 − → `wo_stock` upsert( `issued_qty` + ) → `work_order_material.issued_qty` +
- 정책 `material.consume_timing = ISSUE` 면 **같은 자리에서 사용처리** 까지( `consumed_qty` + ). `PROCESS_START` · `MANUAL` 은 3단계
- 시각 : 출고일시는 소급 규칙( `checkBackdate` ) 그대로 · 미래 금지
- 대상 지시 : **대기 · 진행**만. 완료 · 취소된 지시는 출고 불가
- **취소** : 전표 줄 단위로 **역분개**( `StockService::reverse()` ) → `wo_stock` · `issued_qty` −. **그 LOT 의 보유분( 출고 − 사용 )이 취소 수량 이상일 때만** — 이미 쓴 것은 취소할 수 없다
- 반납( 쓰고 남은 보유분을 창고로 ) · 잔재 재입고는 **Phase 2** ( 재고-수불 §9.2-1 )

## 16. 이번에 하지 않는 것

사용처리 화면 · 투입 시 자동 출고( 3단계 ) · 반납 · 잔재 재입고 · 계산식 등록 화면 `SYS-13` · 기능형 커스텀 컬럼 정의( `var_name` ) · `WEIGHT` 계산( `COIL_WEIGHT` ) · 식별표 스캔 출고 · 수주연동 차감( `consume_source = ORDER_LINKED` )

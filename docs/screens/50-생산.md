## 1. 테이블 ( 1단계 )

ERD §9 를 이 프로젝트 DB 규약으로. 실적 · 실행 · 선행 승인 · `wo_stock` 표는 **해당 단계에서** 만든다.

```
work_order           지시 머리
work_order_source    지시 ↔ 수주 줄 ( 분할 · 병합 — §9-3 )
work_order_op        지시의 공정 ( 라우팅에서 복사한 사본 )
work_order_material  지시의 자재 ( BOM 에서 복사한 사본 — 2단계 출고가 쓴다 )
```

### `work_order`

| 칸 | 내용 |
|---|---|
| `wo_no` | `WO-YYMMDD-NNN` ( §9-4 ) |
| `source` | `ORDER` 수주 / `STOCK` 재고 / `MANUAL` 수동 ( ADR 0012 ) |
| `item_idx` | 만들 품목 — **제품 대분류**( 완제품 · 반제품 · 세트 ) |
| `routing_idx` | 복사해 온 라우팅 ( 표시용 — 실제 공정은 `work_order_op` ) |
| `bom_idx` | **지시 시점의 사용 중 BOM 버전 고정** — BOM 이 바뀌어도 소급되지 않음 ( ERD §9 ) |
| `lot_idx` · `lot_rule_idx` | **생산 LOT** — 지시 저장 때 발급 ( §5 ) |
| `target_qty` | 지시 수량 — 미달로 끝나도 **고치지 않는다** ( 미달은 3단계 `short_qty` ) |
| `scan_qty` | **회당 상승 수량** — 라우트시트 헤더에 인쇄 · 스캔 수량창 기본값 ( 라우트시트 §3 ) |
| `start_date` · `due_date` | 착수 예정일 · 생산 기한 |
| `status` | §6 |
| `approval_status` | Phase 1 `NONE` ( 작업지시서 결재는 Phase 2 ) |
| `remark` | 비고 |

### `work_order_op` — 라우팅의 사본

| 칸 | 내용 |
|---|---|
| `seq` | 순서 ( OP 010 · 020 … 으로 인쇄 ) — **지시에서 DnD 로 바꿀 수 있다** |
| `process_idx` | 공정 · `routing_line_idx`( 라우팅에서 왔으면 ) |
| `equipment_idx` | **지정 설비** ( 공정의 설비 후보 중 · 기본 설비가 기본값 ) — 실제 쓴 설비는 3단계 실행에 |
| `cycle_time_sec` | 개당 표준시간 ( 라우팅에서 복사 ) |
| `due_date` | **공정별 기한** ( 선택 ) |
| `worker_idx` | **작업자 지정** ( 선택 ) — 실제 작업자는 3단계 실행에 |
| `insp_first` · `insp_middle` · `insp_last` | 초 · 중 · 종 ( 초중종 검사 공정만, 라우팅에서 복사 — **라우팅이 바뀌어도 소급 안 됨** ) |
| `pre_approve_min` · `pre_approved_by_design` | 종물 전 선행 진행 승인 조건 ( 복사 — ADR 0025 ) |
| `status` · `qty` · `short_qty` · `short_reason` | 3단계에서 쓴다 — 칸만 지금 |

### `work_order_material` — BOM 의 사본

| 칸 | 내용 |
|---|---|
| `child_item_idx` · `qty_per` · `calc_code` · `ext_n01`( 절단 길이 ) | BOM 줄에서 복사 |
| `work_order_op_idx` | **투입 지점** — BOM 줄의 라우팅 줄을 지시 공정으로 옮겨 단 것 ( ADR 0007 ). 비면 첫 수량 공정 |
| `required_qty` | 소요량 — 1단계는 **`qty_per × 지시 수량`** 로 보여 주기만. 계산식( 절단 · 물림 손실 )은 2단계 출고에서 |

> BOM 을 **버전 번호로만 고정**하지 않고 줄을 복사하는 이유 — 같은 버전의 줄을 나중에 고칠 수 있어( BOM관리 ) 번호만으로는 그때의 소요가 남지 않는다.

## 3. PRD-03 작업지시 등록 · 수정 ( 모달 xl )

```
┌─ 작업지시 등록 ──────────────────────────────────────────────────────────┐
│ [기본] [공정 5] [자재 3] [첨부]                                             │
│ 출처   (●) 수동 ( ) 재고   ( 수주 기반은 수주에서 엽니다 )                     │
│ 품목 * [PN-A 완제품 A ▾]   지시 수량 * [ 500 ]   회당 상승 [ 50 ]             │
│ 착수 예정 * [10-13]  생산 기한 * [10-20]   LOT 규칙 [생산일 기본 ▾]            │
│ 라우팅 [RT-01 기본 ▾]  BOM V2 ( 사용 중 · 자재 3 )                            │
│ 수주 연결  SO-261008-001 #1  PN-A  남은 500 → [ 500 ]   [+ 수주 줄]           │
│ 비고 [                                    ]                               │
└────────────────────────────────────────────────── [취소] [등록] ─────────┘
```

### 기본 탭

| 항목 | 규칙 |
|---|---|
| 출처 | 등록 화면에서는 **수동 / 재고**. **수주**는 수주 화면에서 열 때 정해진다( §4 ) — 수주 줄을 붙이면 수주 |
| 품목 | 제품 대분류 · 사용 중. 고르면 **라우팅( 품목의 기본 라우팅 )** · **사용 중 BOM** · 회당 상승 기본값을 채운다 |
| 지시 수량 | 0 초과 |
| 회당 상승 | 기본 = 품목 포장 수량( 없으면 1 ) — 라우트시트 §3 |
| 착수 예정 · 생산 기한 | 필수. 기한 < 착수면 경고. 수주 연결이 있으면 생산 기한 기본 = 가장 이른 납품일 − 제조리드타임( 포장 · 검사 ) |
| LOT 규칙 | 생산 기준( `PRODUCE_START` 생산일 · `PRODUCE_END` 종료일 ) 사용 중 규칙 — §5 |
| 라우팅 | 기본 = 품목의 기본 라우팅. 바꾸면 **공정 탭을 그 라우팅으로 다시 채움**( 확인 후 ) |
| BOM | 사용 중 버전 표시 ( 고르지 않음 ). 없으면 **경고 후 허용** — 자재 없는 지시( 재작업 등 ) |
| 수주 연결 | §4 — 줄마다 이 지시에 담는 수량. 합 ≠ 지시 수량이면 경고 ( 초과 생산 · 일부만 담기 정상 ) |

### 공정 탭 — 라우팅 사본

```
│ ≡ │ OP  │ 공정         │ 구분 │ 설비          │ 작업자   │ 기한   │ 초 중 종 │ ✕ │
│ ≡ │ 010 │ 원자재출고   │ 시스템 │ —           │          │        │          │   │
│ ≡ │ 020 │ CNC 가공     │ 설비 │ [CNC-3 ▾]     │ [홍길동▾]│ [10-15]│          │ ✕ │
│ ≡ │ 030 │ 초중종검사   │ 검사 │ —             │          │        │ ☑ ☐ ☑   │ ✕ │
│ [+ 공정]                                                                  │
```

- **순서 DnD · 추가 · 삭제** — 원문 *"공정 순서 DnD 변경"*. 라우팅 원본은 바뀌지 않는다
- 설비는 **그 공정의 설비 후보**( BAS-04 )에서 — 설비 공정이 아니면 칸 없음
- 초 · 중 · 종은 **초중종 검사 공정**만 · 셋 다 끌 수 없음 ( 라우팅과 같은 규칙 )
- 시스템 공정 4종은 표시만 ( 3단계에서 *완료만 처리* )
- 공정을 바꾸면 **자재의 투입 지점**이 그 공정을 가리키도록 다시 맞춘다 — 지운 공정을 가리키던 자재는 **첫 수량 공정**으로

### 자재 탭 — BOM 사본 ( 1단계는 보기만 )

```
│ 자재        │ 개당 │ 소요( × 500 ) │ 투입 공정      │ 현재고 │
│ RM-BAR-20   │ 0.1  │ 50            │ 020 CNC 가공   │ 55     │
```

- 현재고는 잔고 합계( 참고 ) — 모자라도 막지 않는다 ( ADR 0008 *자재는 공정을 막지 않는다* )
- 출고 · 계산식 소요는 2단계 `INV-03`

## 4. 수주에서 지시 — 분할 · 병합

원문 *"수주 분할 · 병합 지시 / 수주 없이 단독 지시"*.

| | 내용 |
|---|---|
| 진입 | **수주 수정 창의 품목 줄에 [작업지시]** — 그 줄을 담은 지시 등록 창이 열린다 ( 출처 = 수주 ) |
| 분할 | 수주 줄 500 을 **300 + 200** 두 지시로 — 줄의 *남은 지시 수량* 을 보여 준다 |
| 병합 | 같은 품목의 **여러 수주 줄**을 한 지시에 — 지시 창의 [+ 수주 줄] ( 같은 품목 · 확정 수주 · 남은 지시 수량이 있는 줄 ) |
| 남은 지시 수량 | 수주 줄 수량 − 그 줄을 담은 지시들의 담은 수량( 취소 제외 ) |
| 표 | `work_order_source( work_order_idx, sales_order_line_idx, qty )` — 지시 하나에 수주 줄 여럿, 수주 줄 하나에 지시 여럿 |
| 수주 잠금 | 지시가 붙은 수주 줄은 **품목 변경 · 삭제 불가** — 수주의 *아래 단계 있음* 판정( `hasDownstream` )에 지시를 더한다 |

## 5. 생산 LOT

ADR 0020 *LOT은 재고가 움직이기 전에 발행한다* — 라우트시트에 LOT 이 인쇄되므로 **지시 저장 때** 발급한다.

| | |
|---|---|
| 규칙 | LOT규칙관리의 **생산 기준**( `PRODUCE_START` 생산일 / `PRODUCE_END` 종료일 ) 사용 중 규칙 — 여럿이면 고른다 |
| 번호의 날짜 | 생산일 기준 = **착수 예정일** / 종료일 기준 = **생산 기한** ( §9-5 ) |
| 거래처 요소 | 생산 기준에는 넣을 수 없다 ( BAS-10 규칙 — 거래처는 입고 · 출하만 ) |
| 순번 | 입고와 같은 `lot_seq` |
| 규칙이 없으면 | 저장 막음 + 안내 ( 입고와 같다 ) · `feature.lot` 꺼짐이면 LOT 없이 |
| 분할생산( `SPLIT` ) | 설비 · 작업자가 바뀔 때 새 LOT — **3단계** 실적에서 |
| 취소 | 지시를 취소해도 LOT 은 남는다 ( 미사용 — 번호 재사용 없음 ) |
| 재고 | LOT 은 생기지만 **재고는 3단계 완료 때** ( `in_at` 도 그때 ) |

## 6. 상태 · 수정 · 취소

```
대기( WAIT ) ──첫 실적( 3단계 )──▶ 진행( RUN ) ──모든 공정 종료──▶ 완료( DONE )
     │
     └──[취소]──▶ 취소( CANCELED )
```

| 상태 | 고칠 수 있는 것 |
|---|---|
| 대기 | **전부** — 품목 · 수량 · 공정 · 수주 연결 · 날짜 ( 품목을 바꾸면 LOT 은 그대로 — 번호에 품번이 있으면 §9-7 ) |
| 진행 | 날짜 · 공정별 기한 · 작업자 · 비고만 ( 수량 · 공정 구성 잠금 — 3단계 ) |
| 완료 · 취소 | 읽기 전용 |

- [취소]는 **대기**만 — 진행 중 지시는 3단계의 *미달 종료* 로 닫는다 ( 지시 수량은 고치지 않는다 — ERD §9 )
- 삭제는 없다 — LOT 이 이미 발급되어 라벨이 나갔을 수 있다 ( 취소로 남긴다 )

| 3 | **수주 연결** | 연결 표( `work_order_source` )로 **분할 · 병합 둘 다** 처음부터. 남은 지시 수량 초과는 경고만 | 수주 줄 FK 하나( 분할만 ) — 병합이 필요해지면 표를 바꿔야 함 |
| 4 | 번호 · 상태 | `WO-YYMMDD-NNN` · 대기 / 진행 / 완료 / 취소 · 취소는 대기만 | |
| 5 | **LOT 날짜** | 지시 저장 때 발급 · 생산일 기준 = 착수 예정일 / 종료일 기준 = 생산 기한 | 종료일 기준 규칙은 완료 때 발급 ( 그러면 라우트시트에 LOT 이 없다 ) |
| 6 | **메뉴** | 생산관리 하위에 작업지시 메뉴가 **없다** ( 생산계획관리 · 공정실적관리 · 생산실적현황 · 생산일정관리 · 외주관리 ) → **생산관리 > 작업지시( 4006 )** 를 새로 만들고 생산계획관리 다음 순서에 둔다 | 생산계획관리( 4001 )를 작업지시로 쓴다 ( 계획은 Phase 2 라 비어 있음 ) |
| 7 | 대기 중 품목 변경 | 허용하되 **LOT 을 새로 발급**( 기존 번호는 미사용으로 남김 ) — 번호에 품번이 들어가 있을 수 있음 | 품목 변경 막음 ( 취소 후 새로 ) |
| 8 | 코드 위치 | 패키지 `MesCore\Production` · `config('mes.modules')` 의 `Production` | |

> 구현하며 정한 것 — 지시번호의 날짜는 **지시한 날**. 선행 진행 승인 조건 · 표준시간은 화면 값을 믿지 않고 **라우팅 줄에서 다시 읽는다**. 자재 사본은 대기 상태에서 저장할 때마다 **그때의 사용 중 BOM 으로 다시 복사**한다. 수주 수정 창의 품목 줄에 *지시 수량* 과 [작업지시]( 남은 지시 수량이 있을 때 )

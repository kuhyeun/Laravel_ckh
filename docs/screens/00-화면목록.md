## 3. 공통 컴포넌트 — 0순위

**화면이 아니라 부품입니다.** 59개 화면 대부분이 이걸 쓰므로 **가장 먼저** 만듭니다.
여기서 흔들리면 전 화면을 다시 손봅니다.

| ID | 컴포넌트 | 내용 | 난이도 |
|---|---|---|---|
| `CMP-01` | **목록 그리드** | **첫 컬럼에 상세보기 버튼 고정**(원문 요건) · 정렬 · 페이징 · 엑셀 내보내기 · **커스텀 컬럼 슬롯 전파** | 상 |
| `CMP-02` | **공통 검색바** | 기간(기본값이 **정책**) + 검색어 + 상세검색. 품목 · 수주 · 작업지시 팝업 검색 | 중 |
| `CMP-03` | **첨부파일** | `attachment.ref_type` + `ref_id`로 어디에나 붙음. 구분 코드(성적서 · 밀시트 · 도면) | 하 |
| `CMP-04` | **바코드 스캔 입력** | 스캐너 입력 수신 · 엔터 확정 · 오독 처리. 스캔 화면 전부가 씀 | 중 |
| `CMP-05` | **실행 결과 알림** | **서버가 내려준 `notice`를 띄웁니다** — 문구를 화면이 정하지 않습니다. 성공 3초 · 경고 수동 닫기 → [프로그램-스펙 §6.1](../프로그램-스펙.md) | 하 |

| `CMP-07` | **등록 폼 뼈대** | 제목 · 필수 표시 · 버튼 줄 · 저장 중 잠금 · **이탈 경고** | 하 |
| `CMP-08` | **기간 입력** | 프리셋 · 최대 기간. 기본값은 `CMP-02`가 정책에서 넣습니다 | 하 |

> **부품은 만들 때마다 [`01-공통컴포넌트.md`](./01-공통컴포넌트.md)에 기록합니다.**
> props · emits · slots · **쓰는 화면 목록**이 거기 있고, **코드가 아니라 그 문서가 계약**입니다.

> `CMP-01`은 **커스텀 컬럼**([커스텀-컬럼-설계.md](../커스텀-컬럼-설계.md))과 맞물립니다.
> 슬롯 컬럼이 목록 · 검색 · 정렬 · 엑셀에 자동으로 나타나야 하므로 그리드가 정의를 읽어 그립니다.

## 4-1. 모든 화면이 지키는 것

| 규칙 | 내용 |
|---|---|
| **상단 로그인 표시** | **이름 · 부서**를 모든 화면 상단에. 레이아웃에 한 번 두고 화면이 관여하지 않습니다 |
| **작업자 기본값** | 실적 입력의 작업자는 **로그인 사용자로 채워지고 바꿀 수 있습니다** |
| **입력자 분리** | `created_by`(입력자)는 **서버가 쓰고 못 바꿉니다.** 작업자와 다르면 `대신 입력` |
| 첫 컬럼 | 목록의 **첫 컬럼은 상세보기 버튼 고정**(`CMP-01`) |
| 기간 기본값 | 검색 기간은 **정책**에서 옵니다(`CMP-02`) |
| 결과 알림 | **서버가 내려준 `notice`**를 `CMP-05`가 띄웁니다. 화면이 문구를 정하지 않습니다 |

> **공용 단말에서는 "지금 누구인가"가 가장 중요한 정보입니다.**
> 상단 표시와 작업자 기본값이 **자동 로그아웃과 함께** QR 로그인의 위험을 낮춥니다
> ([프로그램-스펙 §7.3–7.4](../프로그램-스펙.md)).

## 5. 화면 간 이동 규칙

조회 화면에서 발견한 것을 **그 자리에서 처리**할 수 있어야 합니다.
목록으로 돌아가 메뉴를 다시 찾게 하면 아무도 쓰지 않습니다.

| 상황 | 처리 |
|---|---|
| **단건** — LOT 하나의 라벨 발행 · 창고이동 · 조정 | **팝업** |
| **다건 · 조건** — 미발행 6건 일괄 발행 | **전용 화면으로 이동**하며 **지금 필터를 그대로 넘김** |
| **이력 · 재발행 · 폐기** | **별도 메뉴에만** — `LBL-03` · `INV-02` |

> **조회 화면은 진입점이지 처리 로직이 아닙니다.**
> 실행은 언제나 전용 화면의 코드가 합니다 — 팝업은 그 화면의 폼을 빌려 씁니다.
> 같은 처리를 두 곳에 구현하면 검증 규칙이 갈라집니다.

이 규칙은 `INV-01` 뿐 아니라 **모든 조회·목록 화면에 같이 적용**됩니다 —
`SAL-01`(→ 작업지시), `SHP-01`(→ 출하등록), `PRD-08`(→ 불량등록).

### 5-1 · 실적을 올리는 스캔은 한 화면에만 둔다

**`PRD-05`가 찍어서 올리고, `PRD-06`은 골라서 고칩니다.**

| 화면 | 하는 일 | 기기 |
|---|---|---|
| `PRD-05` 라우트시트 스캔 | **찍어서 올린다** | 현장 단말 |
| `PRD-06` 공정실적관리 | **골라서 고친다** · 스캔은 **찾는 데만** | 사무실 |

처음에는 `PRD-06`에도 스캐너 입력을 두고 **두 화면의 스캔 규칙을 맞췄습니다.**
그것이 곧 중복이었습니다 — 같은 규칙을 두 곳에 구현하고, 고칠 때 두 곳을 고치고,
현장은 **어디서 찍어야 하는지**를 배워야 했습니다.

> **두 화면이 같은 규칙을 갖는다는 것은 한 화면에 있어야 할 것이 둘로 나뉘어 있다는 뜻입니다.**
> 규칙을 맞추지 않고 **없앴습니다.**

#### 바코드가 하는 일

| 읽은 것 | `PRD-05` 현장 | `PRD-06` 사무실 |
|---|---|---|
| **작업지시 바코드** | 그 지시로 화면이 열립니다 | 그 지시를 고르고 **넘어갑니다** |
| **공정 바코드** | **실적을 올립니다** | **라우트시트 스캔으로 넘어갑니다** |
| **수량 바코드** | 수량창을 채웁니다 | **쓰지 않습니다** |
| **자재 식별표**(LOT) | — | **사용처리** 팝업 |

**`PRD-06`에서 공정 바코드를 읽으면 라우트시트 스캔으로 넘어갑니다.**
고르고 멈추지 않습니다 — 찍었다는 것은 **올리겠다는 뜻**이기 때문입니다.
넘어가는 화면이 **지시 · 공정 · 회당 수량**을 그대로 들고 갑니다.

사무실에서 시트를 모아 입력할 때 **목록을 뒤지지 않게** 하는 것이 스캔의 또 다른 목적입니다 —
수량만 고칠 것이면 넘어가지 않고 그 자리에서 손으로 넣습니다.

**`PRD-06`에 "내 설비"를 걸어 두지 않습니다.** 스캔이 실행을 만들지 않으므로 필요가 없고,
설비는 수량 입력 · 실행 추가에서 그때 고릅니다.

### 5-2 · `INV-01`의 진입점

| 대상 | 액션 | 이동 |
|---|---|---|
| 미발행 LOT | 라벨 발행 | 팝업 → `LBL-02` |
| LOT | 창고이동 (부분 이동 가능) | 팝업 → `INV-04` |
| LOT | 재고조정 (**ADM만**) | 팝업 → `INV-05` |
| 미발행 **2건 이상** | 일괄 발행 | **이동** → `LBL-02` |
| 음수 LOT | 미결 처리 | **이동** → `INV-08` |
| 최소 규격 미만 잔재 | 폐기 | **이동** → `INV-05` |

## 6. 프로토타입으로 먼저 만들 4개

**상호작용 자체가 리스크인 화면**입니다. 말로 합의하면 놓칩니다 —
라우트시트에서 이미 겪었습니다.

| ID | 화면 | 왜 |
|---|---|---|
| `PRD-05` | 라우트시트 스캔 | **완료** |
| `PRD-06` | 공정실적관리 | 설비 동시 진행 + 초중종 병행이 **한 화면에서 맞물립니다** |
| `PRD-01` | 부족 시점 조회 | 표 하나가 **작업지시 발행 방식 전체**를 결정합니다 |
| `INV-01` | LOT 재고현황 | 박스 잔량 · 소재 규격별 개수를 **어떻게 한 줄로 보일지**가 미검증 |

## 7. 개발 순서

선행 관계를 따라 5묶음으로 갈립니다. 묶음 안은 병렬 가능합니다.

| 순 | 묶음 | 화면 | 비고 |
|---|---|---|---|
| **0** | 공통 컴포넌트 | `CMP-01` … `CMP-05` | **여기가 흔들리면 전부 다시** |
| **1** | 로그인 · 권한 · 기준정보 | `SYS-01`~`SYS-12` · `BAS-01`~`BAS-10` | 데이터가 없으면 뒤가 안 돎 |
| **2** | 수주 · 발주 · 입고 · 재고 | `SAL-01`~`02` · `PUR-01`~`03` · `INV-01`~`08` · `QUA-01` | **수불이 여기서 완성** |
| **3** | 생산 · 품질 · 라벨 | `PRD-01`~`08` · `QUA-02`·`04`·`05` · `LBL-01`~`03` | 프로토타입 3개가 여기 |
| **4** | 출하 · 추적 · 진행현황 | `SHP-01`~`03` · `QUA-03` · `TRC-01`~`02` · `SAL-03` | **`SAL-03`은 앞이 다 있어야 그려집니다** |

> MVP 성공 기준 — *"수주 1건이 자재 입고 → 작업지시 → 스캔 실적 → 검사 → 출하까지
> 시스템 안에서 완결되고, 그 결과로 재고와 LOT 이력이 맞는다"* —
> 는 **묶음 4가 끝나야** 성립합니다.

## 0-1. 단계 ( 10-29 — 출하대기부터 )

```
[+ 출하 등록] ─▶ ① 출하대기 ──▶ ② 결재 ──────▶ ③ 출하검사 ───▶ ④ 출하처리 ──▶ 완료
                 ( 지시 · LOT 지정 )  설정 켠 업체만     설정 켠 업체 · 품목만    재고 차감 · 수주 반영
                 고칠 수 있음        승인 전엔 막힘     합격 전엔 막힘
                                   반려 → ① 로       불합격 → 그 줄 고치고 재검사
```

| 단계 | 언제 생기나 | 지나가는 조건 | 이 단계에서 할 수 있는 것 |
|---|---|---|---|
| ① 출하대기 | 늘 | — | 줄 · 수량 · **LOT 지정**( 선점 ) 고치기 · 지시서 출력( 나중 ) · 취소 |
| ② 결재 | 정책 **`shipment.approval`**( 새로 · `feature.approval` 이 켜져야 보임 ) = Y | 승인 | [결재 요청] → 승인 / 반려. 요청 중에는 고칠 수 없음 · 반려면 ① 로 |
| ③ 출하검사 | 정책 **`quality.shipping_inspection`**( 있음 · 업체 기본 + 품목별 ) = Y 인 품목의 줄 | 그 줄들이 모두 합격 | 줄마다 합격 / 불합격 ( 검사자 · 일시 · 비고 ) — 품질관리 6003 출고검사 화면 + 출하 상세 |
| ④ 출하처리 | 늘 | ② · ③ 통과 | [출하처리] — 출하일시 · 원장 `OUT_SHIPMENT` · 수주 줄 출하 + · 수주 자동 완료 |

- 상태 칸 : 머리 `status` = `WAIT`( 대기 ) / `DONE`( 출하 완료 ) / `CANCELED` · `approval_status` = `NONE` / `PENDING` / `APPROVED` / `REJECTED` · 줄 `inspect_status` = `NONE`( 검사 안 함 ) / `WAIT` / `PASS` / `FAIL`
- 화면의 **단계 표시**( 대기 · 결재 대기 · 검사 대기 · 출하 가능 · 완료 · 취소 )는 이 셋에서 계산
- 설정을 중간에 바꾸면 : 이미 대기 중인 건은 **처리할 때의 설정**으로 판단 ( 결재를 켜면 대기 건도 결재를 받아야 처리됨 )

### 결재 — 전자결재 전까지 "간이 승인"

전자결재( 결재선 · 상신 · 내 결재함 )는 Phase 2 ( 전자결재-설계 §9 ). 그 전까지는 :

- [결재 요청] → **승인 권한이 있는 사람**( 출하관리 메뉴 can_delete — 관리자급 )이 [승인] / [반려 · 사유] — 결재선 없이 한 명
- 기록 : 요청자 · 요청 일시 · 처리자 · 처리 일시 · 반려 사유 ( `shipment` 칸 )
- 전자결재가 생기면 [결재 요청] 이 결재 문서( `SHIPMENT_ORDER` )를 만들고 `approval_doc_idx` 로 잇는다 — 출하 쪽 단계 규칙은 그대로

### LOT 지정 · 선점

- LOT 은 **출하대기에서 지정** — 출하검사가 실제 그 LOT 을 보고, 처리는 지정한 그대로 나간다
- **선점** ( RFP "출하대기 → 출고 → 출하완료 시 사용처리( 선점 )" ) : 다른 출하대기가 잡은 수량은 LOT 후보에서 **가용 = 잔고 − 다른 대기분** 으로 보여 준다 ( 원장은 처리 때만 )
- 처리 때 다시 확인 : 지정 LOT 의 잔고가 모자라면 처리 막음 ( 그 사이 이동 · 조정 · 다른 출하 )


| 칸 | 규칙 |
|---|---|
| 고객사 | 고르면 [+ 수주 줄] 이 그 고객사의 **확정 · 남은 출하가 있는** 수주 줄만 보여 줌 |
| [+ 수주 줄] | 수주 줄 고르기( 수주번호 · 품목 · 납품일 · 수량 · 생산 · 출하 · 남은 ) — 납품일 이른 순 |
| [+ 품목] | 수주 없이 출하 ( 샘플 · 재고 판매 ) — 제품 · 상품 품목 |
| 출하 수량 | 기본 = min( 남은 수량 , 재고 ) |
| LOT 채움 | 그 품목의 **제품 재고**( 잔고 > 0 · 입고된 LOT ) 를 **선입선출**로 위에서부터. 줄을 펼쳐 LOT · 창고별로 고칠 수 있음 ( 자재출고 채움과 같은 방식 ) |
| 한도 | LOT 잔고보다 많이 낼 수 없음 ( 차단 ) · 남은 수량보다 많으면 §6-2 |
| [저장] | 출하대기로 저장 ( 원장 없음 · LOT 선점만 ) |
| [출하처리] | ② · ③ 통과 후. 한 트랜잭션 : 지정 LOT 잔고 확인 → 원장 OUT · 수주 줄 출하 + · 줄 / 수주 상태 · `shipped_at` |

### 상세 · 취소

- **대기 취소** : 출하대기 건을 취소 ( 원장 없음 — 선점만 풀림 )
- **출하 취소( 완료 건 )** = 건 전체 역분개 ( 원장 · 수주 줄 출하 − · 줄 / 수주 상태 되돌림 ). 일부 줄만 취소는 하지 않음 ( 거래명세서 한 장 단위 ) — 되돌린 건은 **취소**로 끝 ( 다시 대기로 돌리지 않음 · 새로 등록 )
- 완료 건 수정은 없음 — 취소하고 다시 등록 ( 원장을 고치지 않는 원칙 )

## 2-1. 6003 출고검사 ( `QUA-03` · 출하검사 )

- 목록 : **검사 대기 출하 줄**( 정책상 검사 대상 · 결재가 필요하면 승인된 건만 ) — 출하번호 · 고객사 · 품목 · LOT · 수량 · 예정일
- 줄 → [합격] / [불합격 · 사유] ( 정책 `quality.mode.shipping = SIMPLE` — 검사시트는 나중 ) · 검사자 = 로그인 · 일시
- 불합격 줄 : 출하 창에서 수량 · LOT 을 고치면 다시 검사 대기 / 그 줄을 빼면 검사 없이 진행
- 출하 상세에서도 같은 버튼 ( 검사 권한 = 6003 메뉴 can_write )

## 3. 7002 출하이력관리 ( `SHP-03` )

- 출하 **줄 단위** 목록( 출하일 · 출하번호 · 고객사 · 수주 · 품목 · LOT · 창고 · 수량 · 상태 ) — 기간 · 고객사 · 품목 · LOT 검색 · 엑셀
- "품목 전체가 보이는 이력"( RFP ) — 7001 은 건 단위, 7002 는 줄 단위
- 행 클릭 → 그 출하 건 상세

## 4. 수주 쪽 변화

| | |
|---|---|
| 수주 줄 | `shipped_qty` 표시( 이미 칸 있음 ) · 출하 ≥ 수량이면 `line_status = DONE` · 출하 취소로 다시 `OPEN` |
| 수주 상태 | 취소되지 않은 줄이 모두 `DONE` 이면 **자동 완료( CLOSED )** · 출하 취소로 다시 확정 ( 30-수주 §7 "자동 완료는 출하 모듈 때" ) |
| 수정 제한 | 출하가 있는 줄은 수량을 출하량 아래로 못 줄임 ( 이미 규칙 자리 있음 — `hasDownstream` ) |

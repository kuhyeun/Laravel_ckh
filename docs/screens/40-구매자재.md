## 0. 공통

### 0.1 수주와 다른 점

| | 수주 | 발주 |
|---|---|---|
| 뜻 | 고객사가 우리에게 주문 | **우리가 구매처에 주문** |
| 거래처 | 고객사 구분 | **구매처 구분**( `is_supplier = Y` ) · 사용 중 |
| 품목 | 제품 대분류 | **자재 대분류**( 원자재 · 원소재 ) — §9-3 |
| 단가 기본값 | `std_sale_price` 판매단가 | **`std_buy_price` 발주단가** |
| 줄 날짜 | 납품일 | **입고 예정일**( `due_date` ) |
| 진행 수량 | 생산 · 출하 | **입고 수량**( `received_qty` ) — 입고( PUR-03 )가 채운다 |
| 아래 단계 | 작업지시 · 출하 | **입고** — 입고된 줄은 품목 변경 · 삭제 불가, 수량은 입고량 아래로 못 줄임 |
| 번호 | `SO-YYMMDD-NNN` | **`PO-YYMMDD-NNN`** |
| 줄 자동 완료 | 출하 ≥ 수량 | **입고 ≥ 수량** ( 입고 모듈 때 ) |

### 0.2 테이블

ERD §8 의 `purchase_order` · `purchase_order_line` 을 수주와 같은 방식으로 만듭니다.

```
purchase_order        머리   purchase_order_idx PK · order_no · order_date · partner_idx( 구매처 )
                             order_name · status · total_amount · approval_status · remark · ext_* 7칸
purchase_order_line   줄     purchase_order_line_idx PK · purchase_order_idx FK · line_no · item_idx
                             qty · unit_price · amount · due_date( 입고 예정일 ) · received_qty · line_status · remark
```

- 줄 PK 단일 — 입고 줄이 발주 줄 하나를 가리킵니다
- 커스텀 컬럼 슬롯 **7칸을 머리에 처음부터** ( [커스텀-컬럼-설계](../커스텀-컬럼-설계.md) — 발주 7 )
- 수주의 `customer_po_no`( 고객 발주번호 )에 해당하는 칸은 없습니다 — **이 발주번호가 곧 구매처에 주는 번호**입니다
- 발주서 결재( `approval_status` )는 Phase 2 ( 전자결재 ) — 지금은 `NONE`

# 10. 입고 · 재고 — 설계 ( 확정 · 구현 완료 )

> 사용자 결정 ( 2026-10-12 ) — **① 발주 없이 바로 입고도 허용** · **② 검사를 통과해야 재고에 잡힌다**
> 근거 문서 : [재고-수불-설계](../재고-수불-설계.md) · [ERD §7](../ERD.md) · [정책-설정-설계 §6 B-3](../정책-설정-설계.md)

## 10.1 흐름

```
입고등록 ( PUR-03 )                           입고검사 ( QUA-01 )                 재고
  발주 불러오기 or 직접 입력
  줄마다 LOT 발급 ( 라벨 붙일 번호 )
     │
     ├─ 입고검사 = 무검사 ──────────────────────────────────────────────▶ 입고완료 → 원장 + / 잔고 +
     │
     └─ 입고검사 = 샘플링 · 전수 ──▶ 검사대기 ──▶ [검사완료] 합격 n · 불합격 m ──▶ 합격 n 만 입고완료 → 원장 + / 잔고 +
                                     ( 재고 0 )                  불합격 m → 불량 기록 ( 재고에 안 잡힘 )
```

- **줄마다 따로 갈립니다.** 한 입고에 무검사 볼트와 전수검사 환봉이 같이 오면 볼트는 바로 재고, 환봉은 검사대기
- 입고검사 여부는 줄마다 정책 `quality.incoming_inspection` 을 **품목 · 거래처( 구매처 )로 읽습니다** ( 품목 무검사면 거래처 무시 — 이미 구현된 `EXEMPT_THEN_PRIORITY` )
- 검사 완료 방식 `quality.mode.incoming` 은 Phase 1 **`SIMPLE` 만** — 검사완료 버튼 + 합격 / 불합격 수량 + 첨부( 성적서 · 밀시트 )
- **검사완료는 두 곳에서** ( 사용자 판단 2026-10-12 · C안 ) — **입고관리**( 받은 자리에서 바로 ) · **품질관리 › 입고검사**( 검사대기를 모아서 ). 같은 검사완료 창( 컴포넌트 하나 )을 연다. `SHEET`( Phase 2 )가 되면 입고관리 쪽 버튼만 비활성 — 정책-설정-설계 §6 B-3
- **검사대기 자재는 재고에 없습니다** — 출고 · 이동 어디에서도 안 보입니다 ( 하드 블록, 정책 없음 )
- `quality.incoming_confirm_required`( 검사 후 자재팀 확인 )는 이번에 **하지 않습니다** — 정책은 화면에 안 보이는 상태 그대로

## 10.2 재고 엔진 ( 화면 없음 )

[재고-수불-설계 §2](../재고-수불-설계.md) 의 3층 중 **원장 · 잔고**를 지금 만들고, **스냅샷은 데이터가 쌓인 뒤**( §14 ).

| 테이블 | 키 | 하는 일 |
|---|---|---|
| `lot` | `lot_idx` | LOT. **입고 줄마다 새로** ( 같은 외부 LOT 이 다시 와도 합치지 않음 ). `lot_no` 는 UNIQUE 아님 |
| `lot_seq` | `lot_rule_idx` + `period_key` | LOT 순번 카운터 ( 규칙 × 리셋 구간 — 날짜 단위가 곧 리셋 주기 ) |
| `stock_txn` | `stock_txn_idx` | **수불 전표 머리** — 번호 · 종류( `IN_PURCHASE` … ) · 발생 시각 · 등록 시각 · 상태 |
| `stock_txn_line` | `stock_txn_line_idx` | 전표 줄 — 품목 · LOT · 창고 · 수량 · 검사 상태 · 발주 줄 연결 |
| `stock_ledger` | `stock_ledger_idx` | **원장 — 추가만.** 취소는 역분개( `reversed_by` ) |
| `stock_balance` | 품목 + LOT + 창고 + 로케이션( 0 ) | 현재고. 원장을 쓸 때 같은 트랜잭션에서 `qty = qty + delta` |

- **재고를 바꾸는 길은 `StockService` 하나** — 원장 INSERT + 잔고 UPSERT 를 한 트랜잭션으로. 다른 코드가 잔고를 직접 고치지 않는다
- **화면에서 원장을 GROUP BY 하지 않는다** ( 설계 §2 절대 규칙 ) — 현재고는 잔고에서만
- 시각 둘 : `occurred_at`( 실제로 들어온 때 — 화면이 입력, 기본 지금 ) · `recorded_at`( 서버가 찍음, 불변 )
- 소급 경고 : `occurred_at` 이 `stock.backdate_warn_days`( 30 )보다 오래되면 경고. 차단 일수는 비어 있으면 막지 않음
- 음수 재고 : `stock.allow_negative`( Y ) — 입고만 있는 지금은 생기지 않지만 엔진에 규칙을 넣어 둔다
- 이 정책들을 **읽기 시작하므로 `visible` 을 켭니다** ( 규약 )
- `feature.lot` 이 꺼진 업체는 `lot_idx = 0` 으로 품목 × 창고 잔고 ( 설계 §2-1 — 스키마 그대로 )

## 10.3 LOT 발급

| | |
|---|---|
| 번호 | 정책 `lot.material_source` — **`INTERNAL`( 기본 )** : LOT규칙관리의 **자재( MATERIAL ) 기준 규칙**으로 발급, 공급처 번호는 `external_lot_no` 에 / `EXTERNAL` : 공급처 번호를 그대로 `lot_no` 로 ( 입력 필수 ) |
| 규칙 고르기 | 자재 기준 사용 중 규칙이 **여럿이면 입고 화면에서 고릅니다** ( 기본 = 첫 규칙 ). 하나면 고르는 칸 없음 |
| 규칙이 없으면 | §16-6 |
| 거래처 넣기 | 규칙의 거래처 요소가 `ASK` 면 **입고 화면에서 체크** ( 원문 *거래처 넣기 선택* ). `ALWAYS` 면 항상 |
| 순번 | `lot_seq` 를 잠그고 +1 ( 동시 입고에도 겹치지 않음 ). **번호는 재사용하지 않음** — 취소 · 불합격으로 빈 번호가 생겨도 그대로 |
| 소재 규격 | 원소재( `item_kind = STOCK` )는 줄에 **조각 1개 규격값**( `spec_value` — 1000mm 등 )을 입력. 수량은 언제나 **개수** ( 설계 §2-1 ) |
| 발급 시점 | **입고등록 저장 때** — 검사 전에 라벨을 붙여야 하므로 ( ERD *LOT은 재고가 움직이기 전에 생긴다* ) |

- 검색 기간 기준 : **입고일( `occurred_at` )** · 검색어 : 입고번호 · 발주번호 · 품번 · 품명 · LOT · 공급처 LOT · 거르기 : 구매처 · 상태
- 상태 : 줄이 모두 끝나면 `입고완료`, 검사대기 줄이 있으면 `검사대기 n / 전체`, 모두 취소면 `취소`
- 목록에 **등록 시각도** 보입니다 ( 소급 입력 확인 — 설계 §4 )

### 등록 ( 모달 )

```
┌─ 입고 등록 ──────────────────────────────────────────────────────────────┐
│ 구매처 * [대한철강 ▾]   입고일시 * [2026-10-12 09:30]   LOT 규칙 [자재 기본 ▾] │
│ [발주 불러오기]   [+ 직접 추가]                    □ LOT 번호에 거래처 넣기    │
├──────────────────────────────────────────────────────────────────────────┤
│ # │ 품목         │ 발주            │ 남은 수량 │ 입고 수량 * │ 규격( mm ) │ 창고 *    │ 공급처 LOT │ 검사  │
│ 1 │ RM-BAR-20    │ PO-261008-001-1 │ 1,000     │ [   20 ]    │ [ 1000 ]   │ [자재창고] │ [H-77812]  │ 전수  │
│ 2 │ BOLT-M8      │ ( 직접 )        │ —         │ [ 1000 ]    │            │ [자재창고] │ [       ]  │ 무검사 │
```

|---|---|

| 직접 추가 | 발주 없이 품목을 고름 ( 사용 중 품목 — 자재가 기본, 제품은 경고 ). **결정 ①** |
| 입고 수량 | 0 초과. 발주 남은 수량보다 많으면 §16-3 |
| 창고 | 사용 중 창고 ( 트리 — 하위 창고도 고를 수 있음 ). 기본 = 직전에 고른 창고 |

| 검사완료 | 목록에서 검사대기 줄을 열면 **[검사완료]** — QUA-01 과 **같은 창**( §12 ). 권한은 **입고관리 쓰기** |

|---|---|
| 수정 | **하지 않습니다.** 원장이 추가만이므로 고치려면 취소 후 다시 입고 ( LOT 번호는 새로 ) |

|---|---|

## 16. 결정 ( 2026-10-12 확정 — 모두 제안대로 )

| # | 항목 | 결정 | 버린 대안 |
|---|---|---|---|
| 1 | **입고 전표 구조** | 수불 공통 `stock_txn` + `stock_txn_line` 에 담는다 ( 종류 `IN_PURCHASE` ). 나중 출고 · 이동 · 조정도 같은 표 — ERD §7 그대로 | 입고 전용 `receipt` 표 |
| 2 | **부분 불합격** | 합격분만 재고, 불합격분은 불량 기록( 재고 0 ). 반품 처리는 나중 | 줄 단위 합격 / 불합격만 ( 수량 나누지 않음 ) |
| 3 | **과입고** | 발주 남은 수량보다 많이 입고 → **경고 후 허용** ( 현장에서 흔함 ) | 막음 |
| 4 | **입고 취소** | 입고 수정 없음 — 취소( 역분개 ) 후 다시. 그 LOT 이 이미 출고 · 이동됐으면( 잔고 < 입고 수량 ) **취소를 막음** | 음수 재고 허용 정책을 따라 취소 허용 |
| 5 | **번호 · 메뉴** | `RC-YYMMDD-NNN` · 메뉴 3003 입고관리 · 6001 입고검사 · 3005 재고관리 | |
| 6 | **LOT 규칙이 없을 때** | `INTERNAL` 인데 자재 기준 규칙이 없으면 **저장을 막고** "LOT규칙관리에서 자재 기준 규칙을 등록하세요" | 기본 형식( `품번-YYMMDD-NNN` )으로 자동 발급 |
| 7 | 코드 위치 | 패키지 `MesCore\Stock`( 엔진 · 재고현황 ) · `MesCore\Purchase`( 입고 ) · `MesCore\Quality`( 입고검사 ) — 각각 Material · Quality 모듈 스위치 | |

> 구현하며 정한 것 — 성적서 · 밀시트 첨부는 검사 기록이 아니라 **입고 줄**( `receipt_line` )에 붙인다 ( 검사 전에도 올릴 수 있게 ). 검사 후 재고에 잡히는 원장 시각 = **검사 시각**, LOT 의 선입선출 기준( `in_at` ) = **입고 시각**. 발주 줄이 모두 입고되면 발주가 **자동 완료**, 입고 취소로 남은 수량이 생기면 **다시 확정**

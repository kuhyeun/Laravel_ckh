# 공통 컴포넌트 — 부품 대장

> 작성일: 2026-09-02 · 상태: 살아 있는 문서
> **컴포넌트를 하나 만들 때마다 여기에 한 항목을 추가합니다.**

---

## 1. 이 문서가 하는 일

**부품을 만든 사람과 쓰는 사람이 다릅니다.** 그 사이를 잇는 것이 이 문서입니다.

| 없으면 | |
|---|---|
| 같은 부품을 **두 번 만듭니다** | 목록에 있는지 모르니 새로 짭니다 |
| **props를 코드에서 읽습니다** | 쓸 때마다 `.vue` 파일을 열어 봐야 합니다 |
| 고치면 **어디가 깨지는지 모릅니다** | 쓰는 화면 목록이 없습니다 |

그래서 **코드가 아니라 여기가 계약**입니다. 부품의 겉모습(props · emits · slots)은
여기 적힌 것이 전부이고, 여기 없는 것은 **써도 되는지 보장하지 않습니다.**

---

## 2. 기록 규칙

### 언제

| 시점 | 하는 일 |
|---|---|
| **새 부품을 만들 때** | PR에 **§5 항목 추가가 포함되어야 합니다.** 코드만 있는 PR은 반려 |
| **props · emits · slots를 바꿀 때** | 항목 수정 + **변경 이력 한 줄** |
| 내부 구현만 바꿀 때 | 기록하지 않습니다 — 계약이 그대로면 남길 것이 없습니다 |
| **부품을 버릴 때** | 지우지 말고 **`폐기`로 표시**하고 대체품을 적습니다 |

### 무엇을

**§4 틀을 그대로 채웁니다.** 칸을 비우지 않고, 없으면 `—`를 적습니다.
비워 두면 *"아직 안 정했다"*와 *"없다"*가 구분되지 않습니다.

### 부품이 되는 기준

**아무거나 여기 넣지 않습니다.** 셋 중 둘 이상이어야 부품입니다.

| 기준 | |
|---|---|
| **화면 3개 이상**이 씁니다 | 두 곳이면 복사가 낫습니다 |
| **업무 규칙이 안에 있습니다** | 기간 기본값이 정책에서 오는 것처럼 |
| **바깥 라이브러리를 감쌉니다** | 갈아탈 때 한 곳만 고치려고 |

> 화면 하나만 쓰는 것은 그 화면 폴더에 둡니다 — `components/features/<도메인>/`.
> 부품 대장은 **공용만** 담습니다.

---

## 3. 어디에 있나

```
components/
  mes/                       ← 이 문서가 관리하는 곳
    MesGrid.vue              MesGridColumn.ts
    MesSearchBar.vue         MesDateRange.vue
    MesAttach.vue            MesScanInput.vue
    MesModal.vue             MesFormShell.vue
    MesToast.vue
  features/<도메인>/          ← 화면 전용. 여기 안 적습니다
```

**Nuxt 자동 임포트라 `import` 없이 바로 씁니다.**
이름이 곧 계약이므로 **`Mes` 접두사를 붙이고, 접두사 없는 이름은 화면 전용**입니다.

## 4. 기록 틀

새 부품을 만들면 **이 블록을 복사해** §5 끝에 붙입니다.

```markdown
### CMP-nn 컴포넌트명

파일   components/mes/MesXxx.vue
목적   한 줄. 무엇을 대신해 주는가
등록   2026-09-02 · 상태 사용중 | 폐기

[Props]   | 이름 | 타입 | 필수 | 기본값 | 설명 |
[Emits]   | 이름 | 페이로드 | 언제 |
[Slots]   | 이름 | 슬롯 props | 무엇을 그리나 |
[타입]    쓰는 인터페이스 (있으면 정의 위치)
[쓰는 곳] 화면 ID 목록
[예시]    최소 코드
[안 하는 것] 이 부품이 책임지지 않는 것
[이력]    날짜 · 무엇이 바뀌었나
```

**`[안 하는 것]`을 반드시 채웁니다.** 부품이 커지는 이유는 대부분
*"이것도 여기서 해 주면 편할 텐데"*이고, 경계를 적어 두면 그 요청이 멈춥니다.

**안 하는 것**

| | |
|---|---|

| **검색 조건을 갖지 않습니다** | `CMP-02`가 따로 있습니다 |

> 그래야 그리드를 갈아탈 때 화면 코드가 안 바뀝니다.


**Props** — 없습니다. **전역 하나**를 `app.vue`에 답니다.

**호출** — 컴포저블로 씁니다.

```ts
const { notify } = useNotice()
notify(res.notice)          // 서버 응답의 notice 를 그대로
```

**타입** — `ApiNotice` → [프로그램-스펙 §6.1](../프로그램-스펙.md)

```ts
interface ApiNotice {
  level: 'success' | 'info' | 'warn' | 'error'
  message: string; detail?: string; code?: string; sticky?: boolean
}
```

| `level` | 동작 |
|---|---|
| `success` · `info` | **3초 후 사라집니다** |
| `warn` · `error` | **수동으로 닫습니다** — 놓치면 안 되는 것들입니다 |

**쓰는 곳** — 전 화면(전역)

**안 하는 것**

| | |
|---|---|
| **문구를 만들지 않습니다** | 서버가 내려준 `message`를 그대로 씁니다 |
| 성공/실패를 판단하지 않습니다 | `level`이 이미 적혀 있습니다 |

> **화면이 문구를 정하면 같은 상황에 화면마다 다른 말이 뜹니다.**
> `W_` 경고는 **200에 실려 옵니다** — 4xx로 내리면 화면이 롤백됩니다.

## 7. 부품을 고칠 때

**쓰는 화면이 30개인 부품은 함부로 못 고칩니다.**

| 변경 | 어떻게 |
|---|---|
| **더하기**(새 prop · 새 슬롯) | 기본값을 두고 더합니다. 기존 화면은 안 바뀝니다 |
| **바꾸기**(prop 이름 · 타입) | **바로 바꾸지 않습니다** — 새 것을 더하고, 옛 것에 `@deprecated`를 답니다 |
| **빼기** | 쓰는 화면을 **전부 옮긴 뒤**에 뺍니다. §5의 `쓰는 곳`이 그 목록입니다 |

**어느 쪽이든 `[이력]`에 한 줄을 남깁니다.** 왜 바꿨는지는 여기 말고 남을 곳이 없습니다.

> **부품이 흔들리면 전 화면을 다시 손봅니다.**
> 그래서 `BAS-07 설비관리` 하나로 **먼저 검증하고** 나머지를 시작합니다
> ([프로그램-스펙 §12.1](../프로그램-스펙.md) — 2주차).

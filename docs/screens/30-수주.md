# 수주 — 화면정의

> 작성일: 2026-10-08 · 상태: **확정 · 구현 완료** ( §9 는 제안대로 확정 — 사용자 판단 2026-10-08 )
> `SAL-01` · `SAL-02` 와 이 화면이 처음 쓰는 공통 검색바 `CMP-02`.
> `SAL-03` 수주 진행현황 보드는 작업지시 · 검사 · 출하가 있어야 그려지므로 **업무 묶음 4** 에서 정의합니다.

**모든 화면이 [00-화면목록 §4-1](./00-화면목록.md)의 공통 규칙을 따릅니다.**
기준정보와 같은 것( 목록 + 모달 · 권한 · 확인창 · 엑셀 버튼 위치 )은 [진행상황-인수인계 §2](../진행상황-인수인계.md) 규약 그대로이고,
아래에는 **수주에만 있는 것**을 적습니다.

## 0. 공통

### 0.1 기준정보와 다른 점

| | 기준정보 | 수주 |
|---|---|---|
| 성격 | 마스터 — 전표가 참조 | **전표** — 날짜 · 상태 · 금액이 있다 |
| 목록 크기 | 수백 ~ 수천 건 | **계속 쌓인다** → **서버 페이징**( `RespondsWithList` + `DataGrid :pagination` ) |
| 검색 | 검색어 + 사용 여부 | **기간**( 기본값은 정책 ) + 검색어 + 고객사 + 상태 → `CMP-02` |
| 삭제 | 하지 않음( 미사용으로 내림 ) | **§6** — 아래 단계가 없으면 지우고, 있으면 취소 |
| 구조 | 머리 1 | **머리 1 + 줄 N** ( 한 트랜잭션으로 저장, 줄 IDX 유지 ) |

### 0.2 테이블

ERD §8 의 `sales_order` · `sales_order_line` 을 **이 프로젝트 DB 규약**( `xxx_idx` · `is_use` 대신 상태 · 감사 4종 )으로 만듭니다.

```
sales_order               머리   sales_order_idx PK
sales_order_line          줄     sales_order_line_idx PK · sales_order_idx FK · line_no
```

- 줄 PK 는 ERD 의 `( order_id, seq )` 복합키 대신 **단일 `sales_order_line_idx`** — 작업지시 · 출하가 줄 하나를 가리키기 쉽고, 순서를 바꿔도 참조가 깨지지 않습니다( BOM 줄과 같은 이유 )
- **커스텀 컬럼 슬롯 7칸을 머리에 처음부터** — `ext_c01~03`( varchar 200 ) · `ext_n01~02`( decimal 18,6 ) · `ext_d01~02`( date ) + 슬롯마다 인덱스 ([커스텀-컬럼-설계](../커스텀-컬럼-설계.md) §3). 화면 입력은 Phase 2
- 분할 납품( `delivery_type` · `delivered_qty` · `sales_order_delivery` )은 정기수주와 함께 **Phase 2**. 컬럼 추가만 하면 되므로 지금 넣지 않습니다
- `approval_status` 는 두되 Phase 1 은 항상 `NONE` ( 전자결재 Phase 2 )

### 0.3 위치

```
메뉴      수주관리 > 수주관리 ( menu_code 2001 )
화면      Order/SalesOrderManage.vue        목록 ( SAL-01 )
모달      SalesOrderForm.vue               등록 · 수정 ( SAL-02 )
API       /order/sales/*                   권한 MenuAuth ':Order/SalesOrderManage,…'
```

코드는 **패키지 `MesCore\Order`** ( §9-1 ). 라우트 `routes/order.php` 는 `config('mes.modules')` 에 `Order` 가 있을 때만 등록.

## CMP-02 공통 검색바 — 이 화면에서 처음 만듭니다

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [수주일 ▾] [2026-09-28] ~ [2026-10-18]  [오늘][이번 주][이번 달]           │
│ [수주번호 · 수주명 · 품번 · 품명      ] [고객사 ▾] [상태 ▾]  [조회] [초기화] │
└──────────────────────────────────────────────────────────────────────────┘
```

| 항목 | 내용 |
|---|---|
| 기간 기본값 | **정책** `ui.search_range_from_days`( -10 ) ~ `ui.search_range_to_days`( +10 ) — 오늘 기준. 이 정책을 읽기 시작하므로 `visible` 을 `true` 로 |
| 기간 기준 | 화면이 고를 수 있게 줍니다. 수주 : `수주일` / `납품일`( 줄의 납품일이 기간 안에 하나라도 있으면 ) |
| 빠른 선택 | 오늘 · 이번 주 · 이번 달 |
| 초기화 | 정책 기본값으로 되돌림 |
| 하는 일 | 조건을 모아 `search` 를 쏘기만 합니다. **조회는 화면이** 합니다 |
| 슬롯 | 화면별 칸( 고객사 · 상태 … )은 슬롯으로 끼웁니다 |

> 기존 기준정보 화면의 검색바는 **바꾸지 않습니다** ( 기간이 없어 얻을 것이 없음 ). 업무 화면부터 씁니다.

## 5. 상태

```
미확정( DRAFT ) ──확정──▶ 확정( CONFIRMED ) ──모든 줄 출하 완료 or [마감]──▶ 완료( CLOSED )
      │                        │
      └────────[취소]──────────┴──▶ 취소( CANCELED )
```

| 상태 | 뜻 | 쓰이는 곳 |
|---|---|---|
| 미확정 | 견적 · 예상 수주 | **소요 계산 · 부족 시점에 넣지 않습니다** ( ERD §9 *"미확정 수주는 넣지 않는다"* ) |
| 확정 | 받은 수주 | 작업지시 · 자재 소요 · 출하의 대상 |
| 완료 | 다 나갔거나 사용자가 닫음 | 진행 목록에서 빠짐. 되돌리기 가능 |
| 취소 | 안 하기로 함 | 기록은 남음. 되돌리기 가능 |

- 등록 화면에서 **미확정 / 확정만** 고릅니다. 완료 · 취소는 목록의 동작( 마감 · 삭제 )으로
- Phase 1 에는 출하가 없으므로 **자동 완료는 출하 모듈 때** 붙입니다

## 6. 수정 · 삭제 규칙

**아래 단계( 작업지시 · 출하 )가 붙었는지**가 기준입니다.

| | 아래 단계 없음 | 아래 단계 있음 |
|---|---|---|
| 머리 수정 | 자유 | 고객사 변경 불가 · 나머지 자유 |
| 줄 수정 | 자유 | 품목 변경 불가 · **수량을 생산 · 출하량 아래로 못 줄임** |
| 줄 삭제 | 가능 | 불가 ( 그 줄은 수량을 줄이거나 줄 상태를 취소로 ) |
| [삭제] | **지웁니다**( 머리 · 줄 · 첨부 ) | **취소 상태로** 바꿉니다 ( 기록 유지 ) |

- Phase 1 에는 작업지시 · 출하가 없어 **항상 왼쪽 열**입니다. 규칙은 지금 코드에 자리만 두고( "아래 단계 있음" 판정 함수 ) 작업지시 · 출하 모듈이 채웁니다
- 전표는 기준정보와 달리 **아직 아무도 참조하지 않으면 지워도** 깨지는 것이 없습니다 — 잘못 넣은 수주가 목록에 계속 남는 것을 막습니다 ( §9-4 )

## 10. SAL-03 수주진행관리 ( 2026-10-30 · 메뉴 `2002` · `/order/progress` · 조회만 )

수주 줄마다 **지시 → 자재 → 생산 → 출고검사 → 출하** 가 어디까지 왔는지 한 줄로 본다. 처리는 각 메뉴에서.

### 목록

- 한 행 = 수주, ▸ 로 줄 펼침 ( 줄이 하나면 한 행 — 스타일 가이드 §5 트리 ). 서버 페이징 · 정렬( 수주번호 · 수주일 · 고객사 · 납기 )
- 거르기 : 기간( 수주일 / 납품일 ) · 검색어 · 고객사 · 상태( **진행 중** 기본 / 완료 / 전체 — 취소 수주 · 취소 줄은 안 나옴 ) · **납기 지연만**

| 칸 | 값 |
|---|---|
| 수주번호 · 수주일 · 고객사 · 수주명 · 품목 · 규격 · 재질 · 수량 · 납기 | 수주 ( 납기 지연 = 진행 중 줄의 납품일 < 오늘 → 빨강 ) |
| 작업지시 | 이 줄을 담은 작업지시( 취소 제외 ) `WO-… 외 n건` · 없으면 미지시 |
| 원자재 입고 | **이 줄 작업지시에 출고된 자재 LOT 의 입고일**( 가장 늦은 것 ) — 수주 → 발주 연결( 다음 작업 ) 뒤 "연결된 발주의 입고"로 바꾼다 |
| 원자재 출고 | 가장 늦은 출고일 · 다 나가지 않았으면 `n/m`( 자재 줄 기준 ) |
| 공정 | **한 칸 요약** — 지금 공정( 진행 중 첫 공정, 없으면 남은 첫 공정 ) + 상태 · 완료 `n/m` ( 지시가 여럿이면 합친 값 ) — 공정별 날짜는 상세 모달 |
| 생산 · 출고검사 · 출하 · 출하일 | 생산 수량 / 수량 · 출하 줄 검사( 불합격 > 대기 > 합격 ) · 출하 수량( 대기 수량 앞에 ) · 마지막 출하일 |
| 진행 | 단계( 아래 ) + 지연 / 머리 = 가장 늦은 줄의 단계 + 완료 줄 `n/m` |

**단계** ( `SalesProgressService::STAGES` · 화면 `orderCodes.js PROGRESS_STAGES` ) — 앞에서부터 처음 맞는 것

| 단계 | 조건 |
|---|---|
| 취소 · 완료 | 줄 상태 취소 · 출하 완료 |
| 출하 대기 | 출하대기( 안 나간 출하 )에 담긴 수량이 있음 |
| 일부 출하 | 나간 수량이 있음 |
| 생산 완료 | 작업지시가 모두 완료 또는 생산 수량 ≥ 수량 |
| 생산 중 | 시작했거나 끝난 공정이 있음 |
| 자재 출고 | 자재 출고가 있음 |
| 지시 | 작업지시가 있음 |
| 미지시 | 그 밖 |

### 공정 상세 모달 ( 줄 클릭 · xl )

- 위 : 줄 요약 + 단계 흐름 칸 5개 ( 지시 · 자재 출고 · 생산 · 출고검사 · 출하 )
- 작업지시마다 : 지시 수량( 이 수주 몫 ) · LOT · 착수 / 기한 + **공정 표**( 순서 · 공정 · 상태 · 시작 · 완료 · 수량 · 미달 사유 · 검사 — 검사 공정은 마지막 판정 · 초중종 단계 ) + 자재 표( 소요 · 출고 · 반납 · 출고일시 )
- 아래 : 출하 내역 ( 번호 · 상태 · 예정일 · 출하일시 · 수량 · 출고검사 )
- 작업지시 하나가 여러 수주 줄을 담으면( 병합 ) 그 지시는 줄마다 보인다

### 서버

- `Order/Controllers/SalesProgressController` ( `order.progress.list · formData · detail` · 권한 `Order/SalesProgress` 조회 )
- `Order/Services/SalesProgressService` — 목록은 **한 페이지의 줄을 한꺼번에** 읽는다( 지시 · 공정 · 자재 · 출고 · 출하 쿼리 5개 ). `RespondsWithList::listResponse()` 에 `$prepare`( 페이지 묶음을 먼저 받는 함수 ) 인자를 더했다

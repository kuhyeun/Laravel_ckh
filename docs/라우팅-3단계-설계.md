# 공정 라우팅 3단계 설계 ( 기본 · 품목 · 수주 )

> 상태 : **완료 ( 11-03 ) — 1단계 기반 + 품목 · 2단계 수주 · 3단계 작업지시 · 4단계 비교 ( 브라우저 확인은 아직 )**
> 관련 : ERD §6 ( routing · routing_line ) · 화면 BAS-05 공정라우팅 · 품목관리 · 수주관리 · 작업지시 · 수주 진행현황

## 1. 목적

같은 품목이라도 품목마다, 수주마다 공정이 조금씩 다르다. 지금은 품목이 공용 라우팅 하나를 가리키고 작업지시에서만 공정을 고칠 수 있어서

- 품목별 공정 차이를 기준정보로 남길 수 없고
- 수주 때 고객 요구로 바뀐 공정이 기록되지 않으며
- 수주 공정과 실제 작업지시 공정을 비교할 수 없다.

→ 라우팅을 **세 단계**로 나눈다.

| 단계 | 이름 | 만드는 곳 | 고치는 곳 | 라우팅 관리 목록 |
|---|---|---|---|---|
| ① | **기본 라우팅** ( 공용 틀 ) | 공정 라우팅 관리 | 공정 라우팅 관리 | 보임 |
| ② | **품목 라우팅** ( 품목 전용 ) | 품목 저장 시 ①을 복사 | 품목 등록 · 수정 화면 | 숨김 |
| ③ | **수주 라우팅** ( 수주 줄 전용 ) | 수주 저장 시 ②를 복사 | 수주 화면 줄의 [공정] | 숨김 |

생산에서 쓰는 공정 = 수주에서 온 지시는 **③**, 재고 · 수동 지시는 **②**.
작업지시는 지금처럼 공정을 복사해 두고 그 자리에서 더 고칠 수 있다 ( 현장 최종 조정 ).

## 2. 결정 사항 ( 11-03 사용자 확정 )

| # | 항목 | 결정 |
|---|---|---|
| 1 | 품목 라우팅 | 공정을 고치지 않아도 **항상 전용 라우팅**을 만든다 |
| 2 | 품목 · 수주 화면에서 고칠 수 있는 것 | **전부** — 공정 추가 · 삭제 · 순서 · 표준시간 · 초 / 중 / 종물 검사 · 선행 승인 ( 라우팅 관리와 같은 편집기 ) |
| 3 | 기존 품목 | 이관 마이그레이션으로 **전부 전용 라우팅으로 복사** |
| 4 | 엑셀 일괄 등록 | 라우팅 코드를 적으면 그 틀을 **전용 라우팅으로 복사** |
| 5 | 품목 삭제 | 품목 미사용 처리 시 전용 라우팅도 **함께 미사용** ( 품목 삭제가 원래 미사용 처리 — 실제 삭제 없음 ) |
| 6 | 수주에서 바꾼 공정 | **그 수주에만** 적용 ( 품목 라우팅은 안 바뀜 ) · **변경 이력** 남김 |
| 7 | 수주 공정 잠금 | 그 수주 줄로 **작업지시가 생성되면** 잠김 ( 줄 단위 ) |
| 8 | 작업지시 공정 수정 | 지금처럼 허용 · **변경 이력** 남김 → 수주 공정과 비교 |
| — | 수주 라우팅 생성 시점 | 수주 줄마다 **항상** 만든다 ( 고치지 않았으면 "수정 없음" 표시 ) — 비교 기준이 고정되도록 |
| — | 비교 화면 | **수주 진행현황**에 둔다 |
| — | 수주에서 품목 신규 등록 | 품목관리의 등록 모달을 그대로 띄워 저장 → 그 줄에 바로 선택 |

## 3. 데이터 구조

### 3.1 routing ( 칸 추가 )

| 칸 | 타입 | 설명 |
|---|---|---|
| `owner_type` | enum `TEMPLATE` · `ITEM` · `ORDER_LINE` ( 기본 TEMPLATE ) | 단계 |
| `item_idx` | FK item, nullable, **unique** | ② 의 품목 |
| `sales_order_line_idx` | FK sales_order_line, nullable, **unique**, cascade | ③ 의 수주 줄 ( 줄을 지우면 같이 — 지시가 없을 때만 지울 수 있음 ) |
| `base_routing_idx` | FK routing, nullable | 복사해 온 원본 ( ② → ① · ③ → ② ) |

- `routing_code` : ② · ③ 은 자동 ( `IT-{item_idx}` · `SO-{sales_order_line_idx}` ) — 화면에 안 보인다
- `is_default` 는 ① 에서만 의미가 있다
- **모델 스코프** `Routing::templates()` = `owner_type = TEMPLATE`. 공용 틀만 보여야 하는 곳은 전부 이것을 쓴다 ( §6 )

### 3.2 routing_line ( 칸 추가 )

| 칸 | 타입 | 설명 |
|---|---|---|
| `source_routing_line_idx` | nullable ( FK 없음 — 원본이 지워져도 남는다 ) | 복사해 온 원본 줄. 화면에서 새로 더한 공정이면 NULL |

- ③ 줄의 `source_routing_line_idx` = ② 줄 → **BOM 투입 지점**( ② 줄을 가리킴 )을 ③ · 작업지시까지 이어 준다

### 3.3 item

- `item.routing_idx` 는 이제 **② 를 가리킨다** ( 칸은 그대로 )
- 품목 화면에서 고르는 "틀"은 ② 의 `base_routing_idx` 로 남는다

### 3.4 work_order · work_order_op

- `work_order.routing_idx` = 복사해 온 라우팅 ( 수주 지시 = ③ · 재고 / 수동 = ② )
- `work_order_op.routing_line_idx` = 복사해 온 줄 ( ③ 줄 또는 ② 줄 )
- 공정 → BOM 투입 지점 연결 : `source_routing_line_idx ?? routing_line_idx` 로 ② 줄을 찾아 맞춘다 ( `WorkOrderService::syncOps` 의 map 키만 바뀜 )

### 3.5 routing_change_log ( 새 테이블 — 변경 이력 )

| 칸 | 설명 |
|---|---|
| `log_idx` | PK |
| `scope` | `ITEM` · `ORDER_LINE` · `WORK_ORDER` |
| `ref_idx` | item_idx · sales_order_line_idx · work_order_idx |
| `routing_idx` | 대상 라우팅 ( 작업지시면 NULL ) |
| `action` | `CREATE` ( 복사로 생김 ) · `ADD` · `REMOVE` · `MOVE` · `UPDATE` · `RELOAD` ( 원본에서 다시 불러옴 ) |
| `process_idx` | 대상 공정 |
| `seq_before` · `seq_after` | 순서 |
| `before_json` · `after_json` | 바뀐 값 ( 표준시간 · 검사 · 선행 승인 · 설비 · 작업자 등 ) |
| `create_account_idx` · `create_datetime` | 누가 · 언제 |

- 저장할 때 서버가 **이전 줄 ↔ 새 줄**을 비교해 남긴다 ( 화면이 보내는 값을 믿지 않음 )
- ① ( 공용 틀 ) 변경은 남기지 않는다 ( 필요하면 나중에 scope `TEMPLATE` 추가 )

## 4. 흐름

### 4.1 품목 ( ② )

- 등록 : 틀 선택( 기본 = `is_default` ) → 틀의 공정이 편집기에 채워짐 → 고침 → 저장 시 ② 생성 + `item.routing_idx` = ② + 이력 `CREATE` ( 고친 것은 ADD · REMOVE … )
- 수정 : 편집기에 ② 공정 → 고침 → 저장 시 ② 갱신 ( 줄 IDX 유지 → BOM 투입 지점 유지 ) + 이력
- **틀을 바꾸면** : 편집기를 새 틀 공정으로 교체 ( 이력 `RELOAD` ). 저장 때 사라지는 줄을 BOM 이 가리키면 경고 ( 지금 라우팅 관리의 경고 로직 재사용 — 투입 지점은 NULL 로 )
- 제품( PRODUCT )이 아니면 라우팅 없음 ( 지금 규칙 그대로 ) · 제품 → 자재로 바꾸면 ② 미사용
- 미사용 처리 → ② 도 미사용 / 다시 사용 → ② 도 사용
- 엑셀 등록 : 라우팅 코드 · 이름을 **틀**에서 찾고 ( 비우면 기본 틀 ) ② 로 복사
- ( 참고 ) 품목 복사 기능은 지금 없다 — 생기면 ② 도 복사

### 4.2 수주 ( ③ )

- 줄에 품목을 고르면 ② 공정으로 ③ 초안 → 줄의 **[공정]** 버튼( 공정 수 · "수정됨" 표시 )으로 편집기 모달
- 저장 시 줄마다 ③ 생성 / 갱신 + 이력 ( 처음 = `CREATE`, ② 와 다르면 ADD · REMOVE … 함께 )
- **잠금** : 그 줄로 만든 작업지시( 취소 제외 )가 있으면 ③ 수정 불가 ( 서버가 막음 · 화면은 읽기 전용 )
  - 지시를 모두 취소하면 다시 수정 가능
- 줄의 품목을 바꾸면 ( 잠기기 전 ) 새 품목 ② 로 ③ 을 다시 만든다 ( 이력 `RELOAD` )
- [② 에서 다시 불러오기] : 잠기기 전, 그 사이 바뀐 품목 라우팅을 다시 가져올 때
- 품목 ② 가 없으면 ( 라우팅 없는 품목 ) ③ 은 빈 공정 → 작업지시에서 넣는다
- **[+ 새 품목]** : 품목 선택 옆 버튼 → 품목관리 등록 모달( ② 편집기 포함 ) → 저장되면 품목 목록에 더하고 그 줄에 선택 · 품목관리 쓰기 권한이 있을 때만 보임

### 4.3 작업지시

- 수주 줄을 담으면 공정 = 그 줄의 ③ ( 지금은 품목 라우팅 )
- **여러 수주 줄을 한 지시에 담기** : 공정 순서( 공정 목록 )가 같은 줄끼리만 — 다르면 "공정이 다른 수주 줄은 따로 지시하세요" 로 막음
  - 화면 : 고르기 목록 · 병합 대상은 공정 순서가 같은 줄만 ( 재고 · 수동 지시 줄에는 병합하지 않고 새 줄 ) · 처음 담는 수주 줄이면 공정을 그 줄의 ③ 으로 다시 채움 ( 확인 )
- 지시 공정 수정은 지금처럼 · 저장 때 이전 ↔ 새 공정을 비교해 이력 ( scope `WORK_ORDER` )
- 공정 행 삭제는 지금처럼 실제 삭제 ( 이력이 남으므로 )

### 4.4 수주 진행현황 — 비교

- 수주 줄 상세에 **[공정 비교]** : 왼쪽 ③ 공정 / 오른쪽 그 줄로 만든 작업지시 공정 ( 지시가 여럿이면 지시별 )
  - 같은 공정 · 더해진 공정( 초록 ) · 빠진 공정( 빨강 ) · 값이 다른 공정( 노랑 ) — 공정 순서 기준 비교
- 아래에 이력 목록 : ③ 이력 + 작업지시 이력 ( 시간순 · 누가 · 무엇을 )
- ③ 이 ② 와 다른 점도 함께 ( "수주에서 바꾼 공정" )

## 5. 기존 데이터 이관 ( 마이그레이션 )

1. 칸 추가 · `routing_change_log` 생성 · 기존 routing 전부 `owner_type = TEMPLATE`
2. **제품 품목마다** ( `routing_idx` 있음 ) : 가리키던 틀을 ② 로 복사 · 줄 대응표( 틀 줄 → ② 줄 )
   - 그 품목 BOM 의 `bom_line.routing_line_idx` → ② 줄로
   - 그 품목 작업지시의 `work_order_op.routing_line_idx` → ② 줄로 · `work_order.routing_idx` → ② ( **안 하면 진행 중인 지시를 다시 저장할 때 자재 투입 지점이 끊긴다** )
   - `item.routing_idx` → ② · 이력 `CREATE`
3. **수주 줄마다** : 품목 ② 를 ③ 으로 복사 · 이력 `CREATE`
   - 그 줄 하나만 담은 작업지시는 공정 · 라우팅 참조를 ③ 으로 ( 여러 줄을 담은 지시는 ② 그대로 )
4. 되돌리기( down ) : ② · ③ 참조를 원래 틀 줄로 되돌리고 ② · ③ 삭제 → 칸 · 테이블 삭제

## 6. 영향 범위

| 곳 | 바뀌는 것 |
|---|---|
| `RoutingController` list · show · save · deleteMany | 틀만 ( ② · ③ IDX 는 404 ) |
| `ItemController` formData · save · deleteMany | 틀 목록 · ② 생성 / 갱신 · 미사용 연계 |
| `ItemRules` | `routing_idx` → 틀 IDX( `base_routing_idx` ) + 공정 줄 검증 |
| `ItemImport` | 틀에서 찾고 ② 로 복사 |
| `Item` 모델 | 공정 합계( 표준시간 )는 ② 기준 — 그대로 동작 |
| `BomController` | 투입 지점 = ② 줄 — 그대로 동작 |
| `SalesOrderService` · `SalesOrderController` | ③ 생성 / 갱신 · 잠금 · 이력 · 새 품목 권한 |
| `WorkOrderController` | 수주 줄 → ③ 공정 · 라우팅 선택지는 틀만 · 담기 규칙 |
| `WorkOrderService` | syncOps 투입 지점 키 · 공정 이력 |
| `SalesProgressController` | 공정 비교 · 이력 API |
| 새 `RoutingCopyService` | 복사 · 갱신 · 이력 비교를 한곳에 ( ② · ③ · 이관이 같이 씀 ) |
| 화면 | 새 공통 `RoutingLinesEditor` ( 라우팅 관리 편집부를 뺌 ) · `ItemForm` · `SalesOrderForm` ( [공정] · [+ 새 품목] ) · `SalesProgressDetail` ( 비교 ) · `RoutingManage` ( 편집기 교체 ) |
| 문서 | ERD §6 · 화면목록 · 메뉴별 기능정리 · 작업내역 · 진행상황 |

## 8. 정한 것 ( 추가 )

- 작업지시 이력 범위 : **공정 구성( 추가 · 삭제 · 순서 ) + 표준시간 · 검사**만 — 설비 · 작업자 · 기한 변경은 남기지 않는다 ( 현장이 자주 바꿔 이력이 지저분해짐 )

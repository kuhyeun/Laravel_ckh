# ADR 0026. 실적을 올리는 스캔은 한 화면에만 둔다

- 상태: 채택
- 날짜: 2026-09-08
- 관련: `docs/screens/00-화면목록.md` §5-1

## 배경

원문 요구는 *"라우트시트로 바코드 리딩하면서 진행 또는 수동으로 진행, 두 가지 선택지"* 였다.
이것을 **한 화면 안의 두 입력 모드**로 읽고 `PRD-06 공정실적관리`에 스캐너 입력을 넣었다.

그 결과 `PRD-05 라우트시트 스캔`과 **같은 일을 하는 곳이 둘**이 되었다.
두 화면의 스캔 규칙을 애써 일치시켰는데, **그 일치 작업 자체가 중복의 증거**였다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 두 화면의 규칙을 계속 맞춘다 | 고칠 때 **두 곳을 고친다.** 어긋나면 현장이 화면마다 다르게 배운다 |
| `PRD-05`를 없애고 `PRD-06`에 합친다 | **기기가 다르다.** 현장 단말은 전체 화면 · 큰 타깃, 사무실은 3단 목록. 하나로 만들면 **양쪽 다 나빠진다** |
| `PRD-06`의 스캔을 없앤다 | 사무실에서 시트를 모아 입력할 때 **목록을 뒤져야 한다** |
| **`PRD-06`의 스캔을 찾기 전용으로** | 채택 |

## 결정

**역할을 가른다.**

| 화면 | 하는 일 | 기기 |
|---|---|---|
| `PRD-05` 라우트시트 스캔 | **찍어서 올린다** | 현장 단말 |
| `PRD-06` 공정실적관리 | **골라서 고친다** · 스캔은 **찾는 데만** | 사무실 |

`PRD-06`에서 바코드를 읽으면 **그 자리에서 수량이 올라가지 않는다.**
대신 **라우트시트 스캔으로 넘어간다** — 지시 · 공정 · 회당 수량을 들고 간다.
찍었다는 것은 올리겠다는 뜻이므로 **고르고 멈추지 않는다.**

따라서 `PRD-06`에서 뺀 것:

- 입력 모드 토글(스캔 / 수동) — **수동뿐이다**
- 수량 바코드 처리 — 올리는 화면의 것이다
- **내 설비** 선택 — 스캔이 실행을 만들지 않으므로 필요 없다.
  설비는 수량 입력 · 실행 추가에서 그때 고른다

**자재 식별표 스캔은 남긴다.** 자재 사용처리는 `PRD-06`의 일이고 `PRD-05`에 없다 — 중복이 아니다.

## 결과

- 스캔 규칙이 **한 곳에만** 있다. 고칠 곳이 하나다
- 현장은 **찍는 곳이 하나**다. 어디서 찍는지 배울 것이 없다
- `PRD-06`의 목적이 선명해진다 — **소급 · 보정**
- 사무실에서 스캔으로 올리던 길이 막힌다. 스캐너가 있는 사무실이라면
  **라우트시트 스캔을 열어서** 올린다 — 버튼 하나가 더 든다
- 원문의 *"두 가지 선택지"*는 **한 화면의 두 모드가 아니라 두 화면**으로 만족시킨다

> **두 화면이 같은 규칙을 갖는다는 것은 한 화면에 있어야 할 것이 둘로 나뉘어 있다는 뜻이다.**
> 규칙을 맞추는 것이 아니라 **역할을 가르는 것**이 답이었다.

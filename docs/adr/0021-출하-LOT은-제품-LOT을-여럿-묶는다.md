# ADR 0021. 출하 LOT은 제품 LOT을 여럿 묶고, 번호에 원 LOT을 넣으면 쪼갠다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/ERD.md` §7

## 배경

한 번 나가는 100개가 제품 LOT 두 개에서 나올 수 있다.
어제 만든 60개가 모자라 오늘 만든 40개를 채워 보내는 일은 흔하다.
처음에는 `lot.parent_lot_id`로 1:1이라 잡았으나 **단일 FK로는 부모를 하나만 담는다.**

## 검토한 대안

| 대안 | 문제 |
|---|---|
| `parent_lot_id` 유지 | 섞인 출하를 표현 못 한다 |
| 출하 LOT을 항상 쪼갠다 | LOT을 안 넣는 업체까지 라벨이 늘어난다 |
| **연결 테이블** | 채택 |

## 결정

```sql
shipment_lot_source (tenant_id, shipment_lot_id, source_lot_id, qty)
```

수량 합은 **출하 LOT 수량과 같아야** 한다.
`lot.parent_lot_id`는 그대로 두고 **잔재처럼 부모가 하나뿐인 관계**에 쓴다.

**번호 조합에 `LOT_NO`가 들어가면 출하 LOT을 제품 LOT마다 하나씩 발행한다.**
묶어 놓고는 어느 LOT을 번호에 넣을지 정할 수 없기 때문이다.
대표 LOT 하나만 적으면 **라벨에 없는 LOT이 상자 안에 들어간다.**

## 결과

- 구조는 하나다. `shipment_lot_source`가 **1행이냐 N행이냐**만 달라진다
- **역추적이 갈라진다.** `TRC-01`이 한 줄이 아니라 트리로 보여 줘야 한다 —
  자재 문제가 났을 때 어느 제품 LOT까지 영향인지가 여기서 갈린다
- 출하 **건**은 하나다. 거래명세서는 한 장이고 라벨만 여러 장 나온다

# ADR 0025. 종물 전 선행 진행을 승인으로 연다

- 상태: 채택
- 날짜: 2026-09-08
- 관련: `docs/ERD.md` §9, `docs/screens/20-기준정보.md` BAS-05

## 배경

검사 공정은 **켜진 것 중 마지막**이 끝나야 닫히고(ADR 0011),
보통 그것이 **종물**이다. 종물은 마지막 생산품을 보므로 **생산이 다 끝나야** 검사할 수 있다.

그동안 뒷공정은 논다. 도금 · 열처리처럼 **묶어서 돌리는 공정**이 뒤에 있으면
한 배치를 놓쳐 하루가 밀린다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 그대로 둔다 | **현장이 시스템 밖에서 진행하고 나중에 몰아 입력한다.** 이력이 거짓이 된다 |
| 종물을 검사 완료 기준에서 뺀다 | 종물 검사 자체가 형식이 된다. **완료 판정이 무의미해진다** |
| 무조건 진행 허용 + 경고만 | 누가 판단했는지 남지 않는다. **사고 나면 책임 소재가 없다** |
| **승인을 조건으로 연다** | 채택 |

## 결정

**종물이 안 끝났어도 다음 공정으로 나갈 수 있다.** 조건은 승인이고, 두 갈래다.

```sql
-- routing_line
--   pre_approve_min          SMALLINT NOT NULL DEFAULT 0   -- 0이면 선행 진행 불가
--   pre_approved_by_design   BOOLEAN  NOT NULL DEFAULT FALSE
--   pre_approved_by          BIGINT   NULL
--   pre_approved_at          DATETIME(6) NULL
```

| | 언제 승인하나 | 누가 |
|---|---|---|
| **건별 승인** | 그 작업지시마다 | `pre_approve_min` 명 이상 |
| **설계 승인** | 라우팅을 만들 때 한 번 | 체크한 사람이 승인자 |

건별 승인은 여러 명이므로 `wo_op_pre_approval`에 쌓는다.
기본키가 `(work_order_id, op_seq, approver_id)`라 **한 사람이 두 번 눌러도 한 번**이다.

**승인 수는 라우팅 줄에 둔다.** 정책 카탈로그를 늘리지 않았다(ADR 0013) —
공정마다 위험도가 다르므로 **줄 단위가 더 정확하다.**

**설계 승인도 승인자를 남긴다.** 체크만 남으면 *"누가 이걸 열어 놨나"*에 답할 수 없다.
BOM 승인과 같은 원칙이다(ADR 0024).

**초물과 중물은 건너뛰지 못한다.** 켜진 것 중 **종물만** 건너뛴다.
초물도 안 본 물건을 넘기는 것은 선행 진행이 아니라 검사를 안 하는 것이다.

**검사 공정은 여전히 종물로 닫힌다.** 선행 진행은 **다음 공정의 잠금만** 푼다.

## 결과

- 뒷공정이 종물을 기다리지 않는다. **배치 공정의 대기가 사라진다**
- 현장이 시스템을 우회할 이유가 줄어든다
- **종물이 떨어지면 뒷공정이 이미 돌아 있다.** 이것이 이 결정의 대가다.
  되돌릴 수 없으므로 **막지 않고 알린다** — 선행 진행한 공정에 알림을 쏘고
  그 작업지시를 `TRC-01` 추적 대상으로 올린다
- **설계 승인은 검사 없이 나가는 길을 상시로 여는 것**이다. 켤 때 경고하고,
  켠 사람이 기록에 남는다
- 진행 조건 판정이 복잡해진다. `앞 공정 완료` 하나였던 것이
  **완료 · 설계 승인 · 승인 수** 세 갈래가 된다

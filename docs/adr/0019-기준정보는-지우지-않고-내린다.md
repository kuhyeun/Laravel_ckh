# ADR 0019. 기준정보는 지우지 않고 내리며, 열린 목록은 코드 마스터로 뺀다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/screens/20-기준정보.md`

## 배경

기준정보는 전표가 참조한다. 지우면 과거 전표가 깨진다.
그리고 담당자 구분·단위처럼 **업체마다 값이 다른 목록**을 ENUM으로 잡으면 반드시 모자란다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 물리 삭제 | 과거 전표가 깨진다 |
| 참조 있으면 삭제 금지 | 쓰지도 않는 항목이 목록에 계속 남는다 |
| **`is_active`로 내린다** | 채택 |
| 구분값을 ENUM으로 | 업체마다 다른 항목을 못 담는다 |
| **공통코드 `code_item`** | 채택 |

## 결정

- 기준정보에 **삭제 버튼을 두지 않는다.** `is_active = false`로 내린다.
  내린 것은 새 전표에서 선택되지 않고, 과거 전표에는 그대로 보인다
- 열린 목록은 `code` / `code_item`의 그룹으로 뺀다 — **새 테이블을 만들지 않는다**

| 그룹 | 쓰는 곳 |
|---|---|
| `UNIT` | `item.spec_unit` · 검사 항목 단위 |
| `PARTNER_CONTACT_TYPE` | 거래처 담당자 구분 |
| 첨부 구분 | `attachment.category_cd` |

**담당자의 구분과 소속은 다른 축이다** — `contact_type`(역할)과
`site_id`(출고지)를 따로 둔다. *"1공장의 영업담당"*이 한 축으로는 표현되지 않는다.

## 결과

- 단위가 `EA` · `ea` · `개`로 갈리지 않는다. 재고 집계가 한 줄로 모인다
- 계산식이 `SPEC`이 mm인지 m인지 **알 수 있다**
- 코드 추가는 `SYS-06`에서만 한다. **품목 화면에서 만들지 않는다** — 오타가 마스터가 된다
- 단위별 소수 자릿수가 필요해지면 `code_item`을 오염시키지 말고 **전용 테이블로 승격**한다

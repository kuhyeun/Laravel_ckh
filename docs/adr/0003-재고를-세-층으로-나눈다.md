# ADR 0003. 재고를 원장·잔고·스냅샷 세 층으로 나눈다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/재고-수불-설계.md`

## 배경

재고는 두 가지를 동시에 요구한다. **지금 얼마 있나**는 즉시 나와야 하고,
**언제 어떻게 그렇게 됐나**는 지워지면 안 된다. 한 테이블로는 둘 다 못 한다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 잔고만 유지 | 이력이 없다. 틀렸을 때 **되짚을 방법이 없다** |
| 원장만 두고 매번 합산 | LOT이 수만 건이면 목록 한 번에 수 초가 걸린다 |
| **원장 + 잔고 캐시 + 스냅샷** | 채택 |

## 결정

- `stock_ledger` — **append-only.** 수정·삭제하지 않는다. 취소는 반대 전표로
- `stock_balance` — 현재 잔고 캐시. **O(1) 조회용**
- `stock_snapshot` — 특정 시점 잔고. 마감·감사용

**파티션은 쓰지 않는다.** 온프레미스 MariaDB 운영 난이도가 올라가고,
테넌트당 데이터량이 파티션이 필요한 규모가 아니다.

## 결과

- 잔고가 틀리면 **원장에서 다시 만들 수 있다** — 복구 경로가 있다
- 원장과 잔고를 **한 트랜잭션**에서 써야 한다. 빠뜨리면 어긋난다
- 데이터가 커지면 파티션을 나중에 검토한다 (지금 결정을 되돌리는 비용은 낮다)

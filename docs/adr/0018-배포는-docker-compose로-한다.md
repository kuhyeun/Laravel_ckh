# ADR 0018. 배포는 docker compose로 하고 호스트 타입을 설정에 남긴다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/프로그램-스펙.md` §13

## 배경

고객사 서버는 Windows일 수도 Linux일 수도 있다. 설치 방식이 갈리면
장애 대응 때마다 *"거기 환경이 뭐예요"*부터 물어야 한다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| OS별 네이티브 설치 | 재현이 안 된다. **우리도 같은 상태를 못 만든다** |
| Docker Desktop | 규모에 따라 **유료**이고 서버에 GUI가 필요 없다 |
| **Docker Engine + compose 오버레이** | 채택 |

## 결정

- **Docker가 설치 요구사항이다.** 못 쓰는 고객사는 계약 전에 거른다
- 공통 `docker-compose.yml` + OS별 오버레이
- Windows는 **WSL2 + Docker Engine**. 볼륨은 **WSL2 내부**, 백업만 Windows 폴더로
- 설치 스크립트가 타입을 확인하고 **`.env`에 적는다** — `COMPOSE_FILE`을 거기 두어
  이후 명령은 OS와 무관하게 같다
- 앱이 `MES_HOST_OS`를 알고 **모든 로그 줄에 남긴다**

## 결과

- 지원 요청이 오면 **로그 한 줄로 환경을 안다**
- 부팅 자가진단이 Windows에서 DB 볼륨이 바인드 마운트면 경고한다 (성능 사고 예방)
- Docker를 못 쓰는 고객사는 **받지 않는다.** 매출 기회를 포기하는 결정이다

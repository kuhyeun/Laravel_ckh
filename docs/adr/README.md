## 쓰는 법

### 언제 남기나

**되돌리는 데 비용이 드는 것**만 남긴다.

| 남긴다 | 남기지 않는다 |
|---|---|
| 대안이 있었고 그중 하나를 골랐다 | 답이 하나뿐이었다 |
| 나중에 *"왜 이렇게 했지"*가 나올 것이다 | 코드를 보면 바로 안다 |
| 버린 쪽에 **대가**가 있다 | 취향 문제다 |

화면 필드나 컬럼 하나는 설계 문서에 적는다. 여기가 아니다.

### 틀

```markdown
# ADR NNNN. 제목

- 상태: 채택 | 대체됨 | 폐기
- 날짜: YYYY-MM-DD
- 관련: 설계 문서 경로

## 배경        무엇이 문제였나
## 검토한 대안  버린 것과 그 이유
## 결정        무엇으로 정했나
## 결과        그래서 무엇을 얻고 무엇을 감수하나
```

**`검토한 대안`과 `결과`가 핵심이다.** 결정만 적으면 설계 문서와 겹치고,
반년 뒤에 필요한 것은 *"그때 뭘 버렸나"*와 *"뭘 감수하기로 했나"*다.

### 결정을 뒤집을 때

**기존 ADR을 고치지 않는다.** 새 번호로 쓰고 옛것의 상태를 `대체됨`으로 바꾼다.
틀렸던 기록도 기록이다 — 같은 함정을 두 번 밟지 않으려면 남아 있어야 한다.

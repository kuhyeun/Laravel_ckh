# ADR 0002. 테넌트마다 DB를 나눈다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/멀티테넌시-설계.md`

## 배경

패키지 MES라 한 서버에 여러 업체가 올라간다. 업체 데이터가 섞이면 복구가 불가능하고,
업체마다 커스텀 컬럼과 정책이 달라 한 스키마에 다 담으면 컬럼이 계속 늘어난다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 단일 DB + `tenant_id` 필터 | **조건 하나 빠뜨리면 남의 데이터가 보인다.** 복구도 행 단위라 사실상 불가 |
| 테넌트마다 서버 | 온프레미스 단일 업체에는 맞지만 중앙 호스팅에서 비용이 선형으로 는다 |
| **테넌트마다 DB** | 채택 |

## 결정

공용 `mes_common` 하나와 테넌트별 `mes_t{id}`로 나눈다.
요청마다 미들웨어가 접속을 갈아 끼운다.

`tenant_id` 컬럼은 **지우지 않고 남긴다.** DB가 갈렸으므로 필터에는 안 쓰지만,
**오배치를 탐지**하는 데 쓴다 — 다른 테넌트 값이 들어오면 그 자체가 버그 신호다.

## 결과

- 백업·복구가 **업체 단위**로 떨어진다
- 업체마다 스키마가 조금씩 달라도 된다 (커스텀 컬럼 슬롯)
- 마이그레이션을 **테넌트 수만큼** 돌려야 한다 — 도구가 필요하다
- 업체 간 통합 조회는 못 한다. 운영 지표는 `mes_common`에 따로 모은다

# ADR 0009. 자재소요는 좁은 수식으로 계산한다

- 상태: 채택
- 날짜: 2026-09-02
- 관련: `docs/자재소요-계산-설계.md`

## 배경

`소요 = BOM수량 × 지시수량`으로는 부족하다. 환봉은 **한 개에서 몇 개가 나오는지**가
절단 길이·톱날 손실·설비 물림에 따라 달라지고, 그 계산식이 업체마다 다르다.
그렇다고 업체가 코드를 짜게 할 수는 없다.

## 검토한 대안

| 대안 | 문제 |
|---|---|
| 코드에 하드코딩 | 업체마다 배포가 갈린다 |
| 범용 스크립트(JS·Groovy) | **무한 루프와 임의 실행**이 열린다. 온프레미스에서 감당 못 한다 |
| 표 기반 설정 | 절단 계산 같은 나눗셈·올림을 표로 못 쓴다 |
| **좁은 수식 DSL** | 채택 |

## 결정

변수 + 연산자 5개 + 함수 6개. **반복도 조건도 없다.**

```
BAR_CUT   CEIL( ORDER_QTY * BOM_QTY / FLOOR( (SPEC - SETUP) / (CUT + KERF) ) )
```

식은 **공용 DB `calc_def`**에 두고 전 테넌트가 공유한다.
찾는 순서는 `bom_line.calc_cd` → `item.calc_cd` → 정책 기본값.
값 변수는 **기능형 커스텀 컬럼**(`var_name`)에서 온다 — `KERF` · `LOSS` · `CUT`.

## 결과

- 정지성이 보장된다. 반복이 없으므로 **끝나지 않는 식이 없다**
- 업체가 식을 못 만든다 — **시스템관리자가 등록**하고 업체는 고른다
- 식을 저장하려면 **시험 계산을 통과**해야 한다
- 표현력에 한계가 있다. 조건 분기가 필요한 요구가 오면 그때 확장을 검토한다

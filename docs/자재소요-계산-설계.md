# 자재소요 계산 설계

> 작성일: 2026-09-01 · 상태: 초안 (미결은 §11)
> 자재를 **얼마나 내보내야 하는가**를 업체마다 다르게 계산합니다.

---

## 1. 문제

`BOM 수량 × 지시 수량`으로 끝나는 자재가 있고, 그렇지 않은 자재가 있습니다.

```
볼트 M6      제품 1개당 8개  →  지시 500개  →  4,000개        ← 곱하기로 끝
환봉 Ø20     제품 1개당 100mm 절단  →  1,000mm 원자재 몇 개?  ← 계산이 필요
코일 t0.8    제품 1개당 200×150mm  →  몇 kg?                  ← 계산이 필요
```

**환봉이 몇 개 필요한지는 곱하기로 나오지 않습니다.**

```
원자재 1,000mm · 절단 100mm · 톱날 손실 3mm · 설비 물림 40mm
  → 실제로 쓸 수 있는 길이  1000 - 40 = 960mm
  → 1개에서 FLOOR(960 / 103) = 9개 채취
  → 500개 필요 → CEIL(500 / 9) = 56개 출고
```

**설비에 물리는 부분은 잘라 쓸 수 없습니다.** 그리고 그 길이는
**어느 공정의 어느 설비를 타느냐에 따라 다릅니다** — 척이 40mm 무는 선반과
60mm 무는 선반이 같은 공장에 있습니다.

> `EA`로 쓰는 자재(볼트 · 포장재)는 이 문제가 없습니다.
> **길이 · 중량으로 잘라 쓰는 소재에만** 해당합니다.

그리고 **이 계산은 업체마다 다릅니다.** 톱날 손실을 빼는 곳과 안 빼는 곳,
로스율을 붙이는 곳과 안 붙이는 곳, 코일 비중을 다르게 잡는 곳이 있습니다.

> 계산을 코드에 박으면 업체마다 분기가 생깁니다.
> **패키지 제품에서 그 분기는 곧 브랜치**가 되고, 나중에 합쳐지지 않습니다.

---

## 2. 방식 — 좁은 수식

**계산식을 문자열로 등록**하되, 도는 언어를 아주 좁게 잡습니다.

```
CEIL( ORDER_QTY * BOM_QTY / FLOOR( (SPEC - SETUP) / (CUT + KERF) ) )
```

| 허용 | 내용 |
|---|---|
| 값 | 숫자, **미리 정의된 변수명**(대문자 + 숫자 + 언더스코어) |
| 연산 | `+` `-` `*` `/` `(` `)` · 단항 `-` |
| 함수 | `CEIL` `FLOOR` `ROUND` `MIN` `MAX` `ABS` — **6개 고정** |

| 없음 | 이유 |
|---|---|
| 변수 대입 · 반복 · 조건 | **항상 종료**해야 합니다. 현장 화면이 멈추면 안 됩니다 |
| 함수 정의 · 외부 호출 | 평가기가 커지면 그 자체가 취약점입니다 |
| 문자열 · 날짜 | 자재 수량 계산에 필요 없습니다 |

**정의되지 않은 변수를 쓰면 저장 자체가 거부됩니다.** 실행 시점에 처음 알게 되면 늦습니다.

### 왜 수식 엔진인가 — 카탈로그로는 부족합니다

계산 유형 몇 개를 미리 만들고 파라미터만 받는 방법도 있습니다.
그 방식은 **새 유형이 나올 때마다 배포**해야 하고, 온프레미스 업체는 그때까지 못 씁니다.

수식은 **데이터**입니다. 등록하면 그 자리에서 돕니다.
대신 언어를 좁혀 위험을 없앴습니다 — 위 표의 "없음"이 그 대가입니다.

## 3. 문법

```ebnf
expr    ::= term   { ("+" | "-") term }
term    ::= factor { ("*" | "/") factor }
factor  ::= [ "-" ] primary
primary ::= NUMBER
          | VAR
          | FUNC "(" expr { "," expr } ")"
          | "(" expr ")"

NUMBER  ::= digit+ [ "." digit+ ]
VAR     ::= upper { upper | digit | "_" }
FUNC    ::= "CEIL" | "FLOOR" | "ROUND" | "MIN" | "MAX" | "ABS"
```

우선순위는 **곱셈·나눗셈 > 덧셈·뺄셈**, 같은 순위는 왼쪽부터. 괄호가 이깁니다.

| 함수 | 인자 | 뜻 |
|---|---|---|
| `CEIL(x)` | 1 | 올림 |
| `FLOOR(x)` | 1 | 내림 |
| `ROUND(x)` | 1 | 반올림 |
| `ABS(x)` | 1 | 절댓값 |
| `MIN(a, b, …)` | **2 이상** | 최솟값 |
| `MAX(a, b, …)` | **2 이상** | 최댓값 |

### 크기 제한

식이 커지는 것 자체를 막습니다. 파서가 폭주할 여지를 남기지 않습니다.

| 제한 | 값 |
|---|---|
| 식 길이 | **500자** |
| 토큰 수 | **200개** |
| 괄호 깊이 | **20단** |
| 함수 인자 수 | **8개** |

## 4. 변수

### 4.1 시스템 변수 — 예약어

**커스텀 변수명으로 쓸 수 없습니다.** 등록할 때 거부합니다.
예약해 두면 이름이 겹칠 일이 없고, 해석 순서를 고민할 필요도 없어집니다.

| 변수 | 뜻 | 출처 |
|---|---|---|
| `ORDER_QTY` | 작업지시 수량 | `work_order.target_qty` |
| `BOM_QTY` | 제품 1개당 소요량 | `bom_line.qty` |
| `SPEC` | 원자재 1개의 규격값 | `lot.spec_value` — **LOT마다 다릅니다**(§6.2) |
| `SPEC2` | 2차원 규격 | `lot.spec_value2` — Phase 1은 항상 `NULL` |
| `PACK` | 포장 수량 | `item.pack_qty` |
| `STOCK` | 현재고 | `stock_balance.qty` 합계 |
| `ISSUED` | 이미 출고된 수량 | `wo_stock.issued_qty` |
| `REMAIN` | 아직 안 낸 수량 | 계산된 소요 − `ISSUED` |
| **`SETUP`** | **설비 세팅으로 못 쓰는 길이** | `process_equipment.setup_loss` — **공정 × 설비**마다 다름(§4.4) |

### 4.2 기능형 커스텀 컬럼

`KERF`(톱날 손실) · `DENSITY`(비중) · `LOSS`(로스율)는 **업체마다 다르고, 품목마다 다릅니다.**
시스템이 컬럼을 정해 줄 수 없습니다.

> **기능형 커스텀 컬럼이 곧 계산식의 변수입니다.**
> 원문의 *"특정 기능을 위한 컬럼"* 이 여기서 답을 얻습니다
> ([커스텀-컬럼-설계.md](./커스텀-컬럼-설계.md) 미결 해소).

`custom_field_def.kind`가 이미 `PLAIN` / `FUNCTIONAL` 둘로 갈려 있습니다. 여기에 이름만 붙입니다.

```sql
-- custom_field_def 에 추가
--   var_name  VARCHAR(20)  NULL   -- kind = FUNCTIONAL 일 때 계산식이 참조할 이름
```

| `kind` | 성격 |
|---|---|
| `PLAIN` | 표시 · 검색 · 정렬용 |
| **`FUNCTIONAL`** | **계산식이 값으로 읽습니다.** `data_type = NUMBER` 슬롯에만 붙습니다 |

```
품목 마스터 · 환봉 Ø20
  톱날 손실  [ 3 ] mm        ← ext_n01 · var_name = KERF
  로스율     [ 2 ] %         ← ext_n02 · var_name = LOSS

BOM 라인 · 완제품 A ← 환봉 Ø20
  절단 길이  [ 100 ] mm      ← ext_n01 · var_name = CUT
```

**변수명은 테넌트 안에서 유일**합니다(`UNIQUE (tenant_id, var_name)`).

### 4.3 `SETUP` — 공정과 설비가 정한다

**같은 환봉이라도 어느 설비에 물리느냐로 쓸 수 있는 길이가 달라집니다.**
품목에도, BOM 라인에도 둘 수 없습니다 — **공정 × 설비**의 성질입니다.

> **자재의 성질이 아닙니다.** 같은 환봉을 물려도 설비가 다르면 값이 다릅니다.
> 그래서 `품목 × 설비`로 축을 하나 더 두지 않습니다 —
> 두면 자재를 등록할 때마다 설비 수만큼 값을 채워야 하고, 대부분 같은 값이 반복됩니다.

```sql
-- process_equipment 에 추가
--   setup_loss  DECIMAL(18,6) NOT NULL DEFAULT 0   -- 물림 · 세팅으로 못 쓰는 길이
```

```
가공 공정
  ├ 설비 3   물림 40mm     ← 1,000mm 중 960mm 사용 가능 → 9개 채취
  └ 설비 5   물림 60mm     ← 1,000mm 중 940mm 사용 가능 → 9개 채취
표면처리 공정
  └ 설비 2   물림  0mm     ← 자르지 않는 공정
```

#### 어느 설비로 계산하는가

**출고 시점에는 설비가 아직 안 정해져 있는 것이 정상입니다.**
실제 설비는 스캔할 때 확정됩니다([라우트시트-설계.md](./라우트시트-설계.md)).

| 상황 | `SETUP` |
|---|---|
| 작업지시에 설비가 지정됨 | **그 설비의 값** |
| 실행(`work_order_op_run`)이 이미 있음 | **그 설비의 값** |
| 아무것도 없음 | **후보 설비 중 가장 큰 값** — 가장 불리하게 |
| 자재를 쓰는 공정이 검사 · 기본 공정 | `0` |

**가장 불리한 값으로 잡는 이유** — 모자라서 라인이 서는 것보다
조금 더 내보내고 남기는 편이 낫습니다. 남은 것은 잔재로 돌아옵니다.

> 설비가 확정되면 **출고 화면에서 다시 계산**할 수 있습니다.
> 이미 출고한 전표를 시스템이 몰래 고치지는 않습니다.

#### 투입 지점은 공정이 아니라 라우팅의 순서다

**공정 마스터의 "가공"을 가리키면 안 됩니다.** 라우팅은 **품목마다 다르고**,
**같은 공정이 순서에 여러 번** 나옵니다.

```
완제품 A 라우팅
  1  절단
  2  가공        ← 여기서 볼트 투입
  3  검사
  4  가공        ← 여기서는 안 함
  5  포장
```

`process_id = 가공` 이라고만 쓰면 **2번인지 4번인지 알 수 없습니다.**

```sql
-- bom_line 에 추가
--   routing_line_id  BIGINT  NULL   -- 투입 지점 = 라우팅의 그 줄
--                                   -- NULL = 첫 수량 공정

-- work_order_op 에 추가
--   routing_line_id  BIGINT  NULL   -- 어느 라우팅 줄에서 복사됐는지
```

작업지시는 라우팅을 **복사해서** 만들고 거기서 순서를 바꿉니다.
`work_order_op.routing_line_id`가 그 흔적이고, **이 값으로 BOM 라인과 이어집니다.**

```
bom_line.routing_line_id  ──▶  routing_line  ──복사──▶  work_order_op.routing_line_id
```

이 컬럼은 **사용처리 자동 차감 시점**에도 쓰입니다 —
원문의 *"원/부자재는 필요시점 자동 차감(공정 시작 전)"* 이 이 값을 봅니다.

### 4.4 그 줄이 없으면 자재도 없다

**어떤 자재는 그 공정 순서가 있을 때만 필요합니다.**

```
완제품 A · BOM                        투입 지점
  환봉 Ø20     언제나                  NULL
  볼트 M6      조립할 때만             라우팅 4번 · 조립
  도금액       도금할 때만             라우팅 6번 · 도금
  포장박스 A   포장할 때만             라우팅 8번 · 포장
```

같은 품목이라도 **라우팅이 갈립니다** — 도금까지 하는 주문과 소재만 가공해 넘기는 주문이 있습니다.
도금을 뺐는데 도금액을 출고하면 **쓰지도 않을 자재가 현장에 나갑니다.**

> **`routing_line_id`가 투입 지점이자 소요 조건입니다.** 컬럼을 하나 더 두지 않습니다 —
> *"이 자재는 이 줄에서 쓴다"* 는 말은 **그 줄이 없으면 안 쓴다**는 뜻이기도 합니다.

| `routing_line_id` | 작업지시에 그 줄이 | 소요 |
|---|---|---|
| `NULL` | — | **언제나** — 첫 수량 공정에서 투입 |
| 있음 | **있음** | 소요. 그 줄에서 투입 |
| 있음 | **없음** | **소요 없음** — 계산에서 빠집니다 |

#### 무엇을 기준으로 판정하는가

품목의 기본 라우팅이 아니라 **그 작업지시에 실제로 남은 줄**입니다.
작업지시는 공정 순서를 **바꾸고 빼고 넣을 수 있습니다**([라우트시트-설계.md](./라우트시트-설계.md)).

| 계산 시점 | 기준 |
|---|---|
| 작업지시가 있음 | **`work_order_op.routing_line_id`** — 실제로 남은 줄 |
| 아직 없음 (수주 단계 소요) | 품목의 **기본 라우팅** |

작업지시에서 **공정을 새로 끼워 넣으면** `routing_line_id`가 `NULL`입니다 —
BOM에 대응할 줄이 없으므로 그 공정에는 자재가 붙지 않습니다. 필요하면 화면에서 직접 출고합니다.

#### 빠진 것을 숨기지 않는다

**조용히 사라지면 위험합니다.** 왜 그 자재가 안 나왔는지 아무도 모릅니다.

```
자재출고 · W-2609-014 · 완제품 A

  RM-BAR-20   환봉 Ø20      56 개
  MT-BOLT-M6  볼트 M6    4,000 개
  ─────────────────────────────────
  도금액                    제외    ⓘ 라우팅에 도금 공정이 없습니다
```

**제외된 줄을 회색으로 남깁니다.** 라우팅을 잘못 짠 것인지, 원래 안 하는 것인지는
현장이 압니다 — 시스템은 **판단을 보여 주기만** 합니다.

#### 중간 공정에 투입되면 소요 시점이 밀린다

```
1공정 ──▶ 2공정 ──▶ 3공정 ──▶ 4공정
                     ▲
                   자재 투입
```

**3공정 자재는 착수일에 있을 필요가 없습니다.** 1 · 2공정이 도는 동안은 쓰지 않습니다.

```
자재 소요 일자 = 작업지시 착수 예정일 + Σ( 앞 공정들의 소요 시간 )
소요 시간      = routing_line.cycle_time_sec × 지시 수량
```

| 투입 공정 | 있어야 하는 때 |
|---|---|
| 1공정 (또는 `NULL`) | **착수일** |
| 3공정 | 착수일 + 1 · 2공정 소요 시간 |

이게 **부족 시점 조회**(`PRD-01`)에 그대로 들어갑니다 —
자재 소요를 전부 착수일에 몰아 놓으면 **없어도 되는 날짜에 부족으로 잡히고**,
필요 없는 발주가 나갑니다.

> **반대 방향도 있습니다.** 1공정 자재가 모자라면 작업지시 자체를 착수할 수 없지만,
> 3공정 자재는 **1 · 2공정을 돌리면서 조달**하면 됩니다. 같은 부족이 아닙니다.

`cycle_time_sec`이 비어 있으면 **착수일로 봅니다** — 모르면 가장 이른 날로 잡는 편이 안전합니다.

#### 같은 공정이 두 번 나와도 헷갈리지 않는다

라우팅은 **같은 공정의 중복을 허용**합니다(`가공 → 검사 → 가공`).
**줄을 가리키므로** 2번 가공과 4번 가공이 구분됩니다 — 공정을 가리켰다면 못 했을 일입니다.

> **순번(`seq`)이 아니라 줄의 `id`를 가리킵니다.** 순번은 순서를 바꾸면 달라지지만
> `id`는 그대로입니다 — **BOM이 라우팅 편집을 견딥니다.**

라우팅에서 그 줄을 **삭제하면** BOM 라인의 참조는 `NULL`이 되고,
그 자재는 **투입 지점 미지정**으로 돌아갑니다. 화면에서 다시 지정해야 합니다.

#### 최소 사용 규격과 함께 본다

`SETUP`을 빼고 나면 **아예 쓸 수 없는 LOT**이 생깁니다.

```
LOT 300mm · 설비 물림 40mm · 절단 100mm + 톱날 3mm
  → 사용 가능 260mm → FLOOR(260/103) = 2개 채취    ✓ 쓸 수 있음

LOT 120mm · 설비 물림 40mm
  → 사용 가능 80mm  → FLOOR(80/103)  = 0개         ✗ 후보에서 제외
```

채취 개수가 **0이 되는 LOT은 출고 후보에서 빠집니다.**
`item.min_usable_spec`(최소 사용 규격)과 같은 성격이지만,
**이쪽은 설비가 정하고 저쪽은 품목이 정합니다.** 둘 다 통과해야 후보입니다.

### 4.5 해석 순서

시스템 변수가 예약어이므로 **커스텀 변수만 찾으면 됩니다.**

```
1. bom_line 의 기능형 값       ← 이 제품에 이 자재를 쓸 때만의 값 (CUT)
2. 자재 품목의 기능형 값        ← 그 자재의 성질 (KERF · DENSITY)
3. 제품 품목의 기능형 값        ← 만드는 쪽의 성질 (LOSS)
4. 없음 → 0 + 경고
```

**가까운 것이 이깁니다.** 같은 `LOSS`라도 BOM 라인에 값이 있으면 그것을 씁니다.

> `CUT`(절단 길이)을 품목이 아니라 **BOM 라인**에 두는 이유가 여기 있습니다.
> 같은 환봉을 100mm로 자르는 제품과 250mm로 자르는 제품이 함께 있습니다.

## 6. 계산 실행

### 6.1 흐름

```
자재출고 화면 진입 (작업지시 W-2608-114)
   │
   ├─ 1. BOM 활성 버전 조회
   │
   ├─ 2. BOM 라인마다
   │      0. 소요 여부 판정       routing_line_id가 지시에 없으면 → 제외(§4.4)
   │      a. calc_cd 결정         bom_line → item → 정책 → BOM_BASIC
   │      b. 투입 지점 결정       bom_line.routing_line_id → work_order_op
   │      c. SETUP 결정           지정 설비 → 실행 중 설비 → 후보 최댓값 → 0
   │      d. 변수 바인딩 수집     시스템 9 + 커스텀(§4.5 순서)
   │      e. SPEC 필요 여부 판단  식에 SPEC이 있으면 → 규격별로 나눠 계산(§6.2)
   │      f. 후보 걸러내기        채취 0개 · min_usable_spec 미만 LOT 제외
   │      g. 평가                 결과 + 경고 + 계산 과정(trace)
   │
   ├─ 3. 화면에 기본값으로 채움 (사용자가 고칠 수 있음)
   │
   └─ 4. 확정 → stock_ledger OUT + wo_stock.issued_qty 증가
```

`ORDER_QTY`는 **작업지시 수량**이지 남은 수량이 아닙니다.
이미 낸 것을 빼려면 식에 `REMAIN`을 쓰거나 화면에서 고칩니다 — 시스템이 몰래 빼지 않습니다.

### 6.2 `SPEC`은 LOT마다 다르다

**이것이 이 설계에서 가장 미묘한 부분입니다.**

`SPEC`(원자재 1개의 규격)은 품목 속성이 아니라 **LOT 속성**입니다.
창고에 1,000mm짜리와 500mm짜리가 함께 있으면 **답이 두 개**입니다.

```
환봉 Ø20 재고 · 설비 물림 SETUP 40mm

  1,000mm × 10개  →  사용 960  → FLOOR(960/103)=9  → CEIL(500/9)  =  56개
    500mm ×  4개  →  사용 460  → FLOOR(460/103)=4  → CEIL(500/4)  = 125개
    120mm ×  6개  →  사용  80  → FLOOR( 80/103)=0  →  후보에서 제외
```

| 처리 | 내용 |
|---|---|
| 계산 시점 | **규격별로 따로 계산**해 목록에 나란히 보여 줍니다 |
| 기본 선택 | 재고가 있는 **가장 큰 규격** — 자투리가 가장 적게 나옵니다 |
| LOT을 바꾸면 | **그 자리에서 다시 계산**됩니다 |
| 섞어 쓰면 | 고른 LOT마다 계산하고 **합산**합니다 |

> 규격을 하나로 뭉개면 답이 틀립니다. 500mm 4개로 500개를 만들 수 없는데
> 평균 규격으로 계산하면 만들 수 있다고 나옵니다.

### 6.3 `result_kind`별 후처리

| 값 | 후처리 | 차감 대상 |
|---|---|---|
| `QTY` | **올림 후 정수** | `stock_balance.qty` |
| `SPEC_COUNT` | **올림 후 정수** | 그 규격 LOT의 개수 |
| `WEIGHT` | **소수 3자리 반올림** | `stock_balance.qty` (단위 kg) |

식이 소수를 내도 개수 단위는 정수여야 합니다. **마지막에 시스템이 한 번 더 올립니다** —
`CEIL`을 식에 넣는 것을 잊어도 56.6개가 출고되지 않습니다.

### 6.4 오류와 경계

**등록 시점**에 잡는 것과 **계산 시점**에 잡는 것을 나눕니다.

| 코드 | 시점 | 내용 |
|---|---|---|
| `E_TOKEN` | 등록 | 허용되지 않은 문자 — 위치를 함께 보고 |
| `E_PAREN` | 등록 | 괄호 불일치 |
| `E_SYNTAX` | 등록 | 문법 오류 — 어느 토큰에서 막혔는지 |
| `E_FUNC` | 등록 | 없는 함수 · 인자 수 불일치 |
| `E_VAR` | 등록 | **정의되지 않은 변수** — 어느 이름인지 지목 |
| `E_RESERVED` | 등록 | 커스텀 변수명이 **시스템 예약어**와 겹침 |
| `E_LIMIT` | 등록 | 길이 · 토큰 수 · 깊이 초과 |
| `E_TEST` | 등록 | **시험 계산 실패** |

| 코드 | 시점 | 처리 |
|---|---|---|
| `W_NULL` | 계산 | 변수 값이 비었음 → **0으로 계산**하고 어느 변수인지 표시 |
| `W_DIV0` | 계산 | 0으로 나눔 → 결과 **0** + 경고. 막지 않고 사용자가 직접 입력 |
| `W_NEG` | 계산 | 결과가 음수 → **0**으로 보정 + 경고 |
| `W_OVER` | 계산 | 결과가 재고보다 큼 → **경고만.** 음수 재고를 허용하는 원칙과 같습니다 |
| `W_SETUP` | 계산 | 설비가 정해지지 않아 **가장 불리한 물림값**으로 계산 → 확정 후 재계산 가능 |
| `W_NOLOT` | 계산 | `SETUP`을 빼면 **쓸 수 있는 LOT이 없음** → 더 긴 규격을 입고해야 합니다 |

**등록 오류는 막고, 계산 경고는 막지 않습니다.**
현장에서 출고를 멈추는 것보다 값이 이상하다고 알려 주는 편이 낫습니다.

## 7. 스키마

### 7.1 계산식 정의 — 공용 DB

```sql
CREATE TABLE calc_def (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  calc_cd      VARCHAR(30)  NOT NULL,
  name         VARCHAR(60)  NOT NULL,
  expr         VARCHAR(500) NOT NULL,
  result_kind  ENUM('QTY','SPEC_COUNT','WEIGHT') NOT NULL,
  sample_json  VARCHAR(500) NULL,      -- 시험 계산에 쓴 값. 재검증용으로 남깁니다
  remark       VARCHAR(200) NULL,
  is_builtin   BOOLEAN NOT NULL DEFAULT FALSE,
  is_active    BOOLEAN NOT NULL DEFAULT TRUE,
  created_at   DATETIME(6) NOT NULL,
  created_by   BIGINT      NOT NULL,
  UNIQUE KEY uk_cd (calc_cd)
) ENGINE=InnoDB;
```

`sample_json`을 남기는 이유 — **함수 동작을 고칠 때 전 식을 다시 돌려 봐야** 하기 때문입니다.
샘플이 없으면 무엇으로 검증할지부터 다시 만들어야 합니다.

`is_builtin = true`인 식은 **수정 · 삭제할 수 없습니다.** 복제해서 새로 만듭니다.

### 7.2 기본 제공

| `calc_cd` | 식 | `result_kind` | Phase |
|---|---|---|---|
| `BOM_BASIC` | `BOM_QTY * ORDER_QTY` | `QTY` | **1** |
| `BOM_LOSS` | `CEIL( BOM_QTY * ORDER_QTY * (1 + LOSS/100) )` | `QTY` | **1** |
| `BAR_CUT` | `CEIL( ORDER_QTY * BOM_QTY / FLOOR( (SPEC - SETUP) / (CUT + KERF) ) )` | `SPEC_COUNT` | **1** |
| `COIL_WEIGHT` | `ORDER_QTY * BOM_QTY * CUT * WIDTH * THICK * DENSITY / 1000000` | `WEIGHT` | 2 |
| `SHEET_GRID` | `CEIL( ORDER_QTY * BOM_QTY / (FLOOR((SPEC-SETUP)/CUT) * FLOOR(SPEC2/WIDTH)) )` | `SPEC_COUNT` | 2 |

**Phase 1은 셋으로 돕니다.** 나머지는 업체가 등록하거나 Phase 2에 내장으로 들어갑니다.

### 7.3 연결

```sql
-- bom_line 에 추가
--   calc_cd  VARCHAR(30)  NULL   -- 이 라인의 계산식
--   ext_n01 … ext_n03            -- 기능형 슬롯 (CUT 등)

-- item 에 추가
--   calc_cd  VARCHAR(30)  NULL   -- 이 자재의 기본 계산식
--   ext_n01 … ext_n03            -- 기능형 슬롯 (KERF · DENSITY · LOSS 등)
```

**테넌트 DB에 계산식 본문을 복사하지 않습니다.** 코드만 참조합니다 —
식이 고쳐지면 전 테넌트가 같이 고쳐져야 하고, 복사본이 있으면 그게 안 됩니다.

> 단, **이미 출고된 전표는 계산 결과를 저장**합니다(`stock_ledger`의 수량).
> 식이 바뀌어도 과거 출고가 다시 계산되지 않습니다 — BOM 버전과 같은 원칙입니다.

## 8. 등록과 검증

계산식 등록은 **시스템관리자 전용**입니다.
기능 스위치 · 커스텀 컬럼 정의와 같은 선을 지킵니다
([정책-설정-설계.md](./정책-설정-설계.md) §7).

| 단계 | 검사 |
|---|---|
| 1 · **토큰** | 허용된 문자만 있는가. 길이 · 토큰 수 제한 |
| 2 · **파싱** | 문법에 맞는가. 괄호 · 함수 인자 수 |
| 3 · **변수** | 쓰인 변수가 **전부 정의되어 있는가**. 없으면 어느 것인지 지목 |
| 4 · **시험 계산** | 샘플 값을 넣어 **실제로 돌려 봅니다.** 결과가 나와야 저장됩니다 |

```
식     CEIL( ORDER_QTY * BOM_QTY / FLOOR( SPEC / (CUT + KERF) ) )
샘플   ORDER_QTY 500 · BOM_QTY 1 · SPEC 1000 · CUT 100 · KERF 3
결과   56                                              ✓ 저장 가능
```

**시험 계산을 통과하지 않으면 저장되지 않습니다.** 현장에서 처음 터지면 늦습니다.

## 9. 출고 화면에서의 동작

계산값은 **기본값일 뿐입니다.** 단가와 같습니다 — 채워 주고, 사용자가 고칩니다.

```
자재출고 · W-2608-114 · 완제품 A · 지시 500

  RM-BAR-20   환봉 Ø20     BAR_CUT
     1,000mm  재고 10       계산 56 개   →  [ 56 ] 개    ⓘ
       500mm  재고  4       계산 125 개  →  [  0 ] 개    ⓘ
  MT-BOLT-M6  볼트 M6      BOM_BASIC
                            계산 4,000   →  [ 4,000 ]   ⓘ
```

**ⓘ를 누르면 계산 과정을 펼칩니다.**

```
BAR_CUT · SPEC_COUNT
  CEIL( ORDER_QTY * BOM_QTY / FLOOR( (SPEC - SETUP) / (CUT + KERF) ) )
  CEIL( 500 * 1 / FLOOR( (1000 - 60) / (100 + 3) ) )
  CEIL( 500 / 9 )
  = 56 개

  ORDER_QTY 500   작업지시
  BOM_QTY     1   BOM 라인
  SPEC     1000   LOT RB-260825-02
  SETUP      60   가공 · 설비 미지정 → 후보 최댓값(설비 5)   ⚠ 확정 후 재계산 가능
  CUT       100   BOM 라인 · 절단 길이
  KERF        3   품목 · 톱날 손실
```

**왜 56인지 보이지 않으면 현장은 계산을 믿지 않습니다.** 그러면 손으로 다시 셉니다.

### 9.1 자재는 공정을 막지 않는다

**자재가 없다고 1공정이 못 도는 것이 아닙니다.**

현장은 실물을 이미 갖고 있는데 **전산만 안 따라온** 경우가 대부분입니다.
출고 전표는 나중에 칩니다 — 이 시스템에서 소급은 예외가 아니라 **정상**입니다
([재고-수불-설계.md](./재고-수불-설계.md) §3).

> 막으면 현장이 시스템을 안 씁니다. **그러면 실적도 안 들어옵니다.**
> 자재 하나 붙잡자고 생산 실적 전부를 잃는 거래입니다.

| 상황 | 처리 |
|---|---|
| 자재 미출고 상태로 공정 시작 | **경고만.** 진행합니다 |
| 재고가 모자란 채로 사용처리 | **음수 재고 허용** + `INV-08` 미결 |
| 자재가 아예 등록 안 됨 | 경고. 나중에 BOM을 고치고 소급 입력 |

**공정 진행 조건에 자재는 들어가지 않습니다.** 조건은 셋뿐입니다 —
앞이 생산이면 **시작(s) 기록**, 검사면 완료, 외주면 외주 입고
([라우트시트-설계.md](./라우트시트-설계.md) §6).

### 9.2 세 사건은 순서가 정해져 있지 않다

```
출고 (창고 → 작업지시)  ─┐
공정 시작                ├─  셋 다 언제든. 순서를 강제하지 않습니다
사용처리 (투입)          ─┘
```

교과서 순서는 `출고 → 시작 → 투입`이지만 현장은 그렇게 안 굴러갑니다.

| 실제로 일어나는 순서 | |
|---|---|
| 출고 → 시작 → 투입 | 교과서 |
| **시작 → 출고 → 투입** | 일단 돌리고 창고에서 나중에 빼옵니다 |
| **시작 → 진행 → 투입(출고 동시)** | 전표를 한꺼번에 몰아서 칩니다 |

**창고에서 빼오는 시점이 공정 시작 이후여도 됩니다.**
시스템이 순서를 정하면 현장은 순서를 맞추려고 거짓 전표를 칩니다.

### 9.3 자재투입을 누르면 사용처리된다

라우팅의 **자재투입 공정**을 완료하면, 그 줄에 붙은 자재가 **한 번에 사용처리**됩니다.

```
자재투입 공정 스캔 · 완료
   │
   └─ 그 routing_line_id 를 가리키는 BOM 라인마다
        필요량 = 계산식 결과
        ├─ 출고되어 있는 만큼        → 사용처리 (wo_stock.consumed_qty +)
        └─ 모자라는 만큼            → 자동 출고 후 사용처리
              └─ 재고가 없으면      → 음수 재고 + INV-08 미결
```

**미출고분을 자동으로 출고까지 처리합니다.** 현장이 투입을 찍었는데
전산이 *"먼저 출고하세요"* 라고 막으면, 그 순간 현장은 시스템을 떠납니다.

자동 출고의 LOT 선택은 **선입선출 + 잔재 정책**을 그대로 씁니다
(`stock.remnant_consume` — [재고-수불-설계.md](./재고-수불-설계.md) §2-1).

| 정책 | 값 | 뜻 |
|---|---|---|
| `material.consume_timing` | **`PROCESS_START`**(기본) | **언제** — 그 공정을 시작할 때 사용처리 |
| | `ISSUE` | 출고할 때 바로 사용처리 (현장 보유 개념 없음) |
| | `MANUAL` | 사람이 화면에서 직접 |
| `material.consume_mode` | **`AUTO`**(기본) | **어떻게** — 계산식으로 수량을 내고 **선입선출**로 LOT까지 자동 선택 |
| | `MANUAL` | **자재 식별표를 스캔**하거나 목록에서 **LOT을 직접** 고름 |

> **`timing`은 언제, `mode`는 어떻게입니다.** 소재처럼 어느 조각을 썼는지가 중요한 자재는
> `MANUAL`로 두고, 볼트 · 포장재는 `AUTO`로 둡니다 — 스코프가 `TENANT → ITEM`이라 품목마다 다르게 잡습니다.

> 자재투입 공정이 **라우팅에 없으면** `routing_line_id = NULL`인 자재는
> **첫 수량 공정**에서 위와 같이 처리됩니다.

## 10. 워크스루 3건

### 볼트 — 곱하기로 끝

```
BOM_BASIC   BOM_QTY * ORDER_QTY
            8 * 500 = 4,000 개
```

### 환봉 — 규격별로 갈림

```
BAR_CUT   CEIL( ORDER_QTY * BOM_QTY / FLOOR( (SPEC - SETUP) / (CUT + KERF) ) )

투입 공정 : 가공        설비 미지정 → 후보 중 최댓값
설비 3 물림 40 · 설비 5 물림 60  →  SETUP = 60  (가장 불리하게)

1,000mm LOT   CEIL( 500 / FLOOR((1000-60)/103) ) = CEIL(500/9) =  56개
  500mm LOT   CEIL( 500 / FLOOR(( 500-60)/103) ) = CEIL(500/4) = 125개
  120mm LOT   FLOOR((120-60)/103) = 0                          → 제외

기본 선택 : 1,000mm (가장 큰 규격 — 자투리 최소)
```

**설비 3으로 확정되면 다시 계산합니다.** `SETUP`이 40으로 줄어
`FLOOR(960/103) = 9`로 같지만, 규격이 짧은 LOT에서는 결과가 달라집니다.

1,000mm 56개를 쓰면 **9 × 56 = 504개**를 만들 수 있고 4개가 남습니다.
남는 자투리는 **잔재 LOT**으로 재입고됩니다(Phase 2) — 그 잔재도
다시 물려야 하므로 `SETUP`이 또 빠집니다.

### 코일 — 중량 (Phase 2)

```
COIL_WEIGHT  ORDER_QTY * BOM_QTY * CUT * WIDTH * THICK * DENSITY / 1000000
             500 * 1 * 200 * 150 * 0.8 * 7.85 / 1000000
             = 94.200 kg
```

`WIDTH` `THICK` `DENSITY`는 전부 기능형 커스텀 컬럼입니다 —
비중을 7.85로 잡는 곳과 7.87로 잡는 곳이 있습니다.

## 11. 미결

| # | 항목 | 확인 필요 |
|---|---|---|
| 1 | **등록 권한** | 지금은 **시스템관리자 전용**입니다. 업체관리자가 등록하면 요청·대기가 없어지지만 **잘못된 식이 현장에 바로 나갑니다** |
| 2 | **잔재를 계산에 넣을지** | 500mm 잔재가 있으면 1,000mm를 덜 내보내도 됩니다. 지금은 **넣지 않습니다** — 계산은 신품 기준이고, 잔재 우선 사용은 출고 정렬(`stock.remnant_consume`)이 담당 |
| 3 | **`CUT`을 정식 컬럼으로 둘지** | 절단 길이는 이산제조가 거의 다 씁니다. 기능형 슬롯 대신 `bom_line.cut_length`로 표준화할 수도 |
| 4 | **기능형 슬롯 수** | 지금은 품목 · BOM 라인 각 **3개** |
| 5 | **식 변경 이력** | `calc_def`가 바뀐 이력을 남길지. 과거 전표는 결과가 저장되어 재계산되지 않으므로 **감사 목적**입니다 — Phase 2 |

> 해결됨 — *`setup_loss`의 축*: **공정 × 설비 하나로 확정.** 자재의 성질이 아니라 **설비의 성질**입니다 —
> 같은 자재를 써도 설비가 다르면 값이 다르고, 자재가 달라도 같은 설비면 같습니다.
> `품목 × 설비` 축을 두지 않습니다.

## 부록 · 결정 요약

| 결정 | 값 |
|---|---|
| 방식 | **좁은 수식** — 변수 + 연산자 5 + 함수 6. 반복 · 조건 · 대입 없음 |
| 크기 제한 | 500자 · 토큰 200 · 깊이 20 · 인자 8 |
| 정의 위치 | **공용 DB** `calc_def`. 테넌트에 본문 복사 안 함 |
| 등록 권한 | **시스템관리자 전용** (미결 1) |
| 시스템 변수 | **9개**(`SETUP` 포함). **예약어** — 커스텀 변수명으로 쓸 수 없음 |
| 커스텀 변수 | 기능형 커스텀 컬럼 `var_name`. `bom_line` → 자재 → 제품 순으로 해석 |
| 적용 우선순위 | `bom_line.calc_cd` → `item.calc_cd` → 정책 → `BOM_BASIC` |
| `SPEC` 처리 | **LOT 규격마다 따로 계산.** 기본은 가장 큰 규격 |
| `SETUP` | **공정 × 설비**의 `setup_loss`. 설비 미지정이면 **후보 중 최댓값**(가장 불리하게) |
| `SETUP`의 축 | **설비의 성질**입니다. 자재별로 나누지 않습니다 — 같은 자재라도 설비가 다르면 값이 다릅니다 |
| 투입 지점 | **`bom_line.routing_line_id`** — 공정 마스터가 아니라 **라우팅의 그 줄**. 없으면 첫 수량 공정 |
| **소요 조건** | `routing_line_id`가 **투입 시점이자 소요 조건**입니다. 그 줄이 작업지시에 없으면 **자재도 없습니다** |
| 판정 기준 | 작업지시가 있으면 **`work_order_op.routing_line_id`**, 없으면 품목 기본 라우팅 |
| 소요 **시점** | **착수일 + 앞 공정들의 소요 시간.** 3공정 자재를 착수일에 몰면 없어도 될 날짜에 부족으로 잡힙니다 |
| **차단 여부** | **자재는 공정을 막지 않습니다.** 미출고 · 재고 부족 모두 **경고만**(§9.1) |
| 순서 | 출고 · 공정 시작 · 사용처리는 **순서가 정해져 있지 않습니다.** 창고에서 빼오는 것이 시작 이후여도 됩니다(§9.2) |
| 사용처리 | **자재투입 공정을 누르면** 그 줄의 자재가 사용처리되고, **미출고분은 자동 출고**됩니다(§9.3) |
| 제외 표시 | **회색 줄로 남깁니다.** 조용히 사라지면 왜 안 나왔는지 아무도 모릅니다 |
| 같은 공정 중복 | **줄을 가리키므로 구분됩니다.** 순번이 아니라 `id`라서 순서를 바꿔도 안 깨집니다 |
| 후보 제외 | `SETUP`을 빼서 **채취 0개**가 되는 LOT은 출고 후보에서 뺍니다 |
| 후처리 | `QTY` · `SPEC_COUNT`는 **올림 정수**, `WEIGHT`는 소수 3자리 |
| 오류 | **등록은 막고**(`E_*`) **계산은 경고만**(`W_*`) |
| 기본 제공 | `BOM_BASIC` · `BOM_LOSS` · `BAR_CUT` — Phase 1 |
| 등록 화면 | **Phase 2**(`SYS-13`). 스키마와 내장 3종은 Phase 1 |
| 계산 결과 | **기본값일 뿐.** 사용자가 고치고, 과정을 펼쳐 봅니다 |

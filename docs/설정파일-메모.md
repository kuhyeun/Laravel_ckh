> 작성 : 2026-11-10
> 개발 중에 정한 설정과, 나중에 업체에 설치하거나 기능을 붙일 때 바꿔야 할 것을 모았습니다.

## 1. 큐 ( Queue ) — 지금은 쓰지 않음

### 지금 상태 ( 2026-11-10 결정 )
- `.env` · `.env.example` · `.env.local` 모두 `QUEUE_CONNECTION=sync`
- 큐에 작업을 넣는 코드가 없다 ( `dispatch` · `ShouldQueue` 없음 ) → 큐 테이블( `jobs` · `failed_jobs` )도 만들지 않았다
- 전에는 `database` 로 되어 있었지만 `jobs` 테이블이 없어서, 큐를 쓰는 순간 "테이블 없음"으로 실패하는 상태였다

### 큐란
시간이 걸리는 작업( 메일 발송 · 큰 엑셀 만들기 · 외부 시스템 연동 등 )을 요청에서 떼어 나중에 처리하는 기능.
요청은 "할 일"만 목록에 넣고 바로 응답 → 따로 도는 **워커**( `php artisan queue:work` )가 목록에서 꺼내 처리한다.

| `QUEUE_CONNECTION` | 목록 위치 | 워커 |
|---|---|---|
| `sync` ( 지금 ) | 목록 없이 그 자리에서 바로 실행 | 필요 없음 |
| `database` | DB `jobs` 테이블 | 필요 |
| `redis` | Redis 서버 | 필요 |

`sync` 에서도 큐 코드( `dispatch` )는 그대로 동작한다 — 다만 요청 안에서 바로 실행되므로 그만큼 응답이 늦다.

### 큐가 필요해지면 ( 순서 )
1. 테이블 마이그레이션 추가 — 기준 파일( `2026_01_01_*` )은 고치지 않고 **새 파일**로
   - `php artisan make:queue-table` · `php artisan make:queue-failed-table` 이 만드는 내용을 `packages/mes-core/database/migrations/` 에 옮긴다
   - `config/mes.php` 의 `log.sql_skip_tables` 에 `jobs` · `job_batches` · `failed_jobs` 는 이미 들어 있다 ( SQL 로그에 안 남김 )
2. `.env` · `.env.example` 을 `QUEUE_CONNECTION=database`
3. **운영 서버에 워커를 상시 띄운다** — 안 띄우면 작업이 쌓이기만 하고 처리되지 않는다
   - 예 : supervisor 로 `php artisan queue:work --tries=3 --max-time=3600` 상시 실행 ( 꺼지면 다시 켜게 )
   - Docker 면 워커용 컨테이너를 하나 더 두는 방법도 있다
   - 코드를 배포한 뒤에는 `php artisan queue:restart` ( 워커는 옛 코드를 메모리에 들고 있다 )
4. 실패한 작업 확인 : `php artisan queue:failed` · 다시 실행 `php artisan queue:retry all`

참고 : `composer dev` 스크립트는 `queue:listen` 도 같이 띄운다. 지금( `sync` )은 할 일이 없어 그냥 대기한다.

## 2. 업체 설치( 운영 ) 때 `.env` 에서 바꿀 것

| 항목 | 개발 | 운영 |
|---|---|---|
| `APP_ENV` | `local` | `production` |
| `APP_DEBUG` | `true` | **`false`** ( 켜 두면 오류 화면에 코드 · 설정이 보인다 ) |
| `APP_KEY` | 있음 | 업체마다 새로 : `php artisan key:generate` |
| `APP_URL` | `http://localhost` | 실제 주소 |
| `APP_NAME` | `Laravel_CKH` | 업체 · 제품 이름 ( 화면 제목 ) |
| `LOG_LEVEL` | `debug` | `warning` 정도 |
| `MES_SQL_LOG` | `true` | 줄을 지우거나 `false` ( 운영 기본 = 끔 · 켜도 비밀번호 해시 · 토큰은 `***` ) |
| `MES_LOG_DAYS` | `30` | 업체 보관 기준대로 |
| `DB_USERNAME` · `DB_PASSWORD` | `root` | MES 전용 계정 |
| `QUEUE_CONNECTION` | `sync` | 큐를 쓰기 전까지 `sync` ( 위 1 ) |

설치 순서 :
1. `composer install --no-dev --optimize-autoloader` ( 운영에서는 `update` 를 쓰지 않는다 — 아래 3 )
2. `.env` 작성 → `php artisan key:generate`
3. `php artisan migrate --force` → `php artisan db:seed --force`
4. `npm ci` → `npm run build`
5. `php artisan config:cache` · `php artisan route:cache`
   - 캐시한 뒤에는 `.env` 를 바꿔도 반영되지 않는다 → 다시 `config:cache`

## 3. composer

- `post-update-cmd` 에 `ide-helper:generate` ( 2026-11-10 ) — `composer update` 때마다 `_ide_helper.php`( 에디터 자동완성용 )를 다시 만든다
  - ide-helper 는 개발용( `require-dev` ) → 운영에서 `composer update --no-dev` 를 하면 이 명령이 없어 실패한다. 운영은 `install` 만
  - 예전 파일이 없는 사용자 모델( `App\Models\User\User` )을 가리켜 `Auth::user()` 마다 에디터 오류가 났던 일이 있다 ( 11-09 )
- Core 패키지 경로가 `/var/www/packages/mes-core`( Docker 안 경로 )로 고정 · 버전 `@dev`
  - Core 를 별도 저장소로 나눌 때( ADR 0028 · 0029 ) git 저장소 주소 + 버전 고정으로 바꾼다
- 이름 `laravel/laravel` · `post-create-project-cmd`( sqlite 파일 생성 )는 기본 템플릿에서 남은 것 — 동작에는 영향 없음
